# Changelog

## 0.1.0 — в работе

- Срез 1, план 1: токены, провайдер, примитивы реестра, демо.
- Срез 1, план 2: `DataGrid` и семейство — типы контракта, `resolveSpans`, `sortRows`, помощники выделения, `ColumnHeader` (сортировка, ресайз), `ColumnsMenu` (состав колонок), клавиатура по паттерну WAI-ARIA grid (`useGridKeyboard`), скелетон той же геометрии; пакет `@katran/effector` — `createFiltersModel`, `createGridModel`, хуки `useGrid`/`useFilters`, persist-адаптеры `localStoragePersist`/`memoryPersist`; демо «Реестр» на 87 документах с фейковым бэкендом; Playwright-замер геометрии грида (`pnpm --filter demo e2e`, вне `pnpm check`); `@katran/ui` объявляет `sideEffects` входа — production-сборка потребителя не теряет `tokens.css`.
- Срез 1, план 2, после финального ревью: абсолютные `aria-rowindex` по выборке; `aria-busy` на таблице и `aria-hidden` у скелетона; минимум показа скелетона 400 мс соблюдается; модель грида принимает только ответ на текущий запрос (своя `attach`-копия `fetchFx`); `remove` в модели фильтров не затирает черновик; ползунок ширины колонки — `aria-orientation="horizontal"` и `aria-valuetext`; Tab в поповере ячейки не уводит фокус в ячейку; линт проверяет, что effector берёт из `@katran/ui` только типы и не обращается к `document`/`window`.
- Breaking: `GridSkeleton` больше не принимает `rowIndexStart` — скелетон скрыт от AT и индексов строк не несёт.
- План 2.1, решения владельца 24.09.2026: запись грида 68 px, как на стенде `pi-constructor` (вертикальный отступ записи — новый токен `grid-pad` = 6; коридор e2e записи 64–72); грид несёт фон `paper` на корне; наведение подсвечивает всю запись (`tbody`), а не одну строку.
- План 2.1: буква `StatusDot` допустима на всех тонах — на светлых `flowl/okl/grey` она тёмная (новый цветовой токен `st-letter-soft`, правило контраста ≥ 4.5 в обеих темах); на странице «Значения» — ряд точек с буквами на всех девяти тонах.
- План 2.1: демо «Реестр» объясняет сквозные строки записи — раскрывающийся блок над гридом с пояснением, фрагментом `spans` из раскладки демо и переключателем подсветки сегментов (пустой сегмент — пунктир из точек).
- `formatAmount`: разряды разделены неразрывным пробелом U+00A0 (узкий U+202F не читался), десятичная точка — как на стенде.
- Срез 1, план 3 (1e): типы фильтра (`Scalar`, `Condition`, `Filter`, `FilterFieldType`, `FilterField`, `FilterMeta`) переехали в `@katran/ui` (в `@katran/effector` остались реэкспортом); breaking — у `FiltersModel`, `GridModel`, `GridBinding`, `FiltersBinding` появились обязательные члены, рукописные моки этих типов нужно дополнить; модель фильтров — `setLane`/`$lane`/`revert`; модель грида — фасеты (`facets: { field, fetchFx }` → `$facets`); новые компоненты `@katran/ui`: `StatusLane` (лейн статусов со счётчиками), `FilterPanel` (панель фильтров simple: чипы, сворачиваемое тело, применить/отменить), `BulkBar` (полоса массовых действий); слот `toolbar` в `DataGrid`; экран «Валютные документы» в демо вместо «Реестра».
- Срез 1, план 3, после финального ревью: поле DATETIME панели очищается из полей и показывает набранную границу (одна граница — `BETWEEN` за этот день); набранное в полях стирается при любой внешней смене черновика (в том числе «-» в числе после «Сбросить»); фокус после ✕ чипа переходит на соседний чип или кнопку «Фильтры», после «Сбросить» — на «Фильтры»; `BulkBar` объявляет «Выделение снято»; `StatusLane` сравнивает значения строго и не режет кольцо фокуса крайних кнопок; `DataGrid` не теряет валидный falsy `toolbar`; внутренние помощники панели (`fieldOp`, `conditionFrom`, `draftOf`, `isoDayStart`, `isoDayEnd`, `RawValue`) из `@katran/ui` больше не экспортируются; демо — лейн без чисел до первого ответа фасетов, `EQ` для строк с учётом регистра, как в контракте.
- План 4 (совместимость): `peerDependencies` `react`/`react-dom` — `>=17` (разработка и демо на React 17.0.2, CI дополнительно гоняет пакеты кита на React 19); API React 18+ в `packages/ui`/`packages/effector` запрещены линтом, совместимая замена `useId` — `useStableId` (`packages/ui/src/compat/`); `dist` всех трёх пакетов (`@katran/tokens`, `@katran/ui`, `@katran/effector`) собирается под Chromium 88 и публикуется (`publishConfig`), `@katran/ui` — classic JSX runtime (`dist` не импортирует `react/jsx-runtime`), проверка планки браузера `pnpm check:target` (`es-check` + CSS); `@katran/effector` больше не `private`; изоляция геометрии кита от глобальных стилей хоста под `[data-k-root]` (демо — режим `?hostile`); **breaking**: ширина колонки — теперь полная ширина ячейки (заданные `width` колонок включают паддинг 16 px, ширины демо-колонок увеличены на 16); тело панели фильтров скрывается атрибутом `hidden` (было видно всегда); Shift+клик по кнопке открытия — второй drawer, как двойной клик; тултип статусной точки (`data-k-tip` из `label`); проп `emptyText` у `DataGrid`; `formatDate` разбирает дату без времени (`YYYY-MM-DD`) без `new Date()` — не зависит от часового пояса машины; демо — полная дата документа с секундами, дата валютирования форматирована, рублёвый счёт с кодом 810, статус `INVALID`, направление в фильтре кодом, строка «Открыт документ…» не сдвигает грид.
- План 4, после финального ревью: **breaking** — под корнем `KatranProvider` модель коробки `content-box` для всех элементов, включая разметку команды внутри провайдера (глобальный `border-box` хоста до неё не доходит — свои блоки задают `box-sizing` явно); исключение — контролы со встроенным `border-box` (`button`, `select`, `input` типов `checkbox`/`radio`/`button`/`submit`/`reset`), их размеры снова совпадают с токенами (кнопка size m — 28 px, а не 30; пункт меню не шире поповера); токен `grid-lead` — полная ширина служебной колонки с паддингом, 100 (было 84 при content-box ячейках), контент колонки — снова 84; `formatDate` возвращает пусто для `YYYY-MM-DD` с месяцем вне 1–12 или днём вне 1–31; линт пакетов запрещает `createRoot`, `hydrateRoot`, `useFormStatus` из `react-dom` и модуль `react-dom/client`; `@katran/tokens` публикует только `dist` и `src/tokens.css`/`src/fonts.css`.
- Изменено (breaking): `Sort` — массив уровней `SortLevel[]` (`[]` — без сортировки), `GridQuery.sort` — массивом, как в контракте `vtb-filters`. Добавлено: `soleSort`, `addSortLevel`, `flipSortLevel`, `removeSortLevel`, `MAX_SORT_LEVELS`; `sortRows` — по уровням; демо — фейковый бэкенд сортирует статус по подписи, `localeCompare('ru')`.
- План 5a: модель грида — `$sort: Store<Sort>` (начальное `[]`, не сохраняется через `persist`), `sortBy: EventCallable<Sort>` — грид сообщает следующее состояние целиком, посчитанное помощниками уровней; `GridQuery.sort` уходит в запрос массивом.
- План 5a: `ColumnHeader` — Shift+клик по заголовку и меню составной колонки с кнопками «+»/«↕» добавляют уровень сортировки; номер уровня верхним индексом у стрелки при двух и более уровнях, `aria-sort` — только у колонки первого уровня; «Сбросить сортировку» составной колонки снимает только её уровни (или всю сортировку, если её уровни — вся сортировка); клавиатура — `Shift+Enter` на ячейке шапки эквивалентен Shift+клику. Новый компонент `@katran/ui` — `SortChips`, `DataGrid` рендерит его над таблицей, пока `sort.length > 0` («Сортировка: 1 Тип сообщения ↑ › 2 BIC 52 ↑»; чип — смена направления и ✕ «убрать уровень»).
- План 5a (R6): `ColumnDef.fullHeight` — ячейка колонки на всю высоту записи (`rowSpan`), рендерится только в первой строке; служебная колонка (чекбокс, открытие, номер) — теперь тоже на всю высоту. `resolveSpans`/`fillSegments` обрезают сквозной сегмент до непрерывного участка колонок первой строки, если в его диапазон попала видимая высокая колонка; остаток закрывают пустые заполнители. `GridSkeleton` повторяет `rowSpan` записи. Клавиатура (`useGridKeyboard`): ↓/↑ из высокой ячейки — в ту же колонку соседней записи, ↓/↑ из соседней строки на колонку высокой ячейки — в эту ячейку. Демо: «Дата / Время», «Тип», «Направление», 32, «S / R in», «Провайдеры» — на всю высоту; причина статуса — сегмент `from: 'status', to: 'id'`.
- План 5a (R5): `ColumnDef.split` — «вместе / раздельно» для составных колонок (общий переключатель в меню состава колонок с подписью `split.label`); `expandColumns(columns, split)` в `@katran/ui` разворачивает части после `visibleColumns` — части следуют за хостом в порядке и скрытии. Модель грида: `$split: Store<string[]>`, `setSplit: EventCallable<{ id: string; on: boolean }>`, сохраняется через `persist` (`GridPersisted.split`, чужие id отбрасываются); `GridModelConfig.columns` включает части — у них свои ширины по умолчанию. `useGrid` отдаёт `split`/`onSplit`. Переключение режима не сбрасывает сортировку — уровни ссылаются на ключ колонки. Демо: 32 — «Валюта отдельной колонкой» (сумма отдельно от валюты-тега); «Дата / Время» — «Валютирование отдельной колонкой» (поля `vdDt`/`vdKt` вместо `valueDate`, три строки в высокой ячейке).
- План 5a (W1): сброс ширин колонок — двойной клик по ручке ресайза любой колонки возвращает все ширины к раскладке; на ползунке `Home` сбрасывает ширину этой колонки, `Shift+Home` — все. Модель — `resetWidths: EventCallable<void>`, `resetWidth: EventCallable<string>`, результат сохраняется через `persist`; `useGrid` отдаёт `onResetWidths`/`onResetWidth`.
- План 5a (B1, B7): `DataGrid` — новые пропы `rowState?: (row: Row) => RowState` и `openHint?: string`. Заблокированная запись (`kind: 'locked'`) — замок тона `warn` вместо иконки открытия (кнопка работает, приложение решает — только просмотр), полоса `warn-soft` 3 px слева, значения приглушены, статусная точка обесцвечена; `onOpen` получает третьим полем `state: RowState`. Неактивная запись (`kind: 'inactive'`) — штриховка ячеек, чекбокс `disabled`. Выделение исключает неактивные: `onSelectPage` отдаёт только id доступных записей. `BulkBar` дописывает «без неактивных» при `mode: 'all'` и наличии неактивных на странице.
