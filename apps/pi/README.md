# `apps/pi`

Прикладное приложение монорепо `katran`: реестры платёжных инструкций «Валютные документы» (`#/fx-docs`) и «Рублёвые документы» (`#/rub-docs`) на FSD, с переносимым швом данных (`requestFx`) и фейковым сервером на контракте `vtb-filters`. Собран на компонентах `@katran/ui` и моделях `@katran/effector` — кит, а не сам `apps/pi`, переиспользуется как библиотека.

Для команды, переносящей эти реестры во внутреннее приложение — `docs/guides/pi-usage.md`. Для бекенда — контракт эндпоинтов и состав строки — `docs/reference/pi-api.md`.

## Запуск

```sh
pnpm --filter pi dev
```

Dev-сервер — порт **5185**. Данные — фейковый сервер в браузере (`src/app/fake/`), 87 записей на каждый реестр, ходить в сеть не нужно.

## Тесты

```sh
pnpm --filter pi test   # vitest — мапперы, порты, createRegistry, компоненты, доступность (axe)
pnpm --filter pi e2e    # playwright — геометрия реестров и деталки на production-сборке
pnpm --filter pi visual # снимки вида (15) против эталонов — пиксель в пиксель, эталоны не обновляются без причины
pnpm --filter pi perf:base <коммит> && pnpm --filter pi perf   # скорость реестра против базы (срез styled)
```

`e2e` собирает приложение и поднимает превью на порту **5186** (`playwright.config.ts`, `webServer`) — отдельно от dev-порта 5185, чтобы не мешать друг другу при параллельном запуске.

Замер скорости (`perf/`, вне `pnpm check`): `perf:base` собирает приложение из заданного коммита во временном worktree в `perf/base`, `perf` — рабочую копию в `perf/head` и гоняет сценарии (первый показ, смена страницы, «выбрать все», смена темы; 50 и 200 записей; процессор обычный и ×4; прокрутка — справочно) по 8 кругов. Код 1 — сценарий хуже базы больше чем на 15 % (для действий короче 100 мс — по времени скриптов); у порога замер шумит — при коде 1 прогон повторяется целиком, провал — только если тот же сценарий хуже порога в обоих прогонах.

## Стили

`apps/pi` — образец кода для команды хоста (спека `docs/superpowers/specs/2026-10-13-katran-styled-design.md`, §4.7): styled-компоненты рядом с компонентом, шаблоны статические, как в ките, — токены объектом `k` из `@katran/tokens`, состояния атрибутами, без функций в шаблоне (правило eslint `APP_STYLED_RULES`; `theme.katran` под `KatranProvider` доступна, но в образце не используется). Свои элементы в ячейках реестра — правило 2: обычные элементы с классами (`fx…`, `rub…`) и один `createGlobalStyle` на сущность (`FxCellStyles`, `RubCellStyles`), который страница монтирует рядом с реестром; правило и числа — `docs/guides/pi-usage.md`, «Стили ячеек реестра».

## Регуляторы фейкового сервера

Только для разработки без бека (`src/app/fake/params.ts`) — у настоящего транспорта их нет:

| Параметр адреса | Действие |
|---|---|
| `?slow=N` | фиксированная задержка ответа `N` мс (по умолчанию — случайная 0,25–0,65 с) |
| `?fail=search` | `search` текущего грида отвечает `500` |
| `?fail=facets` | `facets` текущего грида отвечает `500` |
| `?fail=meta` | `filter-meta` текущего грида отвечает `500` |
| `?fail=suggest` | подсказки при вводе (`POST …/suggest`) отвечают `500` — список подсказок не появляется, фильтр работает |
| `?fail=detail` | деталь документа (`GET …/documents/{id}`) отвечает `500` — ошибка внутри drawer'а с «Повторить», реестр работает |
| `?fail=tab` | любая вкладка деталки (`GET …/documents/{id}/tabs/{tab}`) отвечает `500` — ошибка внутри вкладки с «Повторить», шапка и другие вкладки работают |
| `?fail=tab:<id>` | `500` только на вкладке `<id>` (`?fail=tab:audit`) |
| `?fail=edit` | сохранение правки (`POST …/documents/{id}/edits`) отвечает `500` — ошибка строкой под редактором, «Сохранить» — повтор (срез 2c) |
| `?fail=accounts` | справочник счетов (`GET …/documents/{id}/accounts`) отвечает `500` — «Не удалось загрузить счета» с «Повторить» в правке счёта |
| `?fail=decide` | утверждение и отклонение чужой правки (`POST …/documents/{id}/edits/{target}/confirm`, `…/reject`) отвечают `500` — текст ошибки в `Prompt` решения, кнопка доступна для повтора (срез 2d) |
| `?fail=message` | скачивание сообщения (`GET …/documents/{id}/message`) отвечает `500` — объявление с текстом ошибки |
| `?fail=print` | печатная форма (`GET …/documents/{id}/print/{form}`) отвечает `500` — вкладка «Формируется…» закрывается, объявление с текстом ошибки |
| `?conflict=edit` | любая правка отвечает `409` — «Документ изменили — откройте заново», деталь перезапрашивается |
| `?annul=instant` | аннулирование (`POST …/documents/{id}/annul`) исполняется сразу — статус «Отказ», плашка «Документ аннулирован» (срез 2e) |
| `?annul=pending` | аннулирование создаёт запрос на утверждение — плашка «Аннулирование ожидает утверждения» |
| `?annul=fail` | команда принята (`202`), но документ не меняется — объявление «Команда отправлена — документ пока в статусе «…»» |
| `?fail=annul` | аннулирование, утверждение и отклонение запроса (`…/annul`, `…/annul/confirm`, `…/annul/reject`) отвечают `500` — текст ошибки в `Prompt` |
| `?fail=rates` | курсы (`GET …/documents/{id}/rates`) отвечают `500` — ошибка с «Повторить» в поповере «Курс» |
| `?fail=balances` | остатки (`GET …/documents/{id}/balances`) отвечают `500` — ошибка с «Повторить» в поповере «Проверить баланс» |
| `?fail=resend` | переотправка нотификаций (`POST …/notifications/resend`, `…/{nid}/resend`) отвечает `500` — объявление текста ошибки |
| `?fail=notifmsg` | исходное сообщение (`GET …/notifications/{nid}/message`) отвечает `500` — ошибка с «Повторить» в окне |
| `?docs=N` | размер набора фейка — `N` документов на реестр (по умолчанию 87; замер скорости — 500) |
| `?size=N` | начальный размер страницы реестра |
| `?noauto` | без автооткрытия деталки первой записи при загрузке реестра |
| `?hostlinks=1` | не фейк, а стенд (`src/app/transport.ts`): включает ссылку «Перейти в блок «Ручные отклонения»» (`configureHostLinks`, адрес — `#/manual-deviations?doc=…` стенда) |

Без регулятора правило фейка: сумма больше 1 000 000 — запрос на утверждение, иначе сразу; повторная переотправка документа в течение 2 с — `409`.

Регуляторы читаются из `location.search`, поэтому ставятся **до** `#`: `http://localhost:5185/?fail=search#/fx-docs` — реестр валютных документов показывает состояние ошибки с кнопкой «Повторить».

Отдельно, вне регуляторов сервера — `?hostile` подключает `public/hostile.css` (глобальные стили «враждебного хоста») для проверки изоляции кита от окружения; используется в `e2e/isolation.spec.ts`.

## Деталка

Деталка «Платёжная инструкция» на просмотр (срезы 2a и 2b): кнопка открытия записи — drawer A, двойной клик или Shift — drawer B рядом для сравнения, Esc закрывает верхний; все вкладки валюты и рубля, нелокальные грузятся лениво (`GET …/documents/{id}/tabs/{tab}`), ID связанного документа открывает его в B; как подключить к своему реестру — `docs/guides/pi-usage.md` §13, как добавить вкладку — §13.7.

Правка валютной деталки (срез 2c): SWIFT-поля «Общих данных» по профилю, 20 исх, счета Дт/Кт из справочника, дата валютирования с подтверждением; маркер «изменено», аудит, ↺; уход с несохранённой правкой спрашивает «Отменить правку?». Рубль и заблокированные документы — только просмотр. Эндпоинты `POST …/documents/{id}/edits` и `GET …/documents/{id}/accounts?side=`; как подключить — `docs/guides/pi-usage.md` §14 (в другом реестре — §14.6).

Действия лейна и «вторая рука» (срез 2d): «Обновить» и F5, «Скопировать ссылку» (`#/<грид>?doc=<id>`, по ссылке открывается деталь), «Скачать» сообщение SWIFT/ED, «Печать» формы PDF во вкладке; у чужой правки — «Утвердить» и «Отклонить» (с причиной) в `fx-docs`. «Редактировать» из лейна убран. Эндпоинты `POST …/edits/{target}/confirm|reject`, `GET …/message`, `GET …/print/{form}`; как подключить — `docs/guides/pi-usage.md` §15.

Операции деталки (срез 2e): «Аннулировать» — команда беку с обязательной причиной, затем перезапрос детали; сразу или через утверждение второй рукой решает бек, плашка под лейном показывает запрос и итог (оба реестра). «Курс» в сводке `32A` (валюта) и «Проверить баланс» в блоке «Транзакции» (оба) — поповеры. Вкладка «Нотификации» — «Переотправить все» и «Переотправить» в строке, окно «Исходное сообщение»; вкладка «Задачи» — переход в блок «Ручные отклонения» хоста в новой вкладке (на стенде — с `?hostlinks=1`). «Создать служебный документ» — заглушка. Эндпоинты `POST …/annul`, `…/annul/confirm|reject`, `GET …/rates`, `GET …/balances`, `POST …/notifications/resend`, `…/notifications/{nid}/resend`, `GET …/notifications/{nid}/message`; как подключить — `docs/guides/pi-usage.md` §16.
