# Замер скорости реестра

Инструмент среза «Стилизация на styled-components»: сравнивает production-сборку `apps/pi` базового коммита (`perf/base`) с текущей (`perf/head`). Перенесён из опыта `spike/styled` (`apps/pi/spike/measure.mjs`, `table.mjs`): сценарии, порядок и счётчики прежние, четыре режима опыта заменены двумя сборками.

## Запуск

```sh
pnpm --filter pi perf:base <ref>   # собрать apps/pi из <ref> во временном worktree → perf/base
pnpm --filter pi perf              # собрать текущий apps/pi → perf/head, замер, таблица
pnpm --filter pi perf 4            # то же за 4 круга вместо 8 (быстрая прикидка, не для решения)
```

База собирается один раз и живёт до следующего `perf:base`. Сборки и `result.json` (выборки и медианы) в git не входят.
Проверка инструмента на себе: `pnpm --filter pi perf:base HEAD && pnpm --filter pi perf` — код 0, отличия в пределах шума.

## Что меряется

Адрес — `?slow=0&noauto&docs=500&size=N#/fx-docs`: фейк без задержки, 500 документов, без автооткрытия деталки, N записей на странице (регуляторы стенда описаны в `src/app/fake/params.ts`).

Сценарии для 50 и 200 записей, без троттлинга процессора (×1) и с замедлением ×4:

| Сценарий | Действие | Обязательный |
|---|---|---|
| `first` | переход по адресу → N записей на экране | да |
| `page` | страница 2 и обратно на 1 | да |
| `select` | «Выбрать все на странице» и снять | да |
| `theme` | тёмная тема и обратно | да |
| `scroll` | 40 шагов прокрутки по 120 px по кадрам: средний кадр и число кадров > 25 мс | справочно |
| `dom` | узлов в записях и правил в таблицах стилей | справочно |

Каждый замер — свежий контекст браузера; после действия ждётся условие и два кадра. Счётчики — `Performance.getMetrics` (CDP): полное время (стена), `ScriptDuration`, `RecalcStyleDuration`, `LayoutDuration`, `TaskDuration`. Круги (по умолчанию 8) чередуют порядок сборок, чтобы прогрев и троттлинг машины делились поровну; в таблице — медианы.

Клики идут внутри страницы по простому селектору: `getByRole` с именем перебирает тысячи кнопок в ячейках и сам добавляет ~1 с на действие.

## Порог

Код выхода 1 — обязательный сценарий head медленнее базы больше чем на 15 %. Мера — полное время; если у базы оно короче 100 мс, сравнивается время скриптов (полное время короткого действия тонет в ожидании кадров). Код 2 — нет сборки.
