# Katran: план устранения замечаний Антона и очередь компонентов Родиона

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Устранить пять открытых замечаний katran, проверяя фактический сценарий каждого, и выделить отдельную очередь реализации спецификаций Родиона.

**Architecture:** Исправления механизмов грида и drawer остаются в `@katran/ui`, доменная раскладка рубля — в `apps/pi`. Маршрутизация принадлежит приложению; жизненный цикл страницы и активность отдельного реестра рассматриваются раздельно. Новые компоненты поставляются после стабилизации существующих сценариев.

**Tech Stack:** React 17.0.2, effector 23, styled-components 5.3.11, pnpm, Vitest, Testing Library, Playwright; целевая платформа Chromium 88.

**Spec / исходные требования:** [issues katran](https://github.com/ivanklimenko/katran/issues), [PR Родиона №2](https://github.com/ivanklimenko/katran/pull/2), `docs/superpowers/specs/2026-09-23-katran-design.md`, `2026-09-29-katran-detail-view-design.md`, `2026-10-13-katran-styled-design.md`; руководство `docs/guides/pi-usage.md`, §15.3.

- Срез GitHub на **17 ноября 2026**: пять открытых issues №3–7, все от `abugaets` (Anton Bugaets), созданы 26 октября, обсуждений нет. В `ivanklimenko/pi-constructor` issues отсутствуют.
- Родион (`Starodubenko`, Rodion Starodubenko) внёс требования через PR №2, слитый 19 октября: 17 компонентов и отдельное решение о сегментном переключателе. Это очередь разработки, а не пять багов Антона.
- Локальный katran: `51e82c2`; GitHub main: `4fd42cd6eb1c2201f8cd8e15fce01d62bc2a5a8d`. GitHub compare подтвердил: отличие только в 19 файлах документации из PR №2, исходный код одинаков. Перед реализацией актуализировать рабочую ветку, сохранив чужие изменения.
- `pi-constructor` — эталон поведения и геометрии, не место для параллельного исправления перенесённых механизмов. Сгенерированные HTML вручную не править.
- `@katran/ui` не зависит от effector; модели создаются статически, вне React-рендера. Публичные изменения по возможности обратно совместимы.
- Статические styled-шаблоны через `packages/ui/src/styled.ts`, значения через `k`; состояния атрибутами. `GridRecord`, `GridSkeleton`, `value/` остаются на обычных элементах с классами `k-*`.
- Геометрию, CSS-каскад и прокрутку проверять в браузере: jsdom этого не доказывает. Совместимость Chromium 88 проверяется отдельно от современного Chromium Playwright.

## Review Focus

1. Однострочная запись, несколько `tr`, `rowSpan` и скрытые колонки должны иметь непрерывную внешнюю границу без удвоения линии.
2. Длинные наименования сторон и узкие колонки не должны перекрывать «НАЗН.» или ломать копирование полного значения.
3. Колесо над коротким drawer B и на границе длинного drawer не должно прокручивать реестр; реестр вне панелей остаётся доступным.
4. Документ по ссылке не должен подменяться первой строкой реестра после запоздалого ответа поиска; поведение хоста нужно проверить отдельно от демо.
5. Скрытый реестр не должен посылать запросы или принимать устаревший ответ прежней активации; переключение вкладки не должно терять фильтры и сортировку.

## Фаза 4. Активность отдельного реестра — [№4](https://github.com/ivanklimenko/katran/issues/4), P2

Приоритет повысить до P1, если сценарий с несколькими реестрами уже создаёт лишние запросы в хосте. Это изменение поведения композиции, а не механическая замена фабрики на Gate.

**Файлы:** `apps/pi/src/shared/lib/lifecycle/createPageLifecycle.ts`, `widgets/doc-registry/lib/createRegistry.ts`, композиция страницы; при необходимости `packages/effector/src/createGridModel.ts` и `useGrid.ts`; соответствующие тесты и `docs/guides/effector-fsd.md`.

**Контракт (реализован 17 ноября):** страница сохраняет route lifecycle; у каждого реестра есть собственная опциональная `$active: Store<boolean>`. Эффективная активность — открытая страница AND переданный стор; без опции — вся открытая страница. Скрытый реестр не запрашивает search/facets/подсказки/каталог, сохраняет фильтр/сортировку/страницу/настройки вида; скрытие снимает выделение и закрывает подсказки. Переход в активное состояние делает один search/facets с текущими параметрами, каталог кэшируется и не дублируется во время загрузки. Создание фабрики не запускает сеть, даже при начальном `$active = true`; без опции модель грида сохраняет ручной первый refresh, реестр — обновление на каждый pageOpened. Устаревшие search/facets/подсказки не принимаются. Запросы физически не отменяются; уже начатый запрос статического каталога может завершиться в кэш после скрытия.

- [x] Добавить воспроизведение с двумя моделями под одной страницей: видна одна вкладка; показать текущие лишние запросы второй. Включить случай, когда обе вкладки остаются смонтированы.
- [x] Зафиксировать в короткой спецификации API активности и обратную совместимость: старый потребитель без новой опции сохраняет прежнее поведение. Gate может быть адаптером mount/unmount; выбранная вкладка остаётся отдельным условием, если DOM сохраняется.
- [x] Разделить lifecycle страницы и активацию каждого реестра в композиции. Не создавать модели или `sample` внутри React-эффектов.
- [x] Защитить все исходящие триггеры search/facets: начальное открытие, фильтр, сортировка, page/pageSize, refresh/retry; отдельно проверить filter metadata и внешние `refreshRequested`.
- [x] Добавить идентификатор активации/визита к запросам и приёму ответов по образцу `createDetail`. Сравнения одной query недостаточно для hide/show с теми же параметрами. Физическую отмену HTTP не считать заменой проверке свежести ответа.
- [x] Проверить: скрытому меняют параметры — запросов нет; показ — один актуальный search/facets; hide/show во время запроса; старый ответ не перезаписывает новый; поздняя ошибка не меняет видимое состояние; метаданные не дублируются; выбор и настройки сохраняются по оговорённой политике.
- [x] Обновить пример двух реестров и руководство по статическому effector-графу.

**Готово:** скрытые виджеты не дают сетевую активность по всем перечисленным триггерам, старые ответы из предыдущей активации игнорируются; обычный один реестр сохраняет прежнее поведение.

**Проверка:** тесты `createRegistry` и `createGridModel`, обеих страниц; `pnpm --filter pi exec playwright test e2e/registry.spec.ts e2e/registry-persist.spec.ts e2e/lane-actions.spec.ts`; `pnpm check`.

## Отдельная очередь: спецификации Родиона из PR №2

Источник: [docs/features/required на зафиксированном main](https://github.com/ivanklimenko/katran/tree/4fd42cd6eb1c2201f8cd8e15fce01d62bc2a5a8d/docs/features/required). Документы изучены из полного diff PR; в локальном HEAD их пока нет. Это план очередности, а не детальный implementation plan для всех 17 компонентов.

Предлагаемый приоритет — P2 после исправлений; поднимать конкретный компонент по потребности хоста. Каждая волна допускает несколько независимых PR.

1. **Базовые элементы:** набор иконок, Spinner, Text, Link, Textarea, RadioGroup. Сначала закрыть публичные экспорты, доступные имена/клавиатуру и витрину; существующие внутренние части переиспользовать.
2. **Поля и диапазоны:** публичный TimeField, AmountField → AmountRange, NumberRange, TripleState, MaskedInput. Общие механизмы ввода проверить до составных контролов.
3. **Навигация и уведомления:** Breadcrumbs и очередь Toast, с проверкой портала, фокуса, доступных объявлений и таймеров.
4. **Подсветка и визуальные контроли:** Highlight, Slider, LineChart. Highlight остаётся в горячем пути без `styled.*`; график — SVG без новой runtime-библиотеки.

Всего: **6 + 6 + 2 + 3 = 17** компонентов. Отдельный Switch не добавляется: `switch/SPEC.md` предписывает `Tabs variant="segment"`; булев выбор остаётся у Checkbox.

До реализации уточнить технические места:

- **MaskedInput:** спецификация ссылается на `useMaskCaret`, но нынешний движок маски заточен под форматы даты/времени, а не `9 = цифра`. Нужен отдельный разбор общего механизма редактирования и тесты каретки/вставки, без регрессии DateInput/TimeField.
- **TimeField:** компонент уже существует внутри date, но публичного контракта спецификации пока нет. Расширять существующий компонент с сохранением поведения внутренних потребителей, включая текущий размер, а не создавать второй конкурирующий TimeField.
- **Toast:** `show(): void` не возвращает идентификатор, хотя `close(id)` его требует. В плане конкретного компонента определить, нужен ли внешний handle, и когда стартует таймер у ожидающего пятого тоста. Сам регион размещать внутри `KatranProvider`, сохраняя область CSS-переменных.
- **Slider / LineChart:** зафиксировать вырожденные входы до написания кода: `min >= max`, неположительный/дробный step и NaN у слайдера; одна точка, одинаковые min/max, все значения null и различающиеся категории серий у графика.
- **AmountField:** определить допустимый `fraction`, поведение нечисловых/бесконечных значений и внешнего обновления во время локального незавершённого ввода. `formatAmount` выдаёт разделитель групп NBSP — тест не должен ошибочно ожидать обычный пробел.

Для каждого компонента: прочитать его `SPEC.md`, определить точные экспорты и совместимость, добавить значимые поведенческие тесты, показать в demo на обеих темах, проверить `className`, disabled/invalid и плотность, выполнить `pnpm check`. Для геометрии/контраста/порталов добавить браузерные проверки; новые runtime-зависимости в UI по общей спецификации не добавлять.
