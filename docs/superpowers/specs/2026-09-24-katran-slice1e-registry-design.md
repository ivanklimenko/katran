# Срез 1e: экран реестра — лейн статусов, панель фильтров simple, массовые действия

Дата: 2026-09-24. Статус: согласовано с владельцем (решения от 24.09: полоса действий над пагинацией; панель как на стенде; счётчики лейна отдельным запросом фасетов; состояние — в двух существующих моделях). Дополняет основную спеку `2026-09-23-katran-design.md`: разделы 6.4, 7.1, 8.2–8.4 там правятся синхронно с этим документом, контракты ниже — те же, что в основной спеке.

## 1. Что поставляем

Три чистых компонента в `@katran/ui`, расширение двух моделей в `@katran/effector` и боевой экран «Валютные документы» в демо вместо страницы «Реестр». Эталон вида — стенд `pi-constructor` (`grid.html`): лейн «Все 87 · В работе 15 · К экспорту 6 · …», строка «Фильтры N» с чипами условий, сворачиваемая панель полей. Массовых действий на стенде нет (в футере только «выбрано 0») — `BulkBar` проектируется по основной спеке 6.3.

Вне среза (спека 7.2): advanced-режим, «Добавить фильтр», модификатор оператора у поля, наборы фильтров, справочники с поиском, диапазоны дат с пресетами, OR.

## 2. Принципы, которые тут работают

- **Один стор условий на экран.** Лейн и панель — два интерфейса к `$conditions` модели фильтров. Клик по лейну — это условие `EQ` по полю статуса; панель показывает его чипом и даёт снять; правка поля статуса в панели переключает лейн. Нет «быстрого фильтра» отдельно от «настоящего», как на стенде.
- **Кит не знает полей сущности.** Поле лейна, подписи и тона статусов, каталог полей панели — от приложения (`filter-meta` с бека). Кит знает только форму `Condition` и типы полей.
- **Состояние в моделях, UI чистый.** `StatusLane`, `FilterPanel`, `BulkBar` получают данные и колбэки пропами; в приложении с effector их даёт `useFilters`/`useGrid`. Единственное локальное состояние — раскрыта ли панель, и оно контролируемое (`open`/`onOpenChange`) — экран держит его в `useState`, как у `Tabs`.
- **Типы фильтра живут в `@katran/ui`.** Панели нужны `Condition`, `Filter`, `FilterMeta`, а `ui` не импортирует из `effector` (спека 3.2). Типы переезжают в `packages/ui/src/filters/types.ts`, `@katran/effector` их реэкспортирует — так же, как `Sort` и `Selection` (6.2). Это единственная правка существующего контракта.

## 3. Модель фильтров (8.3)

```ts
createFiltersModel({ meta?, initial?, laneField? })
```

- `laneField` — id поля, которым управляет лейн (в демо `status`). Без него `setLane` — no-op, `$lane` всегда `null`.
- `setLane: EventCallable<Scalar | null>` — `value` ставит `{ field: laneField, op: 'EQ', value }` **сразу в `$conditions` и в `$draft`** (лейн применяется без «Применить», как на стенде); `null` снимает условие поля из обоих. Неприменённые правки других полей в черновике не трогаются — как у `remove`.
- `$lane: Store<Scalar | null>` — производный: значение условия `EQ` по `laneField` в `$conditions`, иначе `null`. Условие с другим оператором по этому полю (например `IN` из панели) даёт `null`: лейн показывает «Все», чип в панели показывает условие. Панель в simple-режиме таких условий не создаёт.
- `revert: EventCallable<void>` — черновик ← применённые (кнопка «Отменить» панели). Отличие от `discard(field)`: снимает все неприменённые правки разом.
- Остальное без изменений: `edit`, `discard`, `apply`, `reset`, `remove`, `$dirty`, `meta`.

Правила связывания: `setLane` и `remove(laneField)` меняют `$conditions` → грид (8.2) получает новый `$filter`: страница 1, выделение сброшено, запрос, фасеты.

## 4. Модель грида: фасеты (8.2)

```ts
type Facet = { value: Scalar; count: number }
type FacetsQuery = { filter: Filter; field: string }

createGridModel({ …, facets?: { field: string; fetchFx: Effect<FacetsQuery, Facet[]> } })
```

- `$facets: Store<Facet[]>` — счётчики по значениям `facets.field`; без конфигурации всегда `[]`.
- Запрос уходит на каждую смену `$filter` и на `refresh`/`retry`, **по фильтру без условий по `facets.field`** — как на стенде: счётчики отвечают на вопрос «сколько будет, если нажать», а не «сколько сейчас». Смена страницы, сортировки, размера страницы фасеты не трогает.
- Транспорт — как у `requestFx`: своя копия `attach({ effect: fetchFx })`, ответ принимается только если `params` совпадает с текущим запросом фасетов (по значению). Отказ запроса фасетов не меняет `$state` грида и не показывается: `$facets` хранит последний удачный ответ — счётчики вспомогательные, реестр без них работает.
- В контракт `vtb-filters` предлагается `POST /grids/{gridId}/facets` с телом `{ filter, field }` и ответом `[{ value, count }]` (семантика фильтра — как у `search`). До согласования фейковый бэкенд демо считает фасеты сам.

## 5. Хуки (8.4)

- `useGrid(model)` дополнительно отдаёт `facets: Facet[]`, `onSelectAll: () => void`, `onClearSelection: () => void`.
- `useFilters(model)` дополнительно отдаёт `lane: Scalar | null`, `setLane`, `revert`, `meta: FilterMeta | null`.

## 6. Компоненты

### 6.1. `StatusLane`

```ts
type LaneItem = { value: Scalar; label: string; tone: StatusTone; count?: number }
type StatusLaneProps = {
  label: string                    // доступное имя группы: «Статусы»
  items: LaneItem[]
  value: Scalar | null             // активный статус; null — «Все»
  onChange: (value: Scalar | null) => void
  allLabel?: string                // «Все»
}
```

`<div role="group" aria-label>` из кнопок-переключателей (`Button` `size="s"` `variant="ghost"` с `pressed`): первая — «Все» со счётчиком-суммой `count` всех элементов (когда хотя бы у одного он задан), дальше по порядку `items`: `StatusDot` (`size="s"`, тон элемента, без буквы) + подпись + `Counter` (`data-zero` при 0, `active` у нажатой). Клик по активному — снятие (`onChange(null)`), как на стенде «Все». Одна строка без переноса, при нехватке ширины — горизонтальная прокрутка группы. Клавиатура — нативные кнопки, Tab по каждой. Приложение собирает `items` из своего словаря статусов и `facets` модели: `{ value, label: STATUS_LABEL[value], tone: STATUS_TONE[value], count }`; статусы с нулём остаются в лейне (счётчик 0), порядок — словаря приложения, не ответа бека.

### 6.2. `FilterPanel` (режим simple)

```ts
type FilterPanelProps = {
  label?: string                   // «Фильтры»
  meta: FilterMeta
  conditions: Filter
  draft: Filter
  dirty: boolean
  open: boolean
  onOpenChange: (open: boolean) => void
  onEdit: (c: Condition) => void
  onDiscard: (field: string) => void
  onApply: () => void
  onRevert: () => void
  onReset: () => void
  onRemove: (field: string) => void
}
```

**Строка состояния** (видна всегда): кнопка `label` с `Counter` числа применённых условий (`aria-expanded`, `aria-controls` тела); список чипов (`<ul>` с доступным именем «Применённые условия»); при пустом фильтре — приглушённый текст «условия не заданы»; при непустом — кнопка «Сбросить» (`ghost`, `size="s"`) → `onReset`.

**Чип** — `<li>`: текст `describeCondition(c, meta)` — «Статус = К экспорту», «Сумма > 100 000», «Дата от 01.09.2026 до 13.09.2026», «Приказодатель содержит „Василёк“» — и `IconButton` ✕ с именем «Убрать условие: …» → `onRemove(field)`. Значение ENUM — подпись из справочника `meta`, DATE — `дд.мм.гггг`, DATETIME — `дд.мм.гггг чч:мм`, BOOLEAN — да/нет, STRING — в кавычках „…“, число — как есть; даты форматируются из строки без учёта зоны исполнения. Оператор — из словаря `OP_LABEL` (`ui/filters/opLabels.ts`, русский): `EQ` «=», `NE` «≠», `CONTAINS` «содержит», `STARTS_WITH` «начинается с», `ENDS_WITH` «заканчивается на», `GT` «>», `GTE` «≥», `LT` «<», `LTE` «≤», `BETWEEN` «от … до», `IN` «в списке», `NOT_IN` «не в списке», `IS_EMPTY` «пусто», `IS_NOT_EMPTY` «не пусто». Чип условия по полю лейна ничем не выделяется.

**Тело** (`open`): поля из `meta.fields` в порядке каталога, сеткой с автопереносом (минимальная ширина поля — токен `filter-field`), у каждого — `<label>` с `label` поля. Оператор по типу — фиксированный, модификатора нет:

| Тип | Контрол | Оператор | Пусто → |
|---|---|---|---|
| STRING | `Input` | `CONTAINS` | `onDiscard` |
| NUMBER | `Input` `inputMode="decimal"` | `EQ` (число) | `onDiscard` |
| DATE | `Input type="date"` | `EQ` (`YYYY-MM-DD`) | `onDiscard` |
| DATETIME | два `Input type="date"` «с» / «по» | `BETWEEN` (начало дня `from`, конец дня `to`, ISO со смещением) | оба пустые → `onDiscard` |
| ENUM | `Select` со значениями `meta` и пустым пунктом | `EQ` | `onDiscard` |
| BOOLEAN | `Select` «да / нет» и пустой пункт | `EQ` | `onDiscard` |

Поле, чей единственный допустимый оператор из `ops` не совпадает с оператором по типу, берёт первый допустимый из `ops` этой же формы (скаляр); поле, у которого нет ни одного скалярного оператора, в simple-режиме не показывается. Значение поля — из `draft`; ввод → `onEdit` с полным условием. Enter в любом поле → `onApply`. Кнопки тела: «Применить» (`primary`, `disabled` без `dirty`) → `onApply`; «Отменить» (`ghost`, `disabled` без `dirty`) → `onRevert`. После `onApply` панель не сворачивается сама — это решает экран.

### 6.3. `BulkBar`

```ts
type BulkBarProps = {
  label?: string                   // «Массовые действия»
  selection: Selection
  total: number
  onClear: () => void
  onSelectAll?: () => void         // нет — нет перехода в режим «всё по фильтру»
  children?: ReactNode             // действия приложения
}
```

Счёт: `mode: 'ids'` → `ids.length`, `mode: 'all'` → `total − except.length`. При нуле не рендерится. Иначе — `<div role="region" aria-label>`: текст «Выбрано N» или «Все N по фильтру»; в режиме `ids`, когда есть `onSelectAll` и `N < total` — кнопка «Выбрать все `total` по фильтру» (`ghost`, `size="s"`); кнопка «Снять выделение» → `onClear`; справа — `children`. Смена числа объявляется через `useKatran().announce` («Выбрано 3»). Полоса не знает действий: приложение передаёт свои кнопки и само вызывает бек с `{ filter, selection }` (6.3 основной спеки).

### 6.4. Слот в `DataGrid`

`toolbar?: ReactNode` — рендерится в футере грида над пагинацией, в одном блоке с ней (`.foot`): полоса не наезжает на записи и не двигает шапку. Экран передаёт `<BulkBar …/>`; пустой `toolbar` не занимает места.

## 7. Экран «Валютные документы» (демо)

Страница `/#/grid` (в меню — «Реестр») становится боевым экраном: заголовок «Валютные документы» + `Counter` общего числа (`total` грида); `StatusLane`; `FilterPanel` (`open` в `useState`, по умолчанию свёрнута); `DataGrid` с `toolbar={<BulkBar …/>}`; блок «Сквозные строки записи» остаётся. Действия полосы — «Экспортировать» и «Отложить» (`Button size="s"`): объявляют через LiveRegion «Экспорт: выбрано N» и ничего не делают.

Фейковый бэкенд (`apps/demo/src/data/fakeBackend.ts`) отдаёт `{ searchFx, facetsFx, filterMeta }`. `filterMeta` — девять полей: `docNumber` NUMBER, `status` ENUM (справочник из `STATUS_LABEL`), `type` ENUM, `direction` ENUM (с подписями), `currency` ENUM, `amount` NUMBER, `created` DATE, `f50name` STRING, `f59name` STRING. `matches()` для DATE сравнивает по дню (`YYYY-MM-DD`), для DATETIME — строкой ISO; `facetsFx` считает по `applyFilter(all, filter)` количество на каждое значение `field`, с той же задержкой, что у `searchFx`.

## 8. Проверки

- Модели (`fork`/`allSettled`): `setLane` ставит и снимает условие в обоих сторах, не трогая черновик других полей; `$lane` следует за `$conditions` (снятие чипа, `reset`, `IN` → `null`); `revert`; фасеты — запрос без условия по полю лейна, устаревший ответ отбрасывается, отказ не портит `$facets` и `$state`; смена страницы фасеты не запрашивает.
- Компоненты (`renderK`, роли, `axe`): лейн — `aria-pressed`, сумма «Все», клик по активному снимает; панель — чипы описывают условия, ✕ снимает, Enter применяет, `Отменить` откатывает, поля по типам ставят верный оператор, пустое значение снимает условие; полоса — тексты режимов, «Выбрать все», объявление, не рендерится при нуле; `DataGrid` с `toolbar` — слот в футере, без него футер прежний.
- e2e без изменений (геометрия записи). Экран сверяется с эталоном в браузере контроллером после исполнения плана.
