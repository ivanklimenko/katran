# Поля ввода для фильтров: даты, справочники с поиском, подсказки

Дата: 2026-09-30. Статус: согласовано с владельцем по частям (состав — даты, справочники с поиском, подсказки с бека; справочник в панели — мультиселект, одно значение = `EQ`; реализация — свои компоненты на поповере кита; подсказки — модель фильтров и `suggestFx` приложения; `apps/pi` — после слияния плана 2a). Дополняет основную спеку `2026-09-23-katran-design.md` (§5.1, 7.1, 8.3, 8.4) и спеку среза 1e `2026-09-24-katran-slice1e-registry-design.md` (§3, §6.2); после исполнения эти разделы правятся синхронно.

## 1. Что и зачем

Панель фильтров сейчас собрана на нативных контролах: `<input type="date">` для дат и `<select>` для справочников. У них нет пресетов периода, выбора нескольких значений, поиска по длинному справочнику и подсказок при вводе; вид расходится между браузерами и темами. Контракт `vtb-filters` при этом уже описывает справочники с `IN` по умолчанию, а прототип `vtb-filters` и стенд `pi-constructor` — мультиселект с чипами и подсказки к текстовым полям.

Срез поставляет пять общих контролов `@katran/ui`, подсказки в модели фильтров и новую раскладку полей панели:

| Компонент | Назначение |
|---|---|
| `DateInput` | одна дата: ввод по маске `дд.мм.гггг` и календарь |
| `DateRange` | период «с — по»: две даты, календарь выбора диапазона, пресеты |
| `SearchSelect` | одно значение из справочника с поиском |
| `MultiSelect` | несколько значений из справочника: чипы, поиск, «Выбрано N · Очистить» |
| `SuggestInput` | свободный текст с подсказками, которые приходят с бека |

Контролы общие: панель фильтров подключает их по типу поля, деталка (срез 2) и формы берут те же.

Вне среза: серверные справочники `LOOKUP` (`GET /dictionaries/{id}` с пагинацией), диапазон чисел, модификатор оператора у поля, «Добавить фильтр», наборы фильтров, время внутри DATETIME. Всё это — advanced (основная спека §7.2); контролы среза проектируются так, чтобы `LOOKUP` лёг на тот же механизм, что и подсказки (§7).

## 2. Принципы

- **Свои компоненты, без новых зависимостей.** Выпадающие части строятся на существующем `Popover` кита (`@floating-ui/dom`, портал в корень провайдера, Escape и клик вне). Причина — ограничения хоста: React 17–19, Chromium 88, поставка в закрытый контур копированием (спека совместимости). Библиотеки дат и комбобоксов либо не поддерживают React 17, либо добавляют зависимости, которые придётся нести в контур.
- **Даты — строки `ГГГГ-ММ-ДД`.** Компоненты и помощники не разбирают ISO через `new Date()`: разбор строки без зоны трактуется браузером как UTC и сдвигает день в западных зонах. «Сегодня» берётся из локальных часов (`getFullYear/getMonth/getDate`), дальше — только арифметика по строкам. Так же уже устроены чипы (спека 1e, Ruling 3) и `formatDate` (план 4).
- **Контролируемые и чистые.** Значение и колбэк — пропы; локальное состояние — только открыт ли поповер, текст поиска и активный пункт. Состояние подсказок живёт в модели фильтров, транспорт — в приложении, как у `fetchFx` и фасетов.
- **WAI-ARIA.** Комбобоксы — паттерн `combobox` + `listbox` с `aria-activedescendant`, календарь — `grid`. Все интерактивные части — настоящие `<button>`/`<input>` с доступным именем.

## 3. Даты

### 3.1. `dateStr` — помощники

Чистые функции в `packages/ui/src/date/dateStr.ts`, публичные (нужны приложениям для пресетов и валидации):

```ts
type IsoDay = string                                   // 'ГГГГ-ММ-ДД'
isValidDay(s: string): boolean                        // календарная проверка: 2026-02-31 — false, 2024-02-29 — true
parseRuDay(text: string): IsoDay | null               // 'дд.мм.гггг' → IsoDay; неполная или невалидная — null
formatRuDay(day: IsoDay): string                      // IsoDay → 'дд.мм.гггг'
addDays(day: IsoDay, n: number): IsoDay
addMonths(day: IsoDay, n: number): IsoDay              // 31.01 + 1 мес. → 28/29.02 (последний день месяца)
startOfMonth(day: IsoDay): IsoDay
endOfMonth(day: IsoDay): IsoDay
weekday(day: IsoDay): 1 | 2 | 3 | 4 | 5 | 6 | 7       // понедельник = 1
monthGrid(month: IsoDay): IsoDay[]                     // 42 дня: 6 недель с понедельника, включая хвосты соседних месяцев
todayLocal(): IsoDay                                   // по локальным часам машины
compareDays(a: IsoDay, b: IsoDay): -1 | 0 | 1          // строковое сравнение
```

Арифметика — через дни от эпохи, вычисленные по формуле григорианского календаря, без объекта `Date`.

### 3.2. `Calendar`

```ts
type CalendarProps = {
  month: IsoDay                       // любой день показываемого месяца
  onMonthChange: (month: IsoDay) => void
  value?: IsoDay | '' | undefined      // одна дата
  range?: { from: IsoDay | ''; to: IsoDay | '' } | undefined   // подсветка диапазона
  onPick: (day: IsoDay) => void
  min?: IsoDay | undefined
  max?: IsoDay | undefined
  today?: IsoDay | undefined           // по умолчанию todayLocal(); проп — для тестов
  label: string                        // доступное имя сетки: «Январь 2026»
}
```

Шапка: «‹ Сентябрь 2026 ›» — кнопки предыдущего и следующего месяца. Сетка — `<table role="grid">` из 6 недель, дни недели «Пн … Вс» в `<th>`, дни соседних месяцев приглушены и выбираемы. Отмечены: сегодня (рамка), выбранный день или границы диапазона (заливка `val`), дни внутри диапазона (`val-soft`), недоступные вне `min`/`max` (`aria-disabled`, не выбираются).

Клавиатура (APG Date Picker Dialog): один таб-стоп на сетке, стрелки — день и неделя, Home/End — начало и конец недели, PgUp/PgDn — месяц, Shift+PgUp/PgDn — год, Enter/Space — выбрать. Уход фокуса за край месяца листает месяц.

### 3.3. `DateInput`

```ts
type DateInputProps = {
  value: IsoDay | ''
  onChange: (value: IsoDay | '') => void
  min?: IsoDay | undefined
  max?: IsoDay | undefined
  disabled?: boolean | undefined
  size?: 's' | 'm' | undefined
  id?: string | undefined
  'aria-label'?: string | undefined
  placeholder?: string | undefined     // по умолчанию «дд.мм.гггг»
}
```

Поле текста с маской: цифры подставляются в `дд.мм.гггг`, точки ставятся сами, лишние символы не вводятся. Пока дата неполная, наружу ничего не уходит; полная и валидная — `onChange(IsoDay)`; полная, но невалидная или вне `min`/`max` — поле `invalid`, наружу `''`. Очистка поля — `onChange('')`. Справа — кнопка-иконка «Выбрать дату» (`aria-haspopup="dialog"`), открывает поповер с `Calendar` на месяце значения или текущем; выбор дня ставит значение и закрывает поповер, фокус возвращается в поле. Внешняя смена `value` перерисовывает текст, если он не совпадает с тем, что человек набирает (тот же принцип, что у числового поля панели, спека 1e §6.2).

### 3.4. `DateRange`

```ts
type DayRange = { from: IsoDay | ''; to: IsoDay | '' }
type DatePreset = { id: string; label: string; range: (today: IsoDay) => { from: IsoDay; to: IsoDay } }
type DateRangeProps = {
  value: DayRange
  onChange: (value: DayRange) => void
  presets?: DatePreset[] | undefined   // по умолчанию DEFAULT_PRESETS; [] — без пресетов
  min?: IsoDay | undefined
  max?: IsoDay | undefined
  today?: IsoDay | undefined
  disabled?: boolean | undefined
  size?: 's' | 'm' | undefined
  label: string                        // имя группы: название поля
}
```

Два поля по маске «с» и «по» в одной рамке (`role="group"`, `aria-label`), общая кнопка календаря. Поповер: слева список пресетов, справа календарь. Выбор диапазона в календаре — двумя кликами: первый ставит «с» и сбрасывает «по», второй ставит «по»; если второй день раньше первого, границы меняются местами. Наведение между кликами подсвечивает будущий диапазон. Пресет ставит обе границы и закрывает поповер.

`DEFAULT_PRESETS` (экспортируются, приложение может собрать свой список из них): «Сегодня», «Вчера», «7 дней» (сегодня и 6 предыдущих), «30 дней», «Текущий месяц» (с 1-го по сегодня), «Прошлый месяц» (весь).

Правило ввода руками: «по» раньше «с» — поле «по» `invalid`, наружу уходит только «с».

## 4. Справочники

### 4.1. Общее

`type Option = { value: Scalar; label: string; hint?: string | undefined }` — `hint` показывается приглушённо справа (код, BIC). Поиск без учёта регистра по вхождению в `label`, `hint` и строковое `value`. Список в поповере — `role="listbox"`, высота ограничена токеном `menu-max-h`, активный пункт прокручивается в видимую часть. Ввод в поиск сбрасывает активный пункт на первый найденный. Пустой результат — строка «Ничего не найдено».

### 4.2. `SearchSelect`

```ts
type SearchSelectProps = {
  options: Option[]
  value: Scalar | null
  onChange: (value: Scalar | null) => void
  placeholder?: string | undefined     // «Не выбрано»
  clearable?: boolean | undefined      // по умолчанию true: кнопка ✕ «Очистить»
  searchable?: boolean | undefined     // по умолчанию — если вариантов больше 7
  disabled?: boolean | undefined
  size?: 's' | 'm' | undefined
  id?: string | undefined
  'aria-label'?: string | undefined
}
```

С поиском — `input role="combobox"` (`aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-autocomplete="list"`): поле показывает подпись выбранного, фокус и ввод открывают список и фильтруют его; уход фокуса без выбора возвращает подпись выбранного. Без поиска — `button` с `aria-haspopup="listbox"`, список открывается по Enter/Space/↓, буква переводит к первому пункту на неё (typeahead). Клавиатура: ↑/↓ — пункт, Enter — выбрать и закрыть, Escape — закрыть без выбора, Home/End — первый и последний.

### 4.3. `MultiSelect`

```ts
type MultiSelectProps = {
  options: Option[]
  value: Scalar[]
  onChange: (value: Scalar[]) => void
  placeholder?: string | undefined     // «Не выбрано»
  maxChips?: number | undefined        // по умолчанию 2: дальше «+N»
  disabled?: boolean | undefined
  size?: 's' | 'm' | undefined
  id?: string | undefined
  'aria-label'?: string | undefined
}
```

Поле — `button` с `aria-haspopup="listbox"`: чипы первых `maxChips` выбранных в порядке `options`, затем «+N»; у каждого видимого чипа ✕ снимает значение, не открывая список. Поповер: сверху поле поиска (`combobox`, фокус при открытии), под ним `listbox` с `aria-multiselectable="true"`, пункты — чекбокс и подпись, `aria-selected` у выбранных; Enter/Space переключает активный пункт, список не закрывается. Подвал: «Выбрано N» и кнопка «Очистить» (недоступна при нуле). Выбранные в поиске не скрываются — отмечены чекбоксом. Порядок `value` в `onChange` — порядок `options`, не порядок кликов: условие `IN` стабильно при одном и том же наборе. Контракт ограничивает `IN` 500 значениями, а встроенные (`INLINE`) справочники по контракту — десятки значений, поэтому в simple-режиме лимит недостижим и не проверяется; проверка понадобится серверным справочникам (`LOOKUP`, вне среза).

## 5. `SuggestInput`

```ts
type SuggestInputProps = {
  value: string
  onChange: (value: string) => void
  suggestions: string[]
  loading?: boolean | undefined
  onQuery: (query: string) => void     // каждое изменение текста, в том числе фокус с непустым текстом
  onClose: () => void                   // подсказки больше не нужны: уход фокуса, Escape, выбор
  disabled?: boolean | undefined
  size?: 's' | 'm' | undefined
  id?: string | undefined
  'aria-label'?: string | undefined
  placeholder?: string | undefined
}
```

`input role="combobox"` с `aria-autocomplete="list"`: список открыт, пока в `suggestions` есть элементы или идёт загрузка (строка «Ищу…»). ↑/↓ — активная подсказка, Enter с активной подсказкой — подставить её текст и закрыть список; Enter без активной подсказки не перехватывается — внутри формы панели он отправляет форму и применяет фильтр. Escape закрывает список, второй Escape обычным путём уходит дальше. Совпадение с набранным текстом в подсказке выделяется полужирным.

## 6. Панель фильтров

### 6.1. Контрол по типу поля

| Тип | Контрол | Условие из значения |
|---|---|---|
| STRING | `SuggestInput`, если у поля `suggest: true`; иначе `Input` | непустой текст — `CONTAINS` (как сейчас); выбранная подсказка — тот же `CONTAINS` с её текстом |
| NUMBER | `Input` (как сейчас) | `EQ` |
| DATE | `DateRange` | обе границы: равны — `EQ`, различны — `BETWEEN`; только «с» — `GTE`; только «по» — `LTE` |
| DATETIME | `DateRange` | то же на границах дня: «с» — `isoDayStart`, «по» — `isoDayEnd`; равные границы — `BETWEEN` за день |
| ENUM | `MultiSelect` из встроенного справочника | одно значение — `EQ`, два и больше — `IN` |
| BOOLEAN | `SearchSelect` без поиска: «да», «нет» | `EQ` |

Сужение операторов метой (`FilterField.ops` не пуст): если нужного оператора нет, берётся ближайший допустимый — для дат без `GTE`/`LTE` одна граница сводится к дню (`EQ` для DATE, `BETWEEN` за день для DATETIME), без `BETWEEN` различные границы недоступны (второе поле `disabled`); для ENUM без `IN` мультиселект ограничен одним значением. Поле, у которого не остаётся ни одного подходящего оператора, в simple-режиме не показывается (как сейчас).

`draftOf`/`conditionFrom` (`fieldOps.ts`) переходят на новые сырые значения: `string` для STRING/NUMBER/BOOLEAN, `DayRange` для DATE/DATETIME, `Scalar[]` для ENUM.

### 6.2. Лейн

Лейн ставит `EQ` по `laneField` (спека 1e §3) — мультиселект того же поля показывает один выбранный чип. Выбор в панели одного значения даёт `EQ`, и лейн подсвечивает его; двух и больше — `IN`, `$lane = null`, лейн показывает «Все». Правило `$lane` не меняется.

### 6.3. Чипы условий

`describeCondition`/`conditionParts` (`opLabels.ts`) добавляют тексты для дат: `GTE` по DATE/DATETIME — «Дата документа с 01.09.2026», `LTE` — «… по 13.09.2026», `BETWEEN` — «… с 01.09.2026 по 13.09.2026» (было «от … до»); у DATETIME, если границы — ровно начало и конец дня, время не показывается. `IN` по ENUM — «Статус в списке Ошибка, Отказ» (как сейчас).

### 6.4. Enter и «Применить»

Поля по-прежнему внутри `<form>` тела панели. Enter в `Input`, `SuggestInput` без активной подсказки и в полях дат отправляет форму (`onApply`, если есть изменения). В комбобоксах и календаре Enter выбирает пункт и форму не отправляет — применяют кнопкой «Применить» (как сейчас у нативного `Select`, спека 1e §6.2, Ruling 4).

## 7. Подсказки: модель

### 7.1. Мета

`FilterField.suggest?: boolean | undefined` — у поля есть подсказки. В контракте `vtb-filters` — одноимённое поле в `filter-meta` (§8). Флаг имеет смысл только у STRING.

### 7.2. `createFiltersModel`

```ts
type SuggestQuery = { field: string; query: string; filter: Filter; limit: number }

createFiltersModel({
  …,
  suggest?: {
    fetchFx: Effect<SuggestQuery, string[]>   // даёт приложение
    delay?: number                              // мс, по умолчанию 250
    minChars?: number                           // по умолчанию 1
    limit?: number                              // по умолчанию 10
  },
})
```

Добавляется в модель:

- `suggest: EventCallable<{ field: string; query: string }>` — ввод в поле.
- `closeSuggest: EventCallable<void>`.
- `$suggest: Store<SuggestState | null>`, где `type SuggestState = { field: string; query: string; items: string[]; loading: boolean }` (тип экспортируется из `@katran/ui`, `filters/types.ts`, — панели он нужен в пропах).

Правила:

- `suggest` с текстом короче `minChars` — `$suggest = { field, query, items: [], loading: false }`, запроса нет.
- Иначе `$suggest.loading = true`, прежние `items` остаются до ответа; запрос уходит через `delay` мс после последнего `suggest`, если за это время не пришёл новый `suggest` или `closeSuggest`. Задержка — эффект-таймер модели (без `setTimeout` в компоненте), под `fork` тестируется фейковыми таймерами.
- `filter` запроса — применённые условия (`$conditions`) без условий по самому полю, как у фасетов (спека 1e §4).
- Транспорт — своя `attach`-копия `fetchFx`; ответ принимается, только если его `params` совпадают с последним отправленным запросом по значению. Ошибка — `items: []`, `loading: false`, без сообщения.
- `closeSuggest` — `$suggest = null`; поздний ответ после закрытия отбрасывается.

### 7.3. Хук и панель

`useFilters` дополнительно отдаёт `suggest: SuggestState | null`, `onSuggest`, `onSuggestClose`. `FilterPanelProps` получает необязательные `suggest`, `onSuggest`, `onSuggestClose`: без них поля с `suggest: true` работают как обычный `Input`. Панель передаёт `suggestions` и `loading` только полю, чьё имя в `suggest.field`.

## 8. Предложение в контракт `vtb-filters`

Для владельца контракта — отдельным документом `docs/reference/suggest-proposal.md`:

- `filter-meta`: у поля необязательный `suggest: boolean` (по умолчанию `false`) — бек включает подсказки там, где они дешёвые (индекс по полю).
- `POST /grids/{gridId}/suggest`, тело `{ field, query, filter, limit }`, ответ `{ items: string[] }`. Семантика: различные значения поля среди записей, удовлетворяющих `filter`, содержащие `query` без учёта регистра; не больше `limit` (1–50, по умолчанию 10); порядок — по убыванию частоты, при равенстве — по алфавиту. Поле без `suggest: true` — `400 SUGGEST_NOT_SUPPORTED`; права — как у `search`.
- Серверные справочники `LOOKUP` (§6.1 контракта) в будущем подключаются к тем же контролам: `SearchSelect`/`MultiSelect` получат режим «варианты с бека» с тем же паттерном `onQuery` → модель → `suggestFx`-подобный эффект.

## 9. Демо и `apps/pi`

- **Демо, страница «Поля ввода»:** все пять контролов в состояниях «пусто», «заполнено», «ошибка», «недоступно»; `DateRange` с пресетами и без; `MultiSelect` на 30 вариантах; `SuggestInput` с фейковым источником. Обе темы переключаются шапкой демо.
- **Демо, экран «Реестр»:** панель на новых контролах; фейковый бэкенд отдаёт `suggestFx` — уникальные значения поля по выборке, как стенд; в `docsFilterMeta` у текстовых полей `suggest: true`.
- **`apps/pi` (после слияния плана 2a в `main`):** `suggest: true` у полей 20 вх и 20 исх, наименования и счета 50/59, BIC; порт `suggestFx` в `shared/api`, маршрут `POST …/suggest` фейкового сервера, контрактный тест, `docs/reference/pi-api.md`.

## 10. Совместимость и токены

- React 17: идентификаторы — `useStableId` кита, не `useId`; никаких API React 18+ (линт плана 4 это проверяет).
- Chromium 88: без `:has`, `inert`, `Array.prototype.at`, `structuredClone`; `Intl.DateTimeFormat` не используется — названия месяцев и дней недели — словарь кита на русском.
- Новые размеры — через `tokens.src.ts`: ячейка календаря `cal-cell: 28`, ширина колонки пресетов `preset-w: 140`. Цвета — существующие токены (`val`, `val-soft`, `faint`, `line`, `chip`).
- Высота контролов равна высоте `Input` того же `size` — поля фильтров в одной строке не пляшут.

## 11. Проверки

- **Модульные:** `dateStr` — високосные годы, 31.02, границы месяцев, маска ввода, `addMonths` на 31-е; прогон при `TZ=UTC`, `Europe/Moscow` и `America/New_York` с одинаковым результатом.
- **Компоненты (jsdom, роли, axe):** календарь — клавиатура и листание, `min`/`max`; `DateInput` — маска, невалидная дата, календарь; `DateRange` — выбор двумя кликами, обмен границ, пресеты с фиксированным `today`; `SearchSelect` и `MultiSelect` — поиск, клавиатура, чипы, «+N», «Очистить», `aria-activedescendant`; `SuggestInput` — Enter с подсказкой и без, Escape.
- **Модель (fork, фейковые таймеры):** задержка, `minChars`, отбрасывание устаревшего ответа и ответа после `closeSuggest`, ошибка, `filter` без условий по полю.
- **Панель:** маппинг каждого типа в условие по таблице §6.1, сужение операторов метой, лейн ↔ мультиселект, чипы дат.
- **e2e (Chromium):** поповеры у правого и нижнего края окна не выходят за экран; высота контролов рядом с кнопками; проход панели клавиатурой; обе темы (скриншоты); выбор периода пресетом и календарём в экране «Реестр».

## 12. Открытое

- Эндпоинт `suggest` и флаг `suggest` в `filter-meta` — предложение владельцу контракта `vtb-filters`; до согласования форма `SuggestQuery` — черновик кита.
- Пресеты по умолчанию — по опыту реестров; если операторам нужны «Неделя с понедельника» или «Квартал», они добавляются в список без изменения API.
