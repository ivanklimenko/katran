## 1. Что и зачем

Панель фильтров сейчас собрана на нативных контролах: `<input type="date">` для дат и `<select>` для справочников, а текстовое поле принимает одну строку. Нет времени и пресетов периода, выбора нескольких значений из справочника, поиска по длинному справочнику, ввода списка ID, поиска по нескольким фразам и подсказок; вид расходится между браузерами и темами. Контракт `vtb-filters` при этом уже описывает `IN` по умолчанию для справочников, `defaultOperator` у поля и несколько условий по одному полю (объединяются по AND, контракт §4.4), а прототип `vtb-filters` и стенд `pi-constructor` — мультиселект с чипами и подсказки к текстовым полям.

Срез поставляет пять общих контролов `@katran/ui`, подсказки и несколько условий на поле в модели фильтров и новую раскладку полей панели:

| Компонент | Назначение |
|---|---|
| `DateInput` | одна дата или дата со временем: ввод по маске из шаблона формата, календарь |
| `DateRange` | период «с — по» с датами или датами и временем: календарь выбора диапазона, пресеты в поповере, горячие кнопки под полем |
| `SearchSelect` | одно значение из справочника с поиском |
| `MultiSelect` | несколько значений из справочника: чипы, поиск, «Выбрано N · Очистить» |
| `TagInput` | несколько значений или фраз свободным вводом: чипы, разбор вставки, подсказки с бека |

Контролы общие: панель фильтров подключает их по типу поля, деталка и формы берут те же.

Вне среза: серверные справочники `LOOKUP` (`GET /dictionaries/{id}` с пагинацией), диапазон чисел, модификатор оператора у поля, «Добавить фильтр», наборы фильтров, OR между условиями. Всё это — advanced (основная спека §7.2). Контролы среза проектируются так, чтобы `LOOKUP` лёг на тот же механизм, что и подсказки (§8).

## 2. Принципы

- **Свои компоненты, без новых зависимостей.** Выпадающие части строятся на существующем `Popover` кита (`@floating-ui/dom`, портал в корень провайдера, Escape и клик вне). Для списков комбобоксов у `Popover` появляется роль `presentation`: всплывающий элемент по паттерну — сам `listbox`, обёртка с ролью `dialog` сбивала бы скринридер. Причина — ограничения хоста: React 17–19, Chromium 88, поставка в закрытый контур копированием (спека совместимости). Библиотеки дат и комбобоксов либо не поддерживают React 17, либо добавляют зависимости, которые придётся нести в контур.
- **Даты — строки, без зоны.** Значения — `ГГГГ-ММ-ДД` и `ГГГГ-ММ-ДДTчч:мм` («настенное» время). Компоненты и помощники не разбирают их через `new Date()`: разбор строки без зоны трактуется браузером как UTC и сдвигает день в западных зонах. «Сегодня» берётся из локальных часов (`getFullYear/getMonth/getDate`), дальше — только арифметика по строкам. Смещение зоны добавляется один раз — при сборке условия для DATETIME (`isoDayStart`/`isoDayEnd` и их аналог для минуты). Так же уже устроены чипы (спека 1e, Ruling 3) и `formatDate` (план 4).
- **Формат вывода — проп, значение — ISO.** Шаблон формата меняет только то, что человек видит и вводит; наружу всегда уходит ISO-строка.
- **Контролируемые и чистые.** Значение и колбэк — пропы; локальное состояние — открыт ли поповер, набираемый текст, текст поиска и активный пункт. Состояние подсказок живёт в модели фильтров, транспорт — в приложении, как у `fetchFx` и фасетов.
- **WAI-ARIA.** Комбобоксы — паттерн `combobox` + `listbox` с `aria-activedescendant`, календарь — `grid`. Все интерактивные части — настоящие `<button>`/`<input>` с доступным именем.

## 3. Даты и время

### 3.1. Значения и формат

```ts
type IsoDay = string        // 'ГГГГ-ММ-ДД'
type IsoMinute = string     // 'ГГГГ-ММ-ДДTчч:мм' — настенное время, без секунд и зоны
type DateValue = IsoDay | IsoMinute | ''
type DateFormat = string    // шаблон: 'DD.MM.YYYY', 'YYYY-MM-DD', 'DD/MM/YYYY', 'DD.MM.YYYY HH:mm', …
```

Шаблон формата состоит из токенов `DD`, `MM`, `YYYY`, `HH`, `mm` и любых символов-разделителей между ними. `DD`, `MM`, `YYYY` обязательны и встречаются по одному разу; `HH` и `mm` — только вместе. Формат по умолчанию — `DD.MM.YYYY`, со временем — `DD.MM.YYYY HH:mm`. Если у компонента включено время, а в шаблоне нет `HH:mm`, к шаблону дописывается ` HH:mm`.

### 3.2. `dateStr` — помощники

Чистые функции в `packages/ui/src/date/dateStr.ts`, публичные (нужны приложениям для пресетов и валидации):

```ts
isValidDay(s: string): boolean                            // календарная проверка: 2026-02-31 — false, 2024-02-29 — true
isValidMinute(s: string): boolean                         // день валиден, 00 ≤ чч ≤ 23, 00 ≤ мм ≤ 59
parseDateText(text: string, format: DateFormat): IsoDay | IsoMinute | null   // полная строка по шаблону → ISO; неполная или невалидная — null
formatDateText(value: IsoDay | IsoMinute, format: DateFormat): string        // ISO → строка по шаблону; день без времени по шаблону со временем — без времени
maskDateText(text: string, format: DateFormat): string   // оставляет цифры и расставляет разделители шаблона по мере ввода
dayOf(value: IsoDay | IsoMinute): IsoDay
addDays(day: IsoDay, n: number): IsoDay
addMonths(day: IsoDay, n: number): IsoDay                  // 31.01 + 1 мес. → 28/29.02 (последний день месяца)
startOfMonth(day: IsoDay): IsoDay
endOfMonth(day: IsoDay): IsoDay
weekday(day: IsoDay): 1 | 2 | 3 | 4 | 5 | 6 | 7           // понедельник = 1
monthGrid(month: IsoDay): IsoDay[]                         // 42 дня: 6 недель с понедельника, включая хвосты соседних месяцев
todayLocal(): IsoDay                                       // по локальным часам машины
compareDates(a: IsoDay | IsoMinute, b: IsoDay | IsoMinute): -1 | 0 | 1   // строковое сравнение
isoMinuteStart(value: IsoMinute): string                  // '…T18:30:00+03:00' — смещение зоны на эту минуту
isoMinuteEnd(value: IsoMinute): string                    // '…T18:30:59+03:00'
```

Арифметика дней — через число дней от эпохи по формуле григорианского календаря, без объекта `Date`. Смещение зоны для DATETIME берётся на ту минуту, для которой строится граница (не на полночь дня), поэтому граница в день перехода на летнее время верна; этим же правилом исправляются `isoDayStart`/`isoDayEnd` в `fieldOps.ts` (техдолг STATE §7).

### 3.3. `Calendar`

```ts
type CalendarProps = {
  month: IsoDay                       // любой день показываемого месяца
  onMonthChange: (month: IsoDay) => void
  value?: IsoDay | '' | undefined      // одна дата
  range?: { from: IsoDay | ''; to: IsoDay | '' } | undefined   // подсветка диапазона
  onPick: (day: IsoDay) => void
  min?: IsoDay | undefined
  max?: IsoDay | undefined
  today?: IsoDay | undefined           // по умолчанию todayLocal(); проп — для тестов
  label?: string | undefined           // доступное имя сетки; по умолчанию месяц и год: «Сентябрь 2026»
  autoFocus?: boolean | undefined      // при монтировании фокус на выбранный или сегодняшний день (поповер дат)
  onHoverDay?: ((day: IsoDay | null) => void) | undefined   // наведение — DateRange подсвечивает будущий диапазон
}
```

Шапка: «‹ Сентябрь 2026 ›» — кнопки предыдущего и следующего месяца. Сетка — `<table role="grid">` из 6 недель, дни недели «Пн … Вс» в `<th>`, дни соседних месяцев приглушены и выбираемы. Отмечены: сегодня (рамка), выбранный день или границы диапазона (заливка `val`), дни внутри диапазона (`val-soft`), недоступные вне `min`/`max` (`aria-disabled`, не выбираются). Названия месяцев и дней недели — словарь кита на русском (без `Intl`).

Клавиатура (APG Date Picker Dialog): один таб-стоп на сетке, стрелки — день и неделя, Home/End — начало и конец недели, PgUp/PgDn — месяц, Shift+PgUp/PgDn — год, Enter/Space — выбрать. Уход фокуса за край месяца листает месяц.

### 3.4. Пресеты

```ts
type DatePreset = { id: string; label: string; range: (today: IsoDay) => { from: IsoDay; to: IsoDay } }
```

Экспортируются готовые пресеты, из них приложение собирает свои списки:

| id | Подпись | Период |
|---|---|---|
| `today` | Сегодня | сегодня — сегодня |
| `yesterday` | Вчера | вчера — вчера |
| `last3` | 3 дня | сегодня и 2 предыдущих дня |
| `last7` | 7 дней | сегодня и 6 предыдущих |
| `last30` | 30 дней | сегодня и 29 предыдущих |
| `thisMonth` | Текущий месяц | с 1-го числа по сегодня |
| `lastMonth` | Прошлый месяц | весь прошлый месяц |

`QUICK_PRESETS = [today, yesterday, last3, last7]` — горячие кнопки по умолчанию. `DEFAULT_PRESETS` — все семь, список в поповере по умолчанию. Пресеты задают целые дни: у периода со временем они ставят даты без времени, и граница «по» охватывает весь день.

### 3.5. `DateInput`

```ts
type DateInputProps = {
  value: DateValue
  onChange: (value: DateValue) => void
  time?: boolean | undefined           // разрешить время; по умолчанию false
  format?: DateFormat | undefined      // по умолчанию 'DD.MM.YYYY' (со временем — 'DD.MM.YYYY HH:mm')
  quick?: DatePreset[] | undefined     // горячие кнопки под полем; по умолчанию нет; у одиночной даты кнопка ставит `from` пресета
  min?: IsoDay | undefined
  max?: IsoDay | undefined
  today?: IsoDay | undefined
  disabled?: boolean | undefined
  size?: 's' | 'm' | undefined
  id?: string | undefined
  'aria-label'?: string | undefined
  placeholder?: string | undefined     // по умолчанию — шаблон формата строчными буквами: «дд.мм.гггг»
}
```

Поле текста с маской по шаблону: цифры подставляются на места токенов, разделители ставятся сами, лишние символы не вводятся. Время необязательно даже при `time`: полная дата без времени — `onChange(IsoDay)`, полная дата со временем — `onChange(IsoMinute)`. Неполное значение — наружу `''` без подсветки (условие снимается, пока дата не набрана); полное, но невалидное или вне `min`/`max` — поле `invalid`, наружу `''`. Очистка поля — `onChange('')`.

Справа — кнопка-иконка «Выбрать дату» (`aria-haspopup="dialog"`), открывает поповер: календарь на месяце значения или текущем, при `time` под ним поле «Время» по маске `чч:мм` и кнопка «Готово». Без `time` выбор дня ставит значение и закрывает поповер; со временем выбор дня ставит день, поповер закрывается кнопкой «Готово», Enter в поле времени или Escape (Escape — без изменения значения). Фокус возвращается в поле.

Внешняя смена `value` перерисовывает текст, если он не совпадает с тем, что человек набирает (тот же принцип, что у числового поля панели, спека 1e §6.2).

### 3.6. `DateRange`

```ts
type DateRangeValue = { from: DateValue; to: DateValue }
type DateRangeProps = {
  value: DateRangeValue
  onChange: (value: DateRangeValue) => void
  time?: boolean | undefined
  format?: DateFormat | undefined
  quick?: DatePreset[] | undefined     // горячие кнопки под полем; по умолчанию QUICK_PRESETS; [] — без кнопок
  presets?: DatePreset[] | undefined   // список в поповере; по умолчанию DEFAULT_PRESETS; [] — без списка
  min?: IsoDay | undefined
  max?: IsoDay | undefined
  today?: IsoDay | undefined
  disabled?: boolean | undefined
  size?: 's' | 'm' | undefined
  label: string                        // имя группы: название поля
}
```

Два поля по маске «с» и «по» в одной рамке (`role="group"`, `aria-label`), общая кнопка календаря.

**Горячие кнопки** — строка маленьких кнопок под полем (`role="group"`, имя «Быстрый период»): по умолчанию «Сегодня», «Вчера», «3 дня», «7 дней». Клик ставит обе границы без времени. Кнопка, чей период совпадает с текущим значением на сегодня, отмечена `aria-pressed="true"`; повторный клик по отмеченной очищает период.

**Поповер:** слева список пресетов, справа календарь; при `time` под календарём два поля времени «с» и «по» и кнопка «Готово». Выбор диапазона в календаре — двумя кликами: первый ставит «с» и сбрасывает «по», второй ставит «по»; если второй день раньше первого, границы меняются местами. Наведение между кликами подсвечивает будущий диапазон. Без `time` второй клик и пресет закрывают поповер; со временем поповер закрывает «Готово».

Правило ввода руками: «по» раньше «с» — поле «по» `invalid`, наружу уходит только «с».

## 4. Справочники

### 4.1. Общее

`type Option = { value: Scalar; label: string; hint?: string | undefined }` — `hint` показывается приглушённо справа (код, BIC). Поиск без учёта регистра по вхождению в `label`, `hint` и строковое `value`. Список в поповере — `role="listbox"`, высота ограничена токеном `menu-max-h`, активный пункт прокручивается в видимую часть. Ввод в поиск сбрасывает активный пункт на первый найденный. Пустой результат — строка «Ничего не найдено».

### 4.2. `SearchSelect`

```ts
type SearchSelectProps = {
  options: Option[]
  value: Scalar | null
  onChange: (value: Scalar | null) => void
  placeholder?: string | undefined     // «Не выбрано»
  clearable?: boolean | undefined      // по умолчанию true: кнопка ✕ «Очистить»
  searchable?: boolean | undefined     // по умолчанию — если вариантов больше 7
  disabled?: boolean | undefined
  size?: 's' | 'm' | undefined
  id?: string | undefined
  'aria-label'?: string | undefined
}
```

С поиском — `input role="combobox"` (`aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-autocomplete="list"`): поле показывает подпись выбранного, фокус и ввод открывают список и фильтруют его; уход фокуса без выбора возвращает подпись выбранного. Без поиска — `button` с `aria-haspopup="listbox"`, список открывается по Enter/Space/↓, буква переводит к первому пункту на неё (typeahead). Клавиатура: ↑/↓ — пункт, Enter — выбрать и закрыть, Escape — закрыть без выбора, Home/End — первый и последний.

### 4.3. `MultiSelect`

```ts
type MultiSelectProps = {
  options: Option[]
  value: Scalar[]
  onChange: (value: Scalar[]) => void
  placeholder?: string | undefined     // «Не выбрано»
  maxChips?: number | undefined        // по умолчанию 2: дальше «+N»
  max?: number | undefined             // предел выбора; по умолчанию без предела; 1 — одиночный выбор в том же виде
  disabled?: boolean | undefined
  size?: 's' | 'm' | undefined
  id?: string | undefined
  'aria-label'?: string | undefined
}
```

Поле — `button` с `aria-haspopup="listbox"`: чипы первых `maxChips` выбранных в порядке `options`, затем «+N»; у каждого видимого чипа ✕ снимает значение, не открывая список. Поповер: сверху поле поиска (`combobox`, фокус при открытии), под ним `listbox` с `aria-multiselectable="true"`, пункты — чекбокс и подпись, `aria-selected` у выбранных; Enter/Space переключает активный пункт, список не закрывается. При `max = 1` выбор другого пункта заменяет выбранный. Подвал: «Выбрано N» и кнопка «Очистить» (недоступна при нуле). Выбранные в поиске не скрываются — отмечены чекбоксом. Порядок `value` в `onChange` — порядок `options`, не порядок кликов: условие `IN` стабильно при одном и том же наборе.

## 5. `TagInput` — список значений или фраз

```ts
type TagInputProps = {
  value: string[]                                   // значения-чипы
  onChange: (value: string[]) => void
  text: string                                      // набираемый, ещё не превращённый в чип текст
  onTextChange: (text: string) => void
  mode: 'values' | 'phrases'
  validate?: ((v: string) => boolean) | undefined   // невалидное значение — красный чип, наружу не уходит
  max?: number | undefined                          // предел числа чипов; по умолчанию: values — 500, phrases — 20
  suggestions?: string[] | undefined                // подсказки с бека (§8)
  loading?: boolean | undefined
  onQuery?: ((query: string) => void) | undefined  // ввод текста — запрос подсказок
  onSuggestClose?: (() => void) | undefined
  disabled?: boolean | undefined
  size?: 's' | 'm' | undefined
  id?: string | undefined
  'aria-label'?: string | undefined
  placeholder?: string | undefined
}
```

Поле — рамка с чипами и строкой ввода в конце; по мере добавления чипов рамка растёт в высоту до трёх строк, дальше прокручивается. Набираемый текст — отдельный контролируемый проп: владелец поля (панель) видит его и может учесть при применении фильтра, не дожидаясь, пока текст станет чипом.

**Разделители и разбор.**

| Режим | Разделители чипов при вводе | Разбор вставки |
|---|---|---|
| `values` (ID, номера, коды) | Enter, `;`, `,`, пробел, Tab | переносы строк, `;`, `,`, пробелы, табуляция (колонка или строка из Excel) |
| `phrases` (текст для поиска по вхождению) | Enter, `;` | переносы строк и `;`; фразы в кавычках `"…"` или `«…»` — каждая отдельно, кавычки снимаются; запятая и пробел остаются частью фразы |

Набор `"счёт не найден" "инструкция инвалидна"` и Enter дают два чипа; вставка того же текста — тоже. Значения обрезаются по краям, пустые отбрасываются, повторы не добавляются (`values` — точное совпадение, `phrases` — без учёта регистра).

**Предел.** Сверх `max` чипы не добавляются, под полем — строка «Добавлено 500 из 732: больше нельзя». Предел `values` — ограничение контракта на `IN` (500 значений), предел `phrases` держит фильтр в ограничении контракта «не больше 100 условий».

**Клавиатура.** Enter с непустым текстом делает чип и форму не отправляет; Enter с пустым текстом не перехватывается — внутри формы панели он применяет фильтр. Backspace в пустой строке выделяет последний чип, второй Backspace снимает его. ← и → в пустой строке переходят по чипам, Delete снимает выделенный. У каждого чипа ✕ с именем «Убрать: …». Чипы — `<ul>` с именем поля, строка ввода — `input role="combobox"`, когда есть подсказки.

**Подсказки.** При `suggestions`/`onQuery` строка ввода — комбобокс с `aria-autocomplete="list"`: список открыт, пока есть подсказки или идёт загрузка («Ищу…»); ↑/↓ — активная подсказка, Enter с активной подсказкой добавляет её чипом, Escape закрывает список. Совпадение с набранным текстом в подсказке выделяется полужирным.

## 6. Панель фильтров

### 6.1. Мета поля

`FilterField` получает два необязательных поля, оба из `filter-meta` контракта:

- `defaultOp?: Condition['op'] | undefined` — оператор поля по умолчанию (`defaultOperator` контракта §6). Для STRING и NUMBER `IN` включает ввод списка значений.
- `suggest?: boolean | undefined` — у поля есть подсказки (предложение в контракт, §9). Имеет смысл у STRING.

### 6.2. Контрол по типу поля

| Тип | Условие выбора | Контрол | Условия из значения |
|---|---|---|---|
| STRING | `defaultOp: 'IN'` | `TagInput mode="values"` | одно значение — `EQ`, два и больше — `IN` |
| STRING | иначе | `TagInput mode="phrases"` | каждая фраза — своё `CONTAINS`, условия по полю объединяются по AND |
| NUMBER | `defaultOp: 'IN'` | `TagInput mode="values"`, `validate` — число | одно — `EQ`, два и больше — `IN` |
| NUMBER | иначе | `Input` (как сейчас) | `EQ` |
| DATE | — | `DateRange` без времени | обе границы: равны — `EQ`, различны — `BETWEEN`; только «с» — `GTE`; только «по» — `LTE` |
| DATETIME | — | `DateRange` со временем | «с» — `isoDayStart` дня или `isoMinuteStart`; «по» — `isoDayEnd` дня или `isoMinuteEnd`; обе границы — `BETWEEN`, одна — `GTE`/`LTE` |
| ENUM | — | `MultiSelect` из встроенного справочника | одно значение — `EQ`, два и больше — `IN` |
| BOOLEAN | — | `SearchSelect` без поиска: «да», «нет» | `EQ` |

Набираемый в `TagInput` текст, ещё не ставший чипом, учитывается как ещё одно значение (или фраза): поле работает и как обычное текстовое — набрал «Василёк», нажал «Применить», получил `CONTAINS`. Подсказки подключаются к `TagInput` любого режима, если у поля `suggest: true`; выбор подсказки добавляет чип.

Сужение операторов метой (`FilterField.ops` не пуст): если нужного оператора нет, берётся ближайший допустимый.

- Даты без `GTE`/`LTE` — одна граница сводится к дню или минуте (`EQ` для DATE, `BETWEEN` за день или минуту для DATETIME); без `BETWEEN` различные границы недоступны (поле «по» `disabled`).
- ENUM и списки значений без `IN` — не больше одного значения (`max = 1`).
- Фразы без `CONTAINS` — если есть `STARTS_WITH` или `EQ`, фразы строятся с ним; иначе поле не показывается.

Поле, у которого не остаётся ни одного подходящего оператора, в simple-режиме не показывается (как сейчас).

`draftOf`/`conditionFrom` (`fieldOps.ts`) переходят на сырые значения по контролу и возвращают список условий поля: `string` для NUMBER без списка и BOOLEAN, `string[]` (+ набираемый текст) для `TagInput`, `DateRangeValue` для DATE/DATETIME, `Scalar[]` для ENUM.

### 6.3. Лейн

Лейн ставит `EQ` по `laneField` (спека 1e §3) — мультиселект того же поля показывает один выбранный чип. Выбор в панели одного значения даёт `EQ`, и лейн подсвечивает его; двух и больше — `IN`, `$lane = null`, лейн показывает «Все». Правило `$lane` уточняется: значение — если по `laneField` ровно одно условие и оно `EQ`.

### 6.4. Чипы условий

Чип — один на поле, по всем его условиям (`describeField(field, conditions, meta, format)` в `opLabels.ts`; `describeCondition`/`conditionParts` остаются для одного условия):

- Фразы: «Сообщение содержит „счёт не найден“ и „инструкция инвалидна“».
- Списки: «ID в списке 400, 403, 406 и ещё 12» — после трёх значений «и ещё N», полный список — в тултипе чипа.
- Даты: `GTE` — «Дата документа с 01.09.2026», `LTE` — «… по 13.09.2026», `BETWEEN` — «… с 01.09.2026 по 13.09.2026» (было «от … до»); у DATETIME время показывается, только если граница не совпадает с началом или концом дня: «Создан с 01.09.2026 09:00 по 13.09.2026».
- Даты в чипах — в формате панели (`dateFormat`).
- `IN` по ENUM — «Статус в списке Ошибка, Отказ» (как сейчас).

✕ чипа снимает все условия поля (как сейчас — `remove(field)`). Счётчик на кнопке «Фильтры N» — число полей с условиями, то есть чипов (при одном условии на поле это то же, что было).

### 6.5. Формат дат панели

`FilterPanelProps.dateFormat?: DateFormat | undefined` — один шаблон для всех полей дат панели и для чипов (время дописывается по правилу §3.1). По умолчанию `DD.MM.YYYY`.

### 6.6. Enter и «Применить»

Поля по-прежнему внутри `<form>` тела панели. Enter в `Input`, в полях дат и в `TagInput` с пустым текстом отправляет форму (`onApply`, если есть изменения). Enter в `TagInput` с текстом делает чип; в комбобоксах и календаре Enter выбирает пункт — форму они не отправляют, применяют кнопкой «Применить» (как сейчас у нативного `Select`, спека 1e §6.2, Ruling 4).

## 7. Модель фильтров: несколько условий на поле

Контракт допускает несколько условий по одному полю (§4.4, объединяются по AND); модель сейчас держит по полю одно условие (`edit` заменяет условие поля). Добавляется:

- `setField: EventCallable<{ field: string; conditions: Condition[] }>` — заменить все условия поля в черновике разом; пустой список — снять поле из черновика.
- `edit(c)` остаётся и равен `setField({ field: c.field, conditions: [c] })`.
- `discard(field)`, `remove(field)`, `setLane`, `$lane` работают со всеми условиями поля (`remove` уже снимает все — фильтр по `field`).
- Порядок условий поля сохраняется в порядке чипов; поля между собой — в порядке первого появления (как сейчас).
- `useFilters` дополнительно отдаёт `setField`; `FilterPanelProps` получает `onSetField` (панель вызывает его вместо `onEdit`/`onDiscard`; `onEdit`/`onDiscard` остаются в API для совместимости).

## 8. Подсказки: модель

### 8.1. `createFiltersModel`

```ts
type SuggestQuery = { field: string; query: string; filter: Filter; limit: number }
type SuggestState = { field: string; query: string; items: string[]; loading: boolean }   // экспортируется из @katran/ui, filters/types.ts

createFiltersModel({
  …,
  suggest?: {
    fetchFx: Effect<SuggestQuery, string[]>   // даёт приложение
    delay?: number                              // мс, по умолчанию 250
    minChars?: number                           // по умолчанию 1
    limit?: number                              // по умолчанию 10
  },
})
```

Добавляется в модель:

- `suggest: EventCallable<{ field: string; query: string }>` — ввод в поле.
- `closeSuggest: EventCallable<void>`.
- `$suggest: Store<SuggestState | null>`.

Правила:

- `suggest` с текстом короче `minChars` — `$suggest = { field, query, items: [], loading: false }`, запроса нет.
- Иначе `$suggest.loading = true`, прежние `items` остаются до ответа; запрос уходит через `delay` мс после последнего `suggest`, если за это время не пришёл новый `suggest` или `closeSuggest`. Задержка — эффект-таймер модели (без `setTimeout` в компоненте), под `fork` тестируется фейковыми таймерами.
- `filter` запроса — применённые условия (`$conditions`) без условий по самому полю, как у фасетов (спека 1e §4).
- Транспорт — своя `attach`-копия `fetchFx`; ответ принимается, только если его `params` совпадают с последним отправленным запросом по значению. Ошибка — `items: []`, `loading: false`, без сообщения.
- `closeSuggest` — `$suggest = null`; поздний ответ после закрытия отбрасывается.
- Подсказки, уже стоящие чипами в поле, панель из списка убирает.

### 8.2. Хук и панель

`useFilters` дополнительно отдаёт `suggest: SuggestState | null`, `onSuggest`, `onSuggestClose`. `FilterPanelProps` получает необязательные `suggest`, `onSuggest`, `onSuggestClose`: без них поля с `suggest: true` работают без подсказок. Панель передаёт `suggestions` и `loading` только полю, чьё имя в `suggest.field`.

## 9. Предложение в контракт `vtb-filters`

Для владельца контракта — отдельным документом `docs/reference/suggest-proposal.md` в ките:

- `filter-meta`: у поля необязательный `suggest: boolean` (по умолчанию `false`) — бек включает подсказки там, где они дешёвые (индекс по полю).
- `POST /grids/{gridId}/suggest`, тело `{ field, query, filter, limit }`, ответ `{ items: string[] }`. Семантика: различные значения поля среди записей, удовлетворяющих `filter`, содержащие `query` без учёта регистра; не больше `limit` (1–50, по умолчанию 10); порядок — по убыванию частоты, при равенстве — по алфавиту. Поле без `suggest: true` — `400 SUGGEST_NOT_SUPPORTED`; права — как у `search`.
- Для сведения бека, без изменения контракта: фразы одного поля приходят несколькими условиями `CONTAINS` по этому полю (контракт §4.4 — AND), списки ID — `IN` до 500 значений; экранирование `%`, `_` и символа экранирования в `CONTAINS` — на беке (контракт §4.2).
- Серверные справочники `LOOKUP` (контракт §6.1) в будущем подключаются к тем же контролам: `SearchSelect`/`MultiSelect` получат режим «варианты с бека» с тем же паттерном `onQuery` → модель → эффект приложения.

## 10. Демо и `apps/pi`

- **Демо, страница «Поля ввода»:** все пять контролов в состояниях «пусто», «заполнено», «ошибка», «недоступно»; `DateInput` и `DateRange` с временем и без, в форматах `DD.MM.YYYY` и `YYYY-MM-DD`, с горячими кнопками и без; `MultiSelect` на 30 вариантах; `TagInput` в обоих режимах с фейковыми подсказками и примером вставки колонки ID. Обе темы переключаются шапкой демо.
- **`apps/pi`** (боевые экраны реестров; демо-реестра в `apps/demo` после плана 6 нет): в `filter-meta` фейкового сервера и маппере контракта — `defaultOperator` и `suggest`; валютный реестр — `defaultOperator: IN` у номера документа, 20 вх и 20 исх; `suggest: true` у наименований 50/59, BIC 52, причины статуса и назначения; фразы — у причины статуса и назначения (70); рублёвый — `defaultOperator: IN` у номера документа и ИНН получателя, `suggest: true` у наименований отправителя и получателя. Фейковый сервер отдаёт подсказки по данным: уникальные значения поля по выборке, как стенд. Порт `suggestFx` в `shared/api`, маршрут `POST …/suggest` фейкового сервера, контрактный тест, `docs/reference/pi-api.md`.

## 11. Совместимость и токены

- React 17: идентификаторы — `useStableId` кита, не `useId`; никаких API React 18+ (линт плана 4 это проверяет).
- Chromium 88: без `:has`, `inert`, `Array.prototype.at`, `structuredClone`, `String.prototype.replaceAll`; `Intl.DateTimeFormat` не используется.
- Новые размеры — через `tokens.src.ts`: ячейка календаря `cal-cell: 28`, ширина колонки пресетов `preset-w: 140`, предел высоты поля с чипами `tag-max-h: 84` (три строки чипа высотой `h-ctl-s` с зазорами `sp-1`). Цвета — существующие токены (`val`, `val-soft`, `faint`, `line`, `chip`, `bad`).
- Высота контролов в одну строку равна высоте `Input` того же `size` — поля фильтров в одной строке не пляшут; `TagInput` растёт только при переносе чипов.

## 12. Проверки

- **Модульные:** `dateStr` — високосные годы, 31.02, границы месяцев, `addMonths` на 31-е, маска и разбор по шаблонам `DD.MM.YYYY`, `YYYY-MM-DD`, `DD/MM/YYYY`, `DD.MM.YYYY HH:mm`, 24:00 и 23:60 невалидны, границы минуты со смещением в день перехода на летнее время; прогон при `TZ=UTC`, `Europe/Moscow` и `America/New_York` с одинаковым результатом. Разбор `TagInput`: разделители каждого режима, кавычки обоих видов, вставка колонки и строки из Excel, повторы, предел.
- **Компоненты (jsdom, роли, axe):** календарь — клавиатура и листание, `min`/`max`; `DateInput` — маска по формату, время необязательно, невалидная дата, календарь с полем времени; `DateRange` — выбор двумя кликами, обмен границ, пресеты и горячие кнопки с фиксированным `today`, `aria-pressed`; `SearchSelect` и `MultiSelect` — поиск, клавиатура, чипы, «+N», «Очистить», `max = 1`; `TagInput` — Enter с текстом и без, Backspace и стрелки по чипам, подсказки.
- **Модель (fork, фейковые таймеры):** `setField` и совместимость `edit`/`discard`/`remove`, `$lane` при нескольких условиях поля; подсказки — задержка, `minChars`, отбрасывание устаревшего ответа и ответа после `closeSuggest`, ошибка, `filter` без условий по полю.
- **Панель:** маппинг каждого типа в условия по таблице §6.2, сужение операторов метой, набираемый текст учитывается при применении, лейн ↔ мультиселект, чипы по полю (фразы, списки, даты, формат).
- **e2e (Chromium):** поповеры у правого и нижнего края окна не выходят за экран; высота контролов рядом с кнопками; проход панели клавиатурой; обе темы (скриншоты); в валютном реестре `apps/pi` (часы страницы зафиксированы на 23.09.2026, данные фейка — сентябрь 2026) — период горячей кнопкой и календарём, список номеров вставкой, две фразы в «Назначении», подсказки.

## 13. Открытое

- Эндпоинт `suggest` и флаг `suggest` в `filter-meta` — предложение владельцу контракта `vtb-filters`; до согласования форма `SuggestQuery` — черновик кита.
- OR между фразами одного поля («содержит любую из») в контракте v1 не выражается (только AND, контракт §4.4); появится вместе с `logic`/`groups` контракта.
- Пресеты по умолчанию — по опыту реестров; если операторам нужны «Неделя с понедельника» или «Квартал», они добавляются в список без изменения API.
