# katran: стилизация на styled-components — дизайн

Дата: 2026-10-13. Дополнение к основной спеке `2026-09-23-katran-design.md` и спеке совместимости `2026-09-24-katran-compat-design.md` (обе binding). **Отменяет** их решение «CSS Modules без рантайма, CSS-in-JS отвергнут» (основная спека §3, `docs/STATE.md` §2). Основание — обратная связь команды хоста после первой интеграции (13.10.2026), решения владельца (13.10.2026) и опыт `spike/styled` (коммит `cd9d70e`, в `main` не входит).

## 1. Зачем

Весь код метаприложения написан на styled-components 5.3.11: так его читают и ревьюят, отдельный способ стилизации в одном модуле команда хоста не принимает. Требование — единообразие, а не дефект: CSS Modules кита в хосте работают. Владелец принял его как установку: **кит и приложения на нём отказываются от CSS-файлов и переходят на styled-components**.

Исходная причина отказа от CSS-in-JS — стили во время выполнения на гриде в тысячи ячеек — остаётся в силе. Срез устроен так, чтобы её снять, и это проверено замером (§3).

## 2. Решения владельца (13.10.2026)

| № | Вопрос | Решение |
|---|---|---|
| В1 | Граница перехода | **Весь кит изнутри**, `apps/pi` и `apps/demo`. CSS-файлов стилей в репозитории не остаётся |
| В2 | Как токены попадают в стили | Переменные `--k-*` остаются механизмом темы и плотности; их объявляет корень `KatranProvider`. Смена темы и плотности не перерисовывает компоненты |
| В3 | Как переход доходит до хоста | **Один выпуск `0.2.0`**, когда переведено всё. Хост до него живёт на `0.1.1`; версии, где смешаны CSS-файлы и styled-components, не выпускаются |
| В4 | Критерий скорости | Грид после перехода не медленнее нынешнего более чем на **15 %** по каждому замеру (§3.2) |
| В5 | Устройство по итогам замера | **Два правила** (§4.2, §4.3): весь кит — styled-компоненты со статическими шаблонами; горячий путь грида — обычные элементы, стили объявлены один раз на провайдер |

В2 уточнено решением В5: первоначальный вариант «стили читают токены функцией от `theme`» по замеру оказался самым медленным (§3.2) и внутри кита не применяется; `ThemeProvider` с объектом токенов остаётся для кода приложений (§4.4).

## 3. Опыт `spike/styled`

### 3.1. Что и как мерили

Горячий путь валютного реестра `apps/pi` (запись грида `GridRecord` и компоненты значений в ячейках: `CopyValue`, `LinkValue`, `AccountValue`, `StatusDot`, `Tag`, `FieldTag`, `SwiftField`) переведён на styled-components 5.3.11 в четырёх вариантах; остальной кит оставался на CSS Modules. Production-сборка, React 17.0.2, Chromium из Playwright 1.63, 500 документов в фейке без задержки, без автооткрытия деталки; 8 кругов, порядок вариантов сдвигается с каждым кругом; медианы. Процессор — обычный и замедленный в 4 раза. Запись реестра — около 110 элементов (5 489 на 50 записей).

Варианты:

- **theme** — каждый элемент styled-компонент, токены функцией `${({ theme }) => theme[…]}`;
- **static** — каждый элемент styled-компонент, токены строками `var(--k-…)`, функций в шаблоне нет;
- **container** — как static, но ячейки записи — обычные элементы, их правила вложены в стили `tbody`; содержимое ячеек — styled-компоненты;
- **global** — на всём горячем пути обычные элементы с постоянными именами классов, стили объявлены одним `createGlobalStyle` под корнем провайдера.

### 3.2. Результат

Полное время действия, мс; в скобках — отличие от CSS Modules. Первые три варианта — прогон 1, **global** — прогон 2 (своя база CSS Modules в пределах ±5 % от прогона 1).

Прокрутка одинакова во всех вариантах (около 17 мс на кадр на 50 записях). Снимок реестра в вариантах static, container и global совпадает с CSS Modules байт в байт.

Выводы:

1. Дорого стоит не CSS, а обёртка styled-компонента на каждом элементе; функции в шаблоне удваивают эту цену.
2. Порогу 15 % удовлетворяет только вариант global. Два его выброса (+26 % и −24 %) — на самых коротких действиях (30–80 мс) при неизменном времени скриптов; это шум замера полного времени.
3. Вне грида цена обёрток незаметна: в форме, окне или панели десятки элементов.

Ограничения опыта: переведён только горячий путь валютного реестра; служебные подписи ячеек самого `apps/pi` (`cells.module.css`) не переводились; 200 записей — нагрузочный случай, в интерфейсе предел страницы — 100.

### 3.3. Шрифты

Пробный пакет с файлами `woff2` рядом со входом и адресами через `new URL('./files/….woff2', import.meta.url)`, установленный через npm, загрузил шрифты в Vite dev (с предсборкой зависимостей), Vite build и webpack 5 без настроек у потребителя. ## 4. Устройство

### 4.1. Зависимость

- `styled-components` — `peerDependencies` у `@katran/ui`: `^5.3.11` (линия 5; версия 6 не поддерживается — другой API пропсов и типов). Разработка, демо и `apps/pi` — ровно на `5.3.11`. `@katran/tokens` и `@katran/effector` от styled-components не зависят.
- Под федерацией `styled-components` — **shared singleton**, как `react` (дополнение к `docs/consuming.md` и макету `examples/federation`). Внутри кита стили от контекста темы не зависят (§4.2), поэтому вторая копия библиотеки не ломает вид — только удваивает код. *Исполнение (R25): у remote — `import: false`, только копия хоста, как React; запасная копия при равных версиях выбиралась вместо хостовой (+13.9 KiB gzip).*
- styled-components вставляет `<style>` во время выполнения. Политика CSP хоста это уже допускает (он сам на styled-components); в `docs/consuming.md` — одна строка об этом.
- **React 17–19 сохраняется** (`peerDependencies` `react >=17`, CI-задача `react19`). Проверено в опыте на React 19: типы `@katran/ui` со styled-компонентами проходят `tsc`, styled-варианты значений и записи грида рендерятся в тестах (падают только два утверждения об именах классов). CI-задача `react19` остаётся обязательной на каждом шаге.
- Серверный рендер не поддерживается и не нужен.

### 4.2. Правило 1 — весь кит: статические styled-компоненты

- Каждый компонент кита стилизуется styled-компонентами в своём модуле. **В шаблонах кита нет функций** — ни от пропсов, ни от `theme`: шаблон вычисляется один раз при загрузке модуля.
- Токены — из типизированного объекта `@katran/tokens` со ссылками на переменные: `${k.paper}` → `var(--k-paper)`. Объект генерируется из `tokens.src.ts` тем же `pnpm gen`, что и значения; имя экспорта и форма ключей — на исполнителе (решение по умолчанию: плоский объект `k`, ключи — имена токенов в camelCase).
- Состояния и варианты — атрибутами (`data-*`, `aria-*`, `:disabled`), как сейчас (89 таких селекторов уже есть); модификаторы, которые сейчас выражены вторым классом (`s.selected`, `s.small`, тон `CopyValue`), переводятся в атрибуты. Переменные значения на элементе — инлайновой CSS-переменной, как нынешняя `--k-lines`.
- Правила с участием соседних частей компонента — вложенными селекторами и ссылками на компоненты (`${Cell}`), специфичность исходных правил сохраняется. Места, где исходник удваивал класс ради специфичности (`.caption.caption`), получают `&&`.
- Каждый компонент кита с корневым элементом принимает `className` и ставит его на корень — у потребителя работает `styled(Button)`.
- Порядок правил. Сброс корня провайдера и правила компонентов равны по специфичности (0,1,0), сейчас спор решает порядок в `ui.css`; при переносе порядок вставки стилей закрепляется (сброс корня — раньше правил компонентов) и подтверждается снимками.
- Имена классов `k-Component__part` исчезают: в DOM — классы styled-components. Они не были публичным API; тесты и e2e, которые на них опирались (20 файлов), переходят на роли, подписи и `data-*`.

### 4.3. Правило 2 — горячий путь грида: без обёрток

- Горячий путь — то, что рисуется в каждой записи грида: `GridRecord`, `GridSkeleton` и семейство `value/` (компоненты значений, предназначенные для ячеек). Точный список фиксирует план по фактическому использованию в колонках `apps/pi` и демо.
- Эти компоненты рендерят обычные элементы с постоянными именами классов `k-<часть>`; их стили объявлены один раз на провайдер, ограничены его корнем (специфичность как у исходных правил, (0,1,0)). Шаблоны — те же статические, с теми же токенами.
- *Исполнение (R16, R18):* правила — фрагменты `css` (`valueHot`, `gridHot`) в шаблоне styled-корня провайдера под `*:where(&) .k-…`, а не `createGlobalStyle`: у `createGlobalStyle` в styled-components 5.3.11 место в листе закрепляется только за первым экземпляром — со вторым провайдером или после перемонтирования правила горячего пути вставали после правил потребителя и перебивали `styled(CopyValue)`. У корня одна статическая группа, объявленная раньше компонентов потребителя, — порядок не зависит от числа провайдеров. `:where(&)` stylis разворачивал в (0,2,0), отсюда `*:where(&)`.
- Компоненты горячего пути так же принимают `className`.
- Правило проверяется линтом (§6): в модулях горячего пути нет вызовов `styled.*`.

### 4.4. Провайдер, токены, тема

- Корень `KatranProvider` — styled-компонент. Он объявляет все `--k-*` (светлая палитра, тёмная по `[data-theme="dark"]` и по `prefers-color-scheme` при теме «системная», размеры с плотностью) и несёт правила изоляции от стилей хоста из нынешнего `Provider.module.css` (`content-box`, типографика контролов). *Исполнение (R7):* изоляция перенесена в шаблон корня последней — в Task 10, когда удалён последний модуль CSS кита и приложений: styled вставляет `<style>` после CSS Modules, и сброс равной специфичности перебивал ещё не переведённые компоненты.
- Палитра по `[data-theme]` объявляется и для потомков корня, а не только на нём самом: страница токенов демо ставит `data-theme` на секции внутри провайдера.
- **Переменные больше не объявляются на `:root`** — только под корнем провайдера. Порталы наложений уже рендерятся внутрь корня. `Shell` обоих приложений уже лежит внутри `KatranProvider`, вне провайдера `--k-*` в приложениях никто не читает.
- `KatranProvider` оборачивает детей в `ThemeProvider` с объектом токенов **под своим ключом и не затирая тему хоста**: `theme={(outer) => ({ ...outer, katran: k })}`. Это для кода приложений; кит свою тему не читает.
- `tokens.css` перестаёт быть поставляемым файлом; `tokens.ts` со значениями (проверки контраста) остаётся.

### 4.5. Шрифты

- Файлы `woff2` IBM Plex поставляются в `@katran/tokens` рядом со сборкой; отдельный вход пакета отдаёт описания начертаний (семейство, вес, `unicode-range`, адрес через `new URL(…, import.meta.url)`).
- `@katran/ui` экспортирует компонент `KatranFonts` (`createGlobalStyle` с `@font-face`); приложение ставит его один раз. `@font-face` глобален по природе — это единственное глобальное правило кита, и оно включается явно.
- Если первая задача плана покажет, что запись `new URL` не переживает сборку или федерацию, запасной путь — шрифты, вшитые в модуль (около +270 КБ JS, без настройки CORS); выбор запасного пути согласуется с владельцем.

### 4.6. Поставка `0.2.0`

- Убираются экспорты `@katran/ui/styles.css`, `@katran/tokens/tokens.css`, `@katran/tokens/fonts.css` и поле `sideEffects` с CSS-глобами (пакеты становятся без побочных эффектов; исключения, если понадобятся, перечисляются явно).
- Подключение у потребителя: `KatranProvider` и `KatranFonts`, без импортов CSS.
- **Breaking** для потребителя: три импорта CSS удалить, добавить `styled-components` в зависимости и shared; переменные `--k-*` недоступны вне провайдера; имена классов `k-*__*` исчезли.
- API компонентов, разметка, геометрия, цвета и поведение не меняются.

### 4.7. Приложения

- `apps/pi` — образец кода команды хоста: styled-компоненты рядом с компонентом, тема через `ThemeProvider` (`theme.katran`) там, где это удобно. *Исполнение (R24):* `apps/pi` пишется статически, как кит, — токены `k`, без функций в шаблонах (правило eslint `APP_STYLED_RULES`); `theme.katran` доступна под провайдером, но в образце не используется. В содержимом ячеек реестра (`cells` обеих сущностей) — только статические шаблоны и по возможности компоненты значений кита; правило и числа §3.2 записываются в `docs/guides/pi-usage.md`.
- Критерий В4 относится к реестру целиком, вместе с ячейками приложения. Своих элементов приложения в записи немного (служебные подписи, значок направления), поэтому по умолчанию они остаются статическими styled-компонентами. Если итоговый замер после перевода `apps/pi` выходит за порог, эти части переводятся на правило 2: обычные элементы и один `createGlobalStyle` рядом с раскладкой колонок; повторяющиеся в обоих реестрах — в компоненты значений кита. Это же записывается в `pi-usage.md` как правило для ячеек.
- Макет `examples/federation` переводится вместе с приложениями: стили remote — на styled-components, `styled-components` — в shared; хост макета получает собственный `ThemeProvider` — проверка, что кит не затирает тему хоста.
- `apps/demo` переводится так же. `public/hostile.css` обоих приложений остаётся: это имитация глобальных стилей хоста, а не стили кита.

## 5. Цели, не-цели, анти-цели

**Цели:** ни одного CSS-файла стилей в `packages/ui`, `apps/pi`, `apps/demo`; вид и поведение без изменений; грид в пределах критерия В4; правила «размеры и цвета только токенами» и планка Chromium 88 продолжают проверяться автоматически.

**Не-цели:** изменения дизайна и API (кроме §4.6); использование темы хоста в ките; styled-components 6; серверный рендер; срез 3a (справочники) — после этого среза.

**Анти-цели** (срез считается неудачным, даже если всё собирается): грид медленнее порога; видимое расхождение с нынешним видом; выпуск версии со смешанными механиками; имена, адреса и названия репозиториев хоста в этом публичном репозитории.

## 6. Проверки

- **Вид.** До начала работ с `main` снимаются эталонные снимки ключевых экранов (оба реестра, деталка со всеми вкладками, панель фильтров и поповеры, страницы демо; светлая и тёмная темы, плотность 100 и 125 %). После каждого семейства — сравнение; ожидается совпадение, каждое расхождение разбирается. Опыт дал совпадение байт в байт.
- **e2e `apps/pi`** (107) и проверки макета федерации (21) проходят; меняются только селекторы, опиравшиеся на имена классов, — утверждения о геометрии и контрасте остаются прежними.
- **Скорость.** Сценарий замера из опыта переносится в репозиторий как инструмент вне `pnpm check`; итоговый замер полностью переведённого кита против `main` — по критерию В4. Обязательные замеры — те же, что в опыте: 50 и 200 записей, процессор обычный и ×4, четыре действия; прокрутка — справочно. Для действий короче 100 мс полное время слишком шумно (§3.2), и порог 15 % применяется к времени скриптов. Промежуточный замер после шага 2 (§7) — по тем же правилам.
- **Линт стилей.** Нынешние правила stylelint (запрет `px`/`rem`/`em` вне перечисленных свойств, hex, именованных цветов и `rgb()/hsl()`, шаблон имён переменных) применяются к шаблонам styled в `.ts`/`.tsx`. Добавляются правила eslint: запрет функций в шаблонах styled внутри `packages/ui`; запрет `styled.*` в модулях горячего пути.
- **Планка Chromium 88 для CSS.** `check-css-target` получает CSS не из `dist/ui.css`, а из шаблонов (способ извлечения — на исполнителе); набор проверок прежний.
- **Юнит-тесты.** Режим `classNameStrategy: 'non-scoped'` и `css-modules.d.ts` уходят; тесты, читавшие классы, переходят на роли и атрибуты.
- **Поставка.** `pnpm release:pack` и `pnpm check:install` проходят с новым составом; в чистом проекте `check:install` нет ни одного импорта CSS.
- `pnpm check` зелёный на каждом коммите; e2e — после каждого семейства.

## 7. Порядок

Одна ветка, worktree; смешанное состояние допустимо только внутри ветки.

1. **Основание:** шрифты (проверка §3.3 на сборке кита и под федерацией), зависимость, генерация объекта токенов, корень провайдера и объявление переменных, линт, эталонные снимки, инструмент замера.
2. **Горячий путь:** `value/`, запись и скелетон грида — с промежуточным замером.
3. **Примитивы и поля:** `button`, `input`, `tag`, `select`, `date`, `form`.
4. **Остальной грид и реестр:** заголовки, меню колонок, `filters`, `pagination`, `table`, `state`, `code`.
5. **Наложения:** `overlay`, `tooltip`, `drawer`, `tabs`.
6. **`apps/pi`**, затем **`apps/demo`**.
7. **Уборка и документы:** удаление инфраструктуры CSS Modules (`generateScopedName`, `css-modules.d.ts`, глобы stylelint, экспорт `styles.css`), манифесты и `0.2.0`, `docs/consuming.md`, `docs/guides/pi-usage.md`, макет федерации, `README`, `CHANGELOG`, `docs/STATE.md` (§2 — новое решение о стилизации), пометки в основной спеке и спеке совместимости; итоговый замер и сверка снимков.

## 8. Открытые вопросы

Работу не блокируют; решения по умолчанию указаны.

1. **Соглашения команды хоста о файлах стилей** (стили в файле компонента или в соседнем `styles.ts`, именование styled-компонентов). По умолчанию — в файле компонента, имена частей с заглавной буквы. Уточнить у разработчика хоста на примере одного их компонента; на `apps/pi` правка механическая.
2. **Версия styled-components у хоста зафиксирована на 5.3.11 или допускает обновление в линии 5** — от этого зависит запись в shared. По умолчанию — `^5.3.11`, singleton.
3. **Запасной путь шрифтов** (§4.5) — только если первая задача плана покажет, что основной не работает.

## 9. Решения исполнителя

Приняты при написании спеки, владелец может изменить:

1. Тема кита кладётся в `ThemeProvider` под ключом `katran` и не затирает тему хоста (§4.4).
2. Переменные `--k-*` объявляются только под корнем провайдера, не на `:root` (§4.4).
3. Специфичность правил горячего пути удерживается через `:where([data-k-root])` (§4.3).
4. Имена классов в DOM не стабилизируются плагином — тесты уходят на роли и атрибуты (§4.2).
5. Версия выпуска — `0.2.0`; пакеты объявляются без побочных эффектов (§4.6).
6. Эталонные снимки как основной способ доказать «вид не изменился» (§6).
7. Свои элементы `apps/pi` в ячейках остаются styled-компонентами, пока итоговый замер укладывается в порог; иначе — правило 2 (§4.7).
8. Для действий короче 100 мс порог 15 % считается по времени скриптов (§6).
9. Макет федерации переводится в этом же срезе, его хост получает свою тему (§4.7).

## 10. Решения при исполнении

Приняты по ходу среза (номера R — решения в рабочем журнале среза, он вне репозитория; здесь — их суть), владелец может изменить:

- **R5 — `react-is` 17.** styled-components 5 распознаёт элементы через `react-is`, а его диапазон закрывается последней версией: `react-is` 19 не узнаёт элементы React 17 (`isElement`/`typeOf`, `Context.Provider` — недопустимый тип). В монорепо закреплён `pnpm.overrides` `"styled-components>react-is": "17.0.2"`; `scripts/use-react.mjs` при переключении на React 19 ставит ту же мажорную (R12). Хосту — требование закрепить `react-is` под свой React, `check:install` это проверяет (R9, `docs/consuming.md`).
- **R13 — одна точка импорта.** В ките styled-components импортирует только `packages/ui/src/styled.ts`: он нормализует default-экспорт (в Node CJS-пакет приходит целиком, `styled.div` — не функция) и реэкспортирует `css`, `createGlobalStyle`, `keyframes`, `ThemeProvider`, `useTheme`, типы. Правило eslint.
- **R16 — правила горячего пути в шаблоне корня** под `*:where(&) .k-…`, не `createGlobalStyle` (§4.3).
- **R21 — `dimClass = 'k-dim'`.** Публичный класс приглушения сохранён постоянной строкой, его правило — фрагмент в шаблоне корня (0,1,0); API для потребителя не изменился.
- **R23 — двойники ячеек приложения.** Свои элементы ячеек `apps/pi` — правило 2 (§4.7: статические styled в ячейках вышли за порог, «выбрать все» 200 записей, скрипты +30 % и +34 %): обычные элементы и `FxCellStyles`/`RubCellStyles` на сущность. 7 правил в них повторяются; перенос в компоненты значений кита меняет его API — техдолг, отдельный срез.
- **R25 — styled-components у remote — `import: false`** (§4.1): копию даёт хост; JS remote макета 83.5 → 69.6 KiB gzip.
