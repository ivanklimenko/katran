## 2. Ячейки на всю высоту записи (R6)

**Объявление.** `ColumnDef.fullHeight?: boolean | undefined`. Ячейка такой колонки рендерится только в первой строке записи с `rowSpan = 1 + число сквозных строк`. Служебная колонка (чекбокс, открытие, номер) — всегда на всю высоту: пустых ячеек под ней в сквозных строках больше нет.

**Сквозные сегменты.** `resolveSpans` раскладывает сегменты только по колонкам без `fullHeight` (колонкам первой строки). Если в диапазон сегмента (`from`–`to` по полному порядку) попала видимая колонка на всю высоту — пользователь переставил колонки, — сегмент обрезается до непрерывного участка колонок первой строки, начиная с первой покрытой; остаток диапазона закрывают пустые заполнители, содержимое не дублируется. `fillSegments` считает заполнители по колонкам первой строки.

**Высота.** `lines` колонки на всю высоту — до 3. Высота записи — максимум из «строка колонок + сквозные строки» и `lines` высоких колонок. Цель демо — 68 px, коридор e2e 64–72 не меняется.

**Скелетон** повторяет структуру записи: `rowSpan` у высоких и служебной колонок, сегменты — как у записи.

**Клавиатура** (`useGridKeyboard`). Высокая ячейка — одна на все строки записи. ↓/↑ из неё — в ту же колонку соседней записи. ↓/↑ из соседней строки на колонку, занятую высокой ячейкой, — в эту ячейку. ←/→ — по ячейкам текущей строки DOM, как сейчас. `data-cell` — прежний (строка, индекс видимой колонки).

**ARIA.** `rowSpan` у `td` отдаёт охват строк в дерево доступности; `aria-rowindex` и `aria-rowcount` считаются по строкам записи, как раньше.

**Демо.** На всю высоту: «Дата / Время» (3 строки), «Тип», «Направление», 32, «S / R in», «Провайдеры». В первой строке с продолжением сквозной строкой: «Статус», «ID», 50, 52, 57, 59. Причина статуса — сегмент `from: 'status', to: 'id'`, как на эталоне.

## 3. Многоуровневая сортировка (S1, S3)

Решение владельца В1 (2026-09-24) снимает запрет основной спеки §1.2 «Мульти-сортировка — не делаем».

**Типы (`@katran/ui`), breaking:**

```ts
export type SortLevel = { key: string; dir: 'asc' | 'desc' }
export type Sort = SortLevel[]              // [] — без сортировки; было { key, dir } | null
export const MAX_SORT_LEVELS = 5            // контракт vtb-filters §5.1: sort — массив до 5 элементов
```

**Помощники** (`ui/grid/sortRows.ts`), общие для шапки и чипов:

| Функция | Поведение |
|---|---|
| `soleSort(sort, key: SortKey): Sort` | ключ единственным; если он уже единственный — смена направления; иначе направление по умолчанию для типа ключа (`defaultDir`) |
| `addSortLevel(sort, key: SortKey): Sort` | добавить уровень в конец; если ключ уже есть — смена направления его уровня; при `MAX_SORT_LEVELS` уровнях новый не добавляется |
| `flipSortLevel(sort, keyId): Sort` | смена направления уровня |
| `removeSortLevel(sort, keyId): Sort` | убрать уровень |

`sortRows` сравнивает по уровням, пока равенство; правила ключа (`order`, `then`, пустые в конце независимо от направления) — прежние.

**Модель.** `$sort: Store<Sort>` (начальное `[]`), `sortBy: EventCallable<Sort>` — имя прежнее, тип новый: грид сообщает следующее состояние, посчитанное помощниками. Смена сортировки → страница 1. `GridQuery.sort: Sort`. Сортировка в `persist` не сохраняется (как раньше).

**Шапка (`ColumnHeader`).**

- Колонка с одним ключом: клик — `soleSort`, Shift+клик — `addSortLevel`.
- Клавиатура: Enter на ячейке шапки — клик; Shift+Enter — клик с `shiftKey` (`useGridKeyboard` передаёт `shiftKey` в синтетический клик).
- Стрелка направления; при двух и более уровнях — номер уровня верхним индексом. `aria-sort` — только у колонки первого уровня.
- Составная колонка: меню «Сортировать «X» по». Строка ключа — кнопка «сделать единственным» (стрелка и номер уровня, если ключ выбран) и кнопка «+» (добавить уровнем) или «↕» (у выбранного — сменить направление уровня); Shift+клик по ключу — тоже добавить уровнем. Подсказка «клик — единственный ключ · «+» или Shift+клик — добавить уровнем»; «Сбросить сортировку» — при непустой сортировке.
- Подпись вместо подзаголовка — ключ первого уровня этой колонки (как сейчас для одного ключа).

**`SortChips`** — новый компонент `@katran/ui`, `DataGrid` рендерит его над таблицей, пока `sort.length > 0`: «Сортировка: 1 Тип сообщения ↑ › 2 BIC 52 ↑». Чип — две кнопки: подпись (смена направления; имя «Тип сообщения, по возрастанию — сменить направление») и ✕ («Убрать уровень Тип сообщения»). При двух и более уровнях — подсказка «Shift+клик по заголовку — ещё уровень». Подписи ключей — из `layout.columns[].sort[]` (с учётом частей `split`, раздел 4).

**Фейковый бэкенд демо** сортирует по уровням; ключ `status` — по подписи статуса, `localeCompare('ru')` (S3).

## 4. «Вместе / раздельно» для составных колонок (R5)

Решение владельца В2 (2026-09-24): вид выбирает пользователь, общим механизмом, в раскладке пользователя.

**Объявление:**

```ts
// в ColumnDef<Row>
split?: {
  /** Подпись переключателя в меню состава: «Валюта отдельной колонкой». */
  label: string
  /** Вид хоста в режиме «раздельно» — без выделенной части. */
  render: (row: Row) => ReactNode
  /** Ключи хоста в режиме «раздельно»; по умолчанию — ключи хоста без ключей частей. */
  sort?: SortKey[] | undefined
  /** Части — обычные колонки со своими id, заголовком, шириной, ключами, fullHeight, render. */
  parts: ColumnDef<Row>[]
} | undefined
```

**Поведение.** «Вместе» — по умолчанию: хост рисует `render`, частей нет. «Раздельно»: хост рисует `split.render`, части стоят сразу за хостом. Части переезжают и скрываются вместе с хостом — отдельных пунктов в порядке и скрытии у них нет. Ширина части своя, меняется и сохраняется по её id. Уровни сортировки ссылаются на ключ, поэтому переключение режима сортировку не сбрасывает — меняется только шапка, где уровень показан. Сегменты по id колонок: если часть в диапазоне сегмента, сегмент её покрывает по общему правилу раздела 2.

**Раскрытие** — `expandColumns(columns, split: string[]): ColumnDef<Row>[]` в `@katran/ui`, до `visibleColumns`. `DataGrid`, скелетон, меню состава и чипы видят развёрнутый список.

**Модель (`createGridModel`).**

- `$split: Store<string[]>` — id хостов в режиме «раздельно»; `setSplit: EventCallable<{ id: string; on: boolean }>`.
- `GridPersisted.split: string[]`; при загрузке id не из раскладки отбрасываются (как у порядка).
- `GridModelConfig.columns` включает части (у каждой — `id` и `width`), чтобы у частей были ширины по умолчанию и сверка сохранённых.
- `useGrid` отдаёт `split` и `onSplit`.

**Меню состава (`ColumnsMenu`).** Под пунктом колонки с `split` — чекбокс с подписью `split.label`; клавиатура — как у остальных пунктов. Галочки в строке фильтров, как на эталоне, нет — раскладка настраивается в одном месте.

**Демо.**

- 32: «вместе» — сумма и валюта второй строкой; «раздельно» — 32 только сумма, колонка «Валюта» (`Tag`, `fullHeight`), подпись «Валюта отдельной колонкой».
- «Дата / Время»: «вместе» — дата документа и валютирование Дт/Кт; «раздельно» — дата документа, колонка «Валютирование» (Дт и Кт двумя строками, `fullHeight`), подпись «Валютирование отдельной колонкой». Данные: в демо вводятся поля `vdDt`/`vdKt` (ключи сортировки «Валютирование Дт», «Валютирование Кт»); вид ячейки по эталону (R10: время приглушённо, Кт цветом `warn` при расхождении) — 5b.

## 5. Сброс ширин (W1)

- Двойной клик по ручке ресайза любой колонки — все ширины обратно к раскладке (как на эталоне).
- Ползунок ширины: Home — ширина этой колонки к раскладке, Shift+Home — все.
- Модель: `resetWidths: EventCallable<void>`, `resetWidth: EventCallable<string>`; результат сохраняется через `persist`. `useGrid` отдаёт `onResetWidths`, `onResetWidth`.

## 6. Состояния записи (B1) и подсказка открытия (B7)

**Проп `DataGrid`** — данные с бека, модели не нужно:

```ts
rowState?: ((row: Row) => RowState) | undefined
export type RowState =
  | { kind: 'locked'; who: string; since: string }   // since — ISO
  | { kind: 'inactive'; why: string }
  | null
```

**Заблокирована.** Вместо иконки открытия — замок тона `warn`; кнопка работает (просмотр — решение приложения): `onOpen(row, { secondary, state })`. Полоса `warn-soft` 3 px слева, значения приглушены (`muted`), статусная точка обесцвечена. Подсказка и доступное имя кнопки: «Заблокирована: Иванова М. П., с 23.09.2026 09:13 · открыть только для просмотра». Выделять можно.

**Неактивна.** Штриховка ячеек (узор на `--k-sunk`; при наведении — обычный `hover`). Чекбокс `disabled`, подсказка «<причина> · выбрать нельзя». Открыть можно, подсказка кнопки «<причина> · открыть».

**Выделение.** `onSelectPage` отдаёт только id доступных записей; трёхпозиционный чекбокс страницы считается по ним. «Все по фильтру» (`mode: 'all'`): исключение неактивных — на беке (требование к операциям над выделением, записывается в документы бека). `BulkBar` при `mode: 'all'` и наличии неактивных на странице дописывает «без неактивных».

**Стили** — классы записи в `Grid.module.css` на существующих токенах (`warn`, `warn-soft`, `muted`, `sunk`, `hover`).

**B7.** Проп `openHint?: string | undefined` — подсказка кнопки открытия общим тултипом по наведению и фокусу; доступное имя остаётся «Открыть запись N». У заблокированной и неактивной записи вместо неё — подсказка состояния. Демо: «Открыть деталку · двойной клик или Shift — рядом для сравнения».

**Демо-данные.** Заблокирована — запись с индексом `i % 11 === 2`, неактивна — `i % 13 === 7`, вымышленные ФИО и причины эталона («Документ в архиве», «Запись отозвана инициатором», «Снят с обработки администратором»).

- Новые пропы и поля (`fullHeight`, `split`, `rowState`, `openHint`, `$split`, `resetWidths`) совместимы назад.

## 8. Проверки

- Помощники сортировки и `sortRows` по уровням: предел 5, `order`/`then` внутри уровня, пустые в конце.
- Модель: `sortBy` массивом → страница 1 и `GridQuery.sort` массивом; `setSplit`, `resetWidths`, `resetWidth` сохраняются через `persist`; чужие id `split` отбрасываются; ширины частей по умолчанию.
- `resolveSpans` / `fillSegments` с `fullHeight`: обрезка на высокой колонке, заполнители только по первой строке, скрытая высокая колонка.
- `GridRecord` / `GridSkeleton`: `rowSpan` у высоких и служебной колонок, во сквозных строках под ними ячеек нет.
- Клавиатура: ↓/↑ из высокой ячейки — в соседнюю запись; из соседней строки — в высокую ячейку; Shift+Enter в шапке — добавить уровень.
- `ColumnHeader`, `SortChips`: Shift+клик, номер уровня, меню с «+»/«↕», чипы (направление, ✕), доступные имена.
- `ColumnsMenu`: переключатель «раздельно»; части не появляются отдельными пунктами.
- B1/B7: замок и подсказка, `disabled` у неактивной, `onSelectPage` без неактивных, `onOpen` с `state`, подсказка `openHint`.
- axe: грид с высокими колонками, чипами, заблокированной и неактивной записями.
- e2e демо: запись с трёхстрочной датой в коридоре 64–72 (цель 68), скелетон = запись ± 2, 125 % → ×1.25 ± 2; «Валюта отдельной колонкой» добавляет колонку и переживает перезагрузку; Shift+клик по двум заголовкам даёт чипы «1 … › 2 …»; двойной клик по ручке возвращает ширины.
- `pnpm check` (React 17) и CI-задача `react19` зелёные.
