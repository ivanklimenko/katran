# Срез 2e: операции деталки в `apps/pi`

Дата: 2026-10-07. Статус: **проект, на ревью владельца**. Решения владельца 07.10 — §1.3; решения по умолчанию, которые владелец может переиграть, — там же и в §8. Основа — исследование эталона `pi-constructor@e065bfb` (`grid.html`: «Курс» в сводке 32A ~1250, «Проверить баланс» ~1342, `tasksHtml` ~1359, `notifHtml` ~1373) и кода `main` `8360b1f` (2a–2d и план 7 слиты).

## 1. Зачем и что в срезе

После 2d в деталке остались заглушки: «Аннулировать» и «Создать служебный документ» в лейне объявляют нажатие (Д75), «Курс» и «Проверить баланс» не перенесены (Д15), кнопки вкладок «Нотификации» и «Задачи» объявляют `STUB`. На эталоне ни у одной из них нет обработчика — поведение, как и в 2d, **проектируется** вместе с контрактом бека и выражается моделью effector (STATE §10).

### 1.1. Входит в 2e

| Действие | Где | Реестры | Что делает |
|---|---|---|---|
| Аннулировать | лейн | `fx-docs`, `rub-docs` | `Prompt` с обязательной причиной → `POST …/annul`; бек аннулирует сразу или создаёт запрос на утверждение |
| Утвердить / Отклонить аннулирование | плашка под лейном | оба | вторая рука решает по ожидающему запросу (как правку в 2d) |
| Курс | сводка, ячейка 32A | `fx-docs` | поповер: курс ЦБ на дату, рублёвый эквивалент, курс сделки при конверсии |
| Проверить баланс | блок «Транзакции» | оба | поповер: остатки по счетам проводок на текущий момент |
| Переотправить | вкладка «Нотификации» | оба | `Prompt` → `POST …/notifications/resend`, вкладка обновляется ответом |
| Исходное сообщение | строка вкладки «Нотификации» | оба | окно поверх деталки с текстом отправленного сообщения |
| Перейти в блок «Ручные отклонения» | вкладка «Задачи» | оба | ссылка хоста в новой вкладке браузера (грид ручных отклонений, отфильтрованный по id документа) |

### 1.2. Не входит в 2e

- «Создать служебный документ» — остаётся заглушкой с объявлением (решение г3), в коде — пометка «отложено, спека 2e §8».
- Операции над ручными отклонениями внутри деталки — серая зона (г5), только переход.
- Горячие клавиши лейна сверх F5 (2d), правка рубля — не нужны для этих действий; остаются в техдолге STATE §7.
- Аннулирование пачкой из реестра.

### 1.3. Решения владельца 07.10

| # | Вопрос | Решение |
|---|---|---|
| г1 | Бизнес-правила | предлагает Claude, владелец правит, аналитик сверяет позже; правила фейка — §3.7 |
| г2 | Режим аннулирования | решает бек: ответ — «аннулировано сразу» или «запрос ожидает утверждения»; при ожидании вторая рука утверждает или отклоняет, как правку в 2d. Фронт поддерживает оба режима |
| г3 | «Создать служебный документ» | отложить; гипотеза — ЭСИД (ED243 у рубля, MT195/MT199 у валюты), вопрос аналитику (§8) |

Решения по умолчанию (принимаю сам, владелец может переиграть — §8): у аннулирования, решений по нему, правки и решений по правке документа — одна операция за раз; при ожидающем или исполненном аннулировании документ только для просмотра (целей правки нет); закрытая плашка отклонённого запроса снова видна при повторном открытии деталки; переотправляются все нотификации документа одним действием (кнопка — в панели вкладки, как на эталоне); окно «Исходное сообщение» одно на экран; «Ручные отклонения» без настроенной ссылки хоста — кнопка недоступна, а не скрыта.

## 3. `apps/pi`

### 3.1. Контракт (предложение в `docs/reference/pi-api.md`)

1. **`canAnnul: boolean`** у детали обоих реестров (§7.2, §7.3). `true` — документ в статусе, допускающем аннулирование, не заблокирован, открытого запроса на аннулирование нет, у пользователя есть право. Ключ бек отдаёт всегда; отсутствующий маппер читает как `false`.
2. **`annul`** у детали обоих реестров: `null` или
   `{ status: 'pending' | 'done' | 'rejected'; who: string; when: string; reason: string; by: string | null; at: string | null; rejectReason: string | null; canConfirm: boolean }`.
   `who`/`when`/`reason` — автор запроса, время и причина; `by`/`at` — кто и когда утвердил или отклонил (у `done` без второй руки — `null`, у `done` через утверждение — утвердивший); `rejectReason` — причина отклонения (только у `rejected`); `canConfirm` — у `pending`, автор не текущий пользователь и есть право утверждать, иначе `false`. Все ключи отдаются всегда.
3. **`POST /grids/{gridId}/documents/{id}/annul`**, тело `{ "reason" }`; `reason` после `trim` — 1–140 символов. Бек сам выбирает режим: аннулирует сразу (`annul.status: "done"`, статус документа меняет бек — нового значения в словаре статусов нет, §8) или создаёт запрос (`annul.status: "pending"`). Ответ `200` — деталь целиком (§7).
4. **`POST …/annul/confirm`**, тело `{ "when": "<annul.when>" }`; **`POST …/annul/reject`**, тело `{ "when", "reason" }`. Утверждение — `annul.status: "done"`, `by`, `at`, статус документа меняет бек; отклонение — `"rejected"`, `by`, `at`, `rejectReason`, документ возвращается в прежнее состояние (`canAnnul` снова по правилам п. 1). Ответ `200` — деталь целиком.
5. **`GET /grids/fx-docs/documents/{id}/rates`** →
   `{ "cb": { "rate", "date", "rub" }, "deal": { "rate", "from", "to", "amount" } | null }`. Числа — строками, уже отформатированными беком (`"92,4517"`, `"924 517,00"`); `cb.rate` — RUB за 1 единицу валюты 32A на `cb.date`, `cb.rub` — рублёвый эквивалент суммы 32A; `deal` — при конверсии (поле 36 или иная валюта списания): курс `from→to` и списанная сумма в `from`. У `rub-docs` эндпоинта нет — `404`.
6. **`GET /grids/{gridId}/documents/{id}/balances`** →
   `{ "asOf": "<отметка времени>", "items": [{ "acc", "ccy", "balance", "available" | null }] }` — по уникальным счетам проводок документа, порядок — как в проводках. Ошибка по отдельному счёту — элемент `{ "acc", "ccy", "error": "<текст>" }` без сумм; ответ в целом при этом `200`.
7. **Нотификации (§8.5).** У строки новое обязательное поле `id` (строка, уникальна в документе). **`GET …/notifications/{nid}/message`** → `{ "contentType": "application/json" | "application/xml" | "text/plain", "body": "<текст>" }`. **`POST …/notifications/resend`**, тело `{}` → `200`, содержимое вкладки `notif` целиком (та же форма, что `GET …/tabs/notif`).
8. **Ошибки 3–7** — Problem Details (§2):

   | Код | Когда | `type` (предложение) | Фронт |
   |---|---|---|---|
   | `400` | причина пуста или длиннее 140; тело не той формы | `urn:katran:annul-validation` | `errors[0].message` под полем причины, `Prompt` открыт |
   | `403` | нет права; автор утверждает свой запрос | — | текст ошибки в `Prompt` (у чтения — в поповере / окне) |
   | `409` | уже аннулирован; запрос уже обработан или `when` не совпал; статус не позволяет; переотправка уже идёт | `urn:katran:annul-conflict`, `urn:katran:resend-conflict` | аннулирование: `Prompt` закрывается, перезапрос детали, объявление «Документ изменили — данные обновлены»; переотправка: объявление текста ошибки, вкладка перезапрашивается |
   | `404` | нет документа; `rates` у рубля; нет нотификации | — | текст ошибки на месте действия |
   | `5xx`, транспорт | — | — | текст ошибки на месте действия, повтор доступен |

9. **«Ручные отклонения»** нового контракта не требуют: адрес строит хост (§3.2).

### 3.3. Слой `features`

- **`features/doc-annul`** — `createDocAnnul({ ports, lifecycle, blockedDocs })`:
  - события `annulRequested(docId)`, `confirmRequested({ docId, when })`, `rejectRequested({ docId, when })`, `reasonChanged({ docId, reason })`, `promptResult({ docId, ok })`;
  - стор `$prompt: Record<docId, { kind: 'annul' | 'confirm' | 'reject'; when: string | null; reason: string; busy: boolean; error: string | null }>`; `$busyDocs` — документы с открытым `Prompt` или запросом в полёте;
  - запросы игнорируются, если документ в `blockedDocs` (стор правки: открыт редактор, сохранение, решение второй руки) — одна операция над документом за раз; `createDocEdit` в обратную сторону получает `$busyDocs` аннулирования тем же способом (новый необязательный параметр `blockedDocs`, без него поведение 2d);
  - успех — событие `docAnnulled({ id, detail, kind })`, `$prompt` документа снимается; `$done: { count, text }` растёт с текстом «Документ аннулирован» (`annul` → `done`), «Запрос на аннулирование отправлен» (`annul` → `pending`), «Аннулирование утверждено», «Аннулирование отклонено»;
  - `409` — `$prompt` снимается, событие `conflict(id)`, `$done` с текстом «Документ изменили — данные обновлены»; прочие ошибки — `error` в `$prompt`, `busy: false`;
  - `promptResult({ ok: false })` при `busy` игнорируется; ответы фильтруются по визиту экрана (как Ruling R10 2d); открытый не `busy` `Prompt` документа, ушедшего из слотов, снимает страница (как R12);
  - вид: `useAnnulOf(model)` → `annulOf(docId) → AnnulView` — состояние кнопки лейна (§4 п. 1), содержимое плашки (§4 п. 4) и `Prompt`; подсказки и тексты — здесь, в ките их нет.
- **`features/doc-lookups`** — `createLookup<T>({ fx, lifecycle })`: стор `$data: Record<docId, { state: 'loading' | 'ready' | 'error'; value: T | null; error: string | null }>`; события `load(docId)` (есть `ready` — ничего не делает), `retry(docId)`, `refresh(docId)` (перезапрос при `ready`, старое значение видно до ответа), `reset(docId)`; `pageClosed` очищает всё; поздний ответ после `reset` отбрасывается (эпоха документа). Два экземпляра на странице валюты (`rates`, `balances`), один у рубля (`balances`). Вид — `useLookupOf(model)` → `(docId) => LookupView<T>`.
- **`features/doc-notif`** — `createDocNotif({ ports, lifecycle })`:
  - `resendRequested(docId)` → `Prompt` «Переотправить нотификацию?» (пояснение «Будет создана новая попытка отправки», кнопки «Переотправить» / «Отмена»), `resendResult({ docId, ok })` → `resendFx`; успех — событие `resent({ id, data })` (страница кладёт в кэш вкладки через `detail.replaceTab`), объявление «Нотификация переотправлена»; `409` и прочие ошибки — `Prompt` закрывается, объявление текста ошибки, вкладка перезапрашивается (`409`) или остаётся (прочие); `$resendBusy: Record<docId, true>`;

### 3.7. Фейк

- **`canAnnul`** — статус `IN_PROGRESS`, `TO_EXPORT`, `ERROR` или `DEFERRED`, нет `lock`, `annul` — `null` или `rejected`.
- **`annul`**: нет `canAnnul` — `409` (заблокирован — `403`); пустая или длинная причина — `400` (путь `reason`); сумма 32A (у рубля — сумма документа) больше 1 000 000 — `pending` от «Вы» (`canConfirm: false`), иначе сразу `done`, статус документа — `REJECTED` («Отказ», §8). Регулятор `?annul=instant|pending` принудительно задаёт режим.
- **`confirm`/`reject`**: нет запроса или `when` не совпал, запрос не `pending` — `409`; автор «Вы» — `403`; причина отклонения пуста или длиннее 140 — `400`; утверждение — `done`, статус `REJECTED`; отклонение — `rejected`, статус документа прежний. `by` — «Вы», `at` — текущее время фейка.
- **Сид:** один документ валюты с чужим ожидающим запросом (Кузнецов Д. А., `canConfirm: true`, сумма > 1 000 000), один уже аннулированный (`done`), один рублёвый с чужим ожидающим запросом.
- **`rates`**: вымышленная таблица курсов ЦБ по валютам и датам (детерминированно от валюты и даты 32A), `rub` — сумма × курс; `deal` — у документов с полем 36 (курс поля 36, валюта списания — из поля 33B или вымышленная пара).
- **`balances`**: по уникальным счетам проводок; остаток и доступно — детерминированно от хеша счёта, `available` у части счетов `null`; у одного счёта сида — `error: "Счёт не найден в АБС"`. `asOf` — текущее время фейка.
- **Нотификации**: строки получают `id`; тело сообщения — JSON у валюты, XML у рубля (`text/plain` — у одной строки сида для проверки языка `text`); `resend` дописывает попытку `OK` с текущим временем; повторный `resend` в течение задержки фейка — `409`.
- **Регуляторы `?fail=annul|rates|balances|resend|notifmsg`** — `500` на соответствующем запросе; **`?hostlinks=1`** — стенд вызывает `configureHostLinks` с адресом-заглушкой реестра стенда (для e2e новой вкладки).
- `contract.test.ts` — новые ответы и все ошибки.

## 4. Поведение

1. **Кнопка «Аннулировать»** (лейн, `danger`). Доступна при `canAnnul`. Иначе — `aria-disabled="true"` с подсказкой по причине: заблокирован — «Документ заблокирован: {who}»; запрос `pending` — «Запрос на аннулирование ожидает утверждения»; `done` — «Документ аннулирован»; иначе — «Аннулирование недоступно для документа в статусе «{статус}»». Пока у документа идёт другая операция (правка, решение) — недоступна с подсказкой «Завершите текущую операцию с документом».
2. **Аннулировать.** Клик → `Prompt` «Аннулировать документ?» (тон danger): номер и сумма с валютой, поле «Причина» (обязательное, счётчик 0/140), кнопки «Аннулировать» / «Отмена». «Аннулировать» недоступна, пока причина пуста после `trim`. В полёте — обе недоступны. Успех — `Prompt` закрыт, деталь и реестр обновлены, объявление «Документ аннулирован» или «Запрос на аннулирование отправлен».
3. **Утвердить / Отклонить аннулирование.** Кнопки на плашке `pending` при `canConfirm`. «Утвердить» → `Prompt` «Утвердить аннулирование?» (автор, время, причина запроса; «Утвердить» / «Отмена»). «Отклонить» → `Prompt` «Отклонить аннулирование?» с обязательной причиной (тон danger, «Отклонить» / «Отмена»). После решения фокус остаётся в drawer (на заголовке, как `fallbackFocus` 2d).
4. **Плашка** (`Banner` под лейном):
   - `pending` — тон warn: «Аннулирование ожидает утверждения · {who}, {when} · Причина: {reason}», действия «Утвердить» / «Отклонить» при `canConfirm`;
   - `done` — тон bad: «Документ аннулирован · {by ?? who}, {at ?? when} · Причина: {reason}»;
   - `rejected` — тон neutral: «Запрос на аннулирование отклонён · {by}, {at} · {rejectReason}», кнопка «Закрыть»; после закрытия скрыта до повторного открытия деталки.
5. **Конфликт.** `409` на любом шаге аннулирования — `Prompt` закрывается, деталь перезапрашивается, объявление «Документ изменили — данные обновлены».
6. **Курс** (только валюта). Кнопка-ссылка «Курс» в ячейке 32A открывает поповер (`Popover` кита, `role="dialog"`, подпись «Курс»): «Курс ЦБ на {date} — {rate} RUB за 1 {ccy}», «Рублёвый эквивалент — {rub} RUB»; при `deal` — «Курс сделки {from}→{to} — {rate} · списано {amount} {from}». Первое открытие загружает, повторное показывает кэш.
7. **Проверить баланс** (оба реестра). Кнопка-ссылка в заголовке блока «Транзакции» открывает поповер: таблица «Счёт · Валюта · Остаток · Доступно» (`available: null` — «—»), строка счёта с ошибкой — текст ошибки на всю ширину строки, подпись «по состоянию на {asOf}», кнопка «Обновить» (перезапрос, старые данные видны до ответа). Клик по кнопке-ссылке не сворачивает и не разворачивает блок.
8. **Общее у поповеров**: загрузка — скелетон, ошибка — текст и «Повторить»; Esc и клик вне — закрыть с возвратом фокуса на кнопку-ссылку; Esc закрывает поповер, а не деталку.
9. **Ручные отклонения.** Ссылка хоста задана — это `<a href target="_blank" rel="noopener">` в виде кнопки (`Button`), открывает новую вкладку браузера. Не задана — `aria-disabled="true"`, подсказка «Переход не настроен для этого стенда».
10. **Переотправить.** Кнопка в панели вкладки → `Prompt` (§3.3); в полёте кнопка `aria-disabled`, `aria-busy`; успех — вкладка показывает новую попытку, объявление «Нотификация переотправлена».
11. **Исходное сообщение.** Ссылка строки → окно (§3.3) поверх деталки; «Скопировать» — в буфер, объявление «Скопировано»; буфер недоступен — объявление «Не удалось скопировать — выделите текст»; Esc и «Закрыть» закрывают окно (не деталку), фокус возвращается на ссылку строки.

## 8. Открытые вопросы

Не блокируют старт; решения по умолчанию приняты выше.

1. **«Создать служебный документ»** (г3) — что это (ЭСИД: ED243 у рубля, MT195/MT199 у валюты?), кто адресат, нужна ли форма ввода. Вопрос аналитику.
2. **Статус после аннулирования.** В словаре нет «Аннулирован»; фейк ставит `REJECTED` («Отказ»). Нужен ли отдельный статус (`CANCELED`?) или достаточно `REJECTED` + плашки — решает бек и аналитик.
3. **Порог «через утверждение».** Фейк: сумма > 1 000 000 (без пересчёта в рубли). Настоящее правило (сумма в рублях, статус, роль, тип документа) — у бека; фронт от него не зависит.
4. **Статусы, допускающие аннулирование** — фейк: `IN_PROGRESS`, `TO_EXPORT`, `ERROR`, `DEFERRED`; проверить у аналитика `PROCESSING` и `INVALID`.
5. **Операции ручных отклонений в деталке** (г5) — серая зона, позже.
6. **Переотправка по одной нотификации** (а не всех документа) — на эталоне кнопка одна в панели; если бек умеет по `nid`, добавить кнопку в строку.
7. Имя функции хоста `configureHostLinks` и ключ `manualDeviations` — согласовать с командой хоста вместе с `configureDocLinks`.
