# Дизайн-система katran — спецификация

Дата: 2026-09-23 · Обновлена: 2026-09-24 — разделы 3, 6–9, 12 приведены к реализации плана 2 (DataGrid, модели effector) · Статус: согласована по секциям · Владелец: Иван Клименко

Katran — самостоятельная дизайн-система для интерфейсов проекта на React + effector. Источник — макеты реестра и деталки валютных платёжных инструкций (`pi-constructor`), прошедшие дизайн-ревью в сентябре 2026. Кит строится вертикальными срезами: первым переносится реестр целиком, компоненты добываются из реального экрана, а не проектируются впрок.

---

## 1. Назначение и границы

### 1.1. Что обслуживает

- **Реестры** — валютные и рублёвые ПИ, справочники, журналы: грид + фильтры + деталка.
- **Формы ввода и правки** — создание и редактирование документа, валидация, подтверждения.
- **Дашборды и мониторинг** — динамика статусов, плитки показателей.

### 1.2. Не делаем

| Что | Почему |
|---|---|
| Admiral — ни как зависимость, ни как обёртка | Решение владельца: кит самостоятелен. Снимает styled-components и привязку к версиям чужого кита |
| Админка, навигация, деревья, сложные селекты | Не в перечне обслуживаемых экранов |
| Виртуализация списка | Пагинация 20 записей на страницу; виртуализация не даёт ничего, кроме сложности |
| i18n | Интерфейс русский |
| Темизация под несколько брендов | Две темы: светлая и тёмная |
| Мульти-сортировка | Вторичный ключ задаётся декларативно через `then`, этого хватает |
| Перетаскивание колонок мышью | Состав и порядок — через меню; DnD конфликтует с ресайзом на той же границе и требует клавиатурного эквивалента |

### 1.3. Отложено с памятью о причине

- **Свой календарь с производственным календарём** — решено «не сейчас»; `DateInput` оставляет место под замену нативного пикера.
- **Advanced-режим фильтров** — требует отдельной проработки (раздел 7). Вендоренная панель `ermo-snapshot` на стенде — функциональный макет, не образец.
- **Канал поставки в целевой проект** — организационно сложен, возможно ручное копирование. Не фиксируем; проектируем переносимость (раздел 3.4).

## 2. Принципы

1. **Компонент рождается из экрана.** Срез 1 — реестр, срез 2 — деталка, срез 3 — дашборд. Ничего впрок.
2. **UI чистый, состояние в моделях, транспорт в приложении.** `@katran/ui` не знает об effector, `@katran/effector` не знает о DOM и HTTP.
3. **Токены — единственный источник цветов и размеров.** Голые `px` и `hex` в компонентном CSS запрещены и ловятся линтером.
4. **Интерактив — настоящая кнопка с именем.** Клавиатура и скринридер — не опция: в банковской ИС «деталку нельзя открыть с клавиатуры» — блокирующий дефект.
5. **Переносимость.** Исходники должны переживать ручное копирование в другой проект.
6. **Эталон поведения — замороженный `pi-constructor`.** Геометрия и поведение сверяются с ним; новые правки идут только в katran.

## 3. Репозиторий и пакеты

### 3.1. Структура

```
katran/
  packages/
    tokens/     источник токенов → tokens.css + index.ts
    ui/         React-компоненты; deps: tokens, @floating-ui/dom
    effector/   фабрики моделей и хуки; deps: effector, effector-react
  apps/
    demo/       витрина и боевые экраны → GitHub Pages
  docs/
    superpowers/specs/, superpowers/plans/
```

Инструменты: pnpm workspaces · TypeScript strict · Vite (library mode для пакетов, app для демо) · vitest + Testing Library · eslint (`import-x/no-restricted-paths`, `@typescript-eslint/no-restricted-imports`, `jsx-a11y`) · stylelint · Playwright для замеров геометрии.

### 3.2. Правило зависимостей — проверяется, не декларируется

| Пакет | Может импортировать | Запрещено |
|---|---|---|
| `tokens` | ничего | — |
| `ui` | `tokens`, `react`, `@floating-ui/dom` | `effector`, всё из `packages/effector` |
| `effector` | `effector`, `effector-react`, типы из `ui` (только `import type`) | DOM API, компоненты `ui` |
| `demo` | всё | — |

Нарушение ловит линт, и `pnpm check` падает. Без этого граница между слоями исчезнет на третьей «срочной» правке. Правила (`eslint.config.js`):

- `import-x/no-restricted-paths` — `ui` не импортирует из `packages/effector`; `effector` не обращается к `packages/ui/src` в обход входа пакета;
- `no-restricted-imports` — `effector` и `effector-react` запрещены везде, кроме `packages/effector` и демо;
- в `packages/effector/src`: `@typescript-eslint/no-restricted-imports` пропускает из `@katran/ui` только `import type` и запрещает подпути `@katran/ui/*` (стили); `no-restricted-globals` запрещает `document` и `window`. `localStorage` не запрещён — им пользуется persist-адаптер (8.2). Правило о типах добавлено по финальному ревью плана 2: прежний набор пропускал value-импорт `DataGrid` в модель.

`@floating-ui/dom` — единственная рантайм-зависимость `ui` помимо React: позиционирование тултипа, меню и поповера. Своя реализация была бы хуже и больше.

### 3.3. Компонент

Папка из четырёх файлов: `Thing.tsx`, `Thing.module.css`, `Thing.test.tsx`, `index.ts`. Стили — CSS Modules без рантайма, имена детерминированные: `k-Thing__part`. Изоляция от хозяина — префиксом `k-`; имена читаемы в devtools и переопределяемы в аварийной ситуации, чего не даёт хеш.

### 3.4. Переносимость

- Пакеты ссылаются друг на друга только по имени (`@katran/tokens`), никаких путей и alias'ов монорепо внутри `src`.
- Peer-зависимости: `react ≥ 18`, `react-dom ≥ 18`, `effector ≥ 23`, `effector-react ≥ 23`. Рантайм-зависимостей сверх `@floating-ui/dom` нет.
- Шрифты IBM Plex Sans / Mono лежат в `tokens` и подключаются `@font-face` — не с Google Fonts: в банковской сети внешних ресурсов нет.
- Каждый пакет собирается в `dist/` (ESM + `.d.ts` + CSS), но и исходники пригодны к прямому подключению. В монорепо потребители работают исходниками (`exports` → `src`); для внешних потребителей `publishConfig.exports` указывает на `dist`. `@floating-ui/dom` не вшивается в сборку.
- **Побочный эффект входа объявлен.** `@katran/ui` декларирует `"sideEffects": ["**/*.css", "./src/index.ts"]`. Вход пакета импортирует `@katran/tokens/tokens.css`; с одними CSS-глобами бандлер считает `src/index.ts` чистым, и production-сборка потребителя по исходному входу выбрасывает этот импорт — страница остаётся без токенов. В dev-сервере дефект не виден; найден Playwright-замером production-сборки демо (план 2).
- **Встраивание через федерацию.** Приложение живёт внутри метаприложения (module federation), поэтому кит не трогает `<html>`, `<body>` и глобальные стили: тема, плотность, портал наложений — всё на корне `KatranProvider`. Близкие по смыслу справочники объединяются в один блок табами ради экономии на точках встраивания.

## 4. Токены

### 4.1. Один источник

`packages/tokens/src/tokens.src.ts` — единственное место правки. Скрипт генерирует `tokens.css` (переменные для двух тем) и `index.ts` (константы для JS — нужны графику). CI проверяет, что сгенерированные файлы совпадают с источником. Два списка руками уже расходились на стенде.

### 4.2. Цвет

Палитра переносится из эталона без изменений — она прошла ревью: `--k-val` = XP-синий `#3A6EA5` (цвет значений, требование владельца), `--k-faint` — служебный токен с контрастом 3.75:1 на белом (не для читаемого текста), статусы сведены с девяти оттенков к четырём семействам.

| Группа | Токены (светлая тема) |
|---|---|
| Поверхности | `ground #EEF1F6` · `paper #FFFFFF` · `sunk #F5F7FB` · `hover #F2F6FA` · `chip #EEF0F4` |
| Текст | `ink #141A29` · `ink2 #3A4357` · `muted #6B7488` · `faint #7C8496` |
| Линии | `line #DCE1EA` · `line2 #EAEEF4` |
| Акцент | `val #3A6EA5` · `val-soft #E9EFF7` |
| Семантика | `ok #17844B` / `ok-soft #E3F5EA` · `bad #C2372E` / `bad-soft #FCE6E4` · `warn #A8620B` / `warn-soft #FDF1DD` / `warn-row #FFF9EE` · `opt #B0247A` / `opt-soft #FBE8F3` · `fold #D0342C` |
| Статусы | в движении: `st-flow #3A6EA5` · `st-flowl #6B98C6` · `st-flowd #2B5384` — внимание: `st-bad #C2372E` · `st-badd #8C2B23` · `st-warn #A8620B` — успех: `st-ok #17844B` · `st-okl #4E9E77` — нейтрально: `st-grey #8A93A6` |

Тёмная тема — свой набор значений тех же имён (перенос из эталона). Роли: значения параметров — `val`, названия полей — `ink2`, теги SWIFT-полей — `opt`, служебные токены вроде `S:`/`R:` — `faint`.

Переключение: атрибут `data-theme="light|dark"` на корне провайдера; без атрибута — `prefers-color-scheme`. Светлая палитра объявляется под `:root, [data-theme="light"]`, тёмная — под `[data-theme="dark"]` и в медиа-запросе `:root:not([data-theme="light"])`: иначе `data-theme="light"` внутри тёмного предка (или при системной тёмной теме) не действует — найдено финальным ревью 2026-09-23.

### 4.3. Плотность вместо zoom

На стенде масштаб 100/110/125 % сделан через CSS `zoom` на `<html>`. Он ломает `getBoundingClientRect` — каждому компоненту, считающему координаты, приходится делить на коэффициент. В ките:

- `--k-density` ∈ {1, 1.1, 1.25}, выставляется провайдером inline на своём корне; корень несёт атрибут `data-k-root`;
- **все размерные токены уже умножены**: `--k-fs-1: calc(12.5px * var(--k-density))`, `--k-sp-2: calc(8px * var(--k-density))`, `--k-h-ctl-m: calc(28px * var(--k-density))`;
- **размерные токены объявляются под селектором `:root, [data-k-root]`**, а не только в `:root`. Причина — правило CSS: `var()` внутри значения custom property резолвится на элементе, где свойство объявлено, и наследуется уже вычисленным; объяви размеры только в `:root` — и переопределение `--k-density` на корне провайдера ни на что не повлияет (найдено браузерной проверкой демо 2026-09-23). Побочный выигрыш: вложенный провайдер с другой плотностью работает. **Общее правило:** любая группа токенов, которую провайдер переопределяет на своём корне (плотность, тема), объявляется под `:root, [селектор корня]`, а не только в `:root`;
- компонентный CSS использует только токены; `stylelint` запрещает голые `px`.

`<html>` не трогаем — чужой CSS в `rem` не страдает; координаты честные. Базовые размеры рассчитаны на 1080p @ 100 % ≈ 2K @ 125 %. По умолчанию плотность 1.25 при ширине экрана ≥ 2200.

### 4.4. Остальные группы

- **Типографика**: `sans` IBM Plex Sans, `mono` IBM Plex Mono; три кегля `fs-1/2/3` = 12.5 / 11 / 10.5; веса 400/500/600/700; заголовок экрана 20.
- **Ритм**: шаг 4; отступы `sp-1..8`; высоты контролов `h-ctl-s/m/l` = 24 / 28 / 32; строка SWIFT-поля 23; радиусы `r-s/m` = 4 / 6.
- **Тень**: `shadow` для наложений.
- **Слои**: `z-sticky 10` · `z-drawer 100` · `z-menu 200` · `z-tooltip 300`. Промт рендерится внутри контекста своего drawer — окно принадлежит документу, а не странице.
- **Длительности**: `t-fast 120ms` · `t-base 200ms`; порог показа скелетона 200 мс, минимум показа 400 мс.

## 6. DataGrid

### 6.1. Модель записи

Запись — не строка, а **`<tbody>` из нескольких `<tr>`**. Первая строка — ячейки колонок, следующие — сквозные сегменты (причина статуса под статусом и ID, назначение платежа сквозь 50–59). Граница `--k-line` проходит по записи; внутри записи линий нет. Запись ≤ 3 строк контента.

**Высота записи** из строки колонок в две строки текста и одной сквозной строки — **72 px при плотности 1 по замеру**: 8 + 2 × 17 + 4 + 17 + 8 + 1 (отступ `sp-2`, две строки `lh-1`, отступ сквозной строки `sp-1`, строка `lh-1`, отступ `sp-2`, граница). Эталон — ≈ 65 px со стенда `pi-constructor`. Реализация расхождение не решает: владелец снимает число со стенда и либо сужает коридор e2e (сейчас 60–74), либо принимает 72 (раздел 12).

**Служебная колонка.** Первая колонка — чекбокс выделения, кнопка открытия, порядковый номер — служебная: не входит в `layout.columns`, не участвует в `spans`, сортировке и составе колонок; ширина — токен `grid-lead`. Причина: данных строки в ней нет, её содержимое определяют пропы грида (`selection`, `onOpen`), а не раскладка. В сквозных строках служебная ячейка пустая.

**Геометрия по построению.** Кламп ячейки — `max-height: calc(var(--k-lh-1) * var(--k-lines))`; `--k-lines` — локальная переменная из `lines` колонки или сегмента (префикс `k-`: правило stylelint для custom properties действует без исключений). Скелетон совпадает с записью, потому что его ячейки резервируют высоту **теми же токенами**: текстовая — `min-height: lh-1 × lines`, служебная — `h-ctl-s` (высота чекбокса и кнопки). По самим плашкам `Skeleton.Line` высота не совпала бы — они ниже строки текста (замер: 67 против 72); общий примитив `Skeleton` ради грида не меняется.

### 6.2. Контракт

```ts
type ColumnDef<Row> = {
  id: string
  title?: string            // пустой допустим — у колонки статуса заголовка нет
  menuTitle?: string        // имя в меню сортировки и состава, если title пуст
  subtitle?: string
  width?: number            // начальная ширина в px при плотности 1
  minWidth?: number         // по умолчанию 36
  resizable?: boolean       // по умолчанию true
  lines?: 1 | 2 | 3         // строк контента; по умолчанию 1. Задаёт скелетон и кламп
  align?: 'left' | 'right'  // right — для сумм
  sort?: SortKey[]          // пусто → не сортируется
  render: (row: Row) => ReactNode
}

type SortKey = {
  id: string
  label: string             // подписывается в шапке, когда ключ выбран
  type?: 'text' | 'number' | 'date'
  then?: string             // второй ключ, в том же направлении
  order?: string[]          // фиксированный порядок значений: ['IN','OUT','TRANSIT','OTHER']
}

type SpanDef<Row> = {
  id: string
  from: string              // id колонки начала
  to: string                // id колонки конца, включительно
  lines?: 1 | 2
  render: (row: Row) => ReactNode | null   // null → бледная подложка, не закрашивается
}

type RecordLayout<Row> = {
  columns: ColumnDef<Row>[]
  spans?: SpanDef<Row>[][]  // дополнительные строки записи; в каждой — сегменты слева направо
  rowKey: (row: Row) => string
}

// состояние вида
type Sort = { key: string; dir: 'asc' | 'desc' } | null
type Selection = { mode: 'ids'; ids: string[] } | { mode: 'all'; except: string[] }
type ColumnsState = { order: string[]; hidden: string[] }
type GridViewState = 'ready' | 'loading' | 'refreshing' | 'error'
```

Типы объявлены в `@katran/ui` (`grid/types.ts`); `@katran/effector` реэкспортирует их через `import type` — у контракта один источник. В коде опциональные поля записаны как `?: T | undefined` (`exactOptionalPropertyTypes`).

### 6.3. Правила

**Сквозные сегменты** адресуются по `id` колонок, не числом `colspan`. Ширина считается от текущего видимого состава: часть колонок диапазона скрыта — сегмент сжимается; все скрыты — не рисуется. При пользовательском порядке сегмент накрывает всё, что стоит между `from` и `to`, границы нормализуются. Реализация — чистая функция `resolveSpans(spans, visibleOrder, fullOrder) → { id, colStart, colSpan }[]`, тестируется без DOM: диапазон берётся по полному порядку (со скрытыми колонками), индексы — по видимым.

**Сортировка.** Одна активная: `{ key, dir }`. Простая колонка (один ключ) — клик по заголовку переключает направление. Составная — клик открывает меню реквизитов, выбранный ключ подписывается в шапке вместо `subtitle`, есть «Сбросить сортировку». Направление по умолчанию: `date` и `number` — по убыванию, `text` — по возрастанию. `order` задаёт фиксированный порядок значений, `then` — вторичный ключ в том же направлении. Разрешение ничьих стабильное. В серверном режиме грид не сортирует сам — модель отправляет `sort` в запрос. Клиентская сортировка `sortRows(rows, sort, columns, get)` (демо, фейковый бэкенд) получает доступ к значению параметром `get`, поэтому в `SortKey` такого поля нет — в серверном режиме оно было бы мёртвым.

**Ресайз.** Ручка на правой границе `<th>`; ширина таблицы = сумма ширин, таблица прижата влево. Минимум — `minWidth` колонки, по умолчанию 36. Это константа (`ColumnHeader`, модель), а не токен: порог задан в px при плотности 1 и в CSS не участвует — токен `grid-min-col` был бы мёртвым. Ручка — `<button role="slider">` с `aria-valuenow`/`aria-valuemin`/`aria-valuemax` (9999 — предела нет), `aria-valuetext="N px"`, `aria-orientation="horizontal"`; стрелки ← → шаг 8, Shift — 32. Не `separator`: `jsx-a11y` не моделирует фокусируемый separator, и пришлось бы отключать правило, а slider семантически точен — у ручки есть значение, и оно меняется стрелками. Цена — скринридер называет ручку «слайдер». Ориентация горизонтальная: значение меняется стрелками влево/вправо, хотя сама ручка — вертикальная черта.

**Состав колонок.** Меню: поиск по названию, галочки показать/скрыть, перенос вверх/вниз. Порядок и видимость хранятся в модели и сохраняются через `persist`.

**Пагинация.** Порядковый номер записи — сквозной по выборке: `(page − 1) × pageSize + i + 1`. Размер страницы 20 по умолчанию, варианты — `pageSizes`, смена — `onPageSize`; переключатель страниц внизу. Смена фильтра, сортировки или размера страницы — на первую страницу.

**Состояния** — `GridViewState`; `empty` — это `ready` без строк. `loading` — скелетон той же геометрии (6.1: по `lines` колонок и сегментов; `skeletonRows` записей, по умолчанию 8), порог показа 200 мс, минимум 400 мс (`sk-show`/`sk-min`, `useLoadingGate`). Пока скелетон удерживается минимумом, записи, пустое состояние и ошибка не показываются — иначе на быстром ответе они мелькнули бы вместе со скелетоном. `refreshing` — полоса прогресса и приглушение (`dim`) показанных данных. `empty` — `emptyTitle` (по умолчанию «По заданным условиям записей нет») и действие `emptyAction` («Сбросить фильтр»). `error` — «Не удалось загрузить данные», текст `error`, кнопка «Повторить» → `onRetry`.

**Выделение и массовые действия.** Чекбокс в служебной колонке и в шапке (трёхпозиционный, по записям текущей страницы); появляются, когда переданы `selection` и колбэк — `onSelect({ id, on })` для записи, `onSelectPage({ ids, on })` для шапки. Состояние — `Selection` (6.2): `ids`/`except` — массивы строк, не `Set`. `Set` не сериализуется в JSON (стор effector, `{ filter, selection }` для массовых действий на беке) и сравнивается по ссылке в пропах React.

`mode: 'all'` — «всё по текущему фильтру» (серверный режим, не список id). `BulkBar` показывает «Выбрано N» или «Все N по фильтру», действия получают `{ filter, selection }`. Выделение обеих строк записи подсвечивается вместе. Смена фильтра сбрасывает выделение; смена сортировки и страницы — нет.

**Открытие деталки.** Запись **не кликабельна** (правило владельца). Открывает только кнопка в первой ячейке — настоящая `<button>` с именем. Грид отдаёт `onOpen(row, { secondary })`; `secondary` — второй клик подряд (`e.detail ≥ 2`), приложение решает, что это второй drawer. Двойной клик даёт два вызова — сначала `secondary: false`, затем `true`; модель drawer-стека (срез 2) это учитывает.

**Клавиатура.** Паттерн WAI-ARIA `grid`: один таб-стоп на весь грид, дальше стрелки по ячейкам (roving tabindex). Вторая строка записи — обычная строка сетки, стрелка вниз на неё заходит: там настоящие данные. `Home`/`End` — начало/конец строки. `Enter` на ячейке переводит фокус на её первый интерактивный элемент, а если он единственный — нажимает его: на значении — копировать, на кнопке — открыть, на заголовке — сортировка/меню. Ручка ресайза в этот набор не входит, иначе `Enter` на заголовке не сортировал бы. Внутри ячейки `Tab`/`Shift+Tab` ходят по кругу по её интерактивным элементам, включая ручку ресайза (APG: навигация внутри виджета ячейки; иначе ручка с клавиатуры недостижима); при одном элементе `Tab` уводит из грида как обычно. `Escape` возвращает фокус в ячейку.

Весь интерактив внутри грида — `tabIndex={-1}`: иначе каждый элемент стал бы своим таб-стопом, и «один таб-стоп» развалился бы. Поповеры и меню ячеек (состав колонок, ключи сортировки) рендерятся порталом, но в React-дереве остаются потомками ячейки, и их синтетический `keydown` всплывает к ней. Обработчик ячейки такие события не трогает (`cell.contains(e.target)`) — иначе `Tab` в поповере уводил бы фокус в ячейку. Смена страницы, числа записей, состава колонок, появление и исчезновение записей (скелетон, ошибка) возвращают таб-стоп на первую ячейку записей, а без записей — на шапку.

**Разметка для AT.** `<table role="grid">` с `aria-label` из обязательного пропа `label` — на странице может быть два грида (8.1), без имени скринридер их не различит; `aria-colcount` = 1 + видимые колонки. Строки нумеруются абсолютно по выборке: шапка — 1, первая строка записи `i` страницы `page` — `aria-rowindex = 2 + ((page − 1) × pageSize + i) × perRecord`, где `perRecord` = 1 + число сквозных строк; `aria-rowcount = 1 + total × perRecord`. Так AT сообщает положение в выборке, а не на странице. Строка empty/error — `aria-rowindex = 2`, и пока она показана, `aria-rowcount` не меньше 2: индекс не может превышать счётчик. Клавиатурный слой считает свои ключи внутри страницы и от `aria-rowindex` не зависит. Скелетон скрыт от AT (`aria-hidden` на его `tbody`, без индексов): пустые ячейки ничего не сообщают. О загрузке говорит `aria-busy` на таблице — при `loading`, `refreshing` и всё время, пока скелетон удерживается минимумом. `aria-multiselectable` — когда передан `selection`; выделенная запись — `aria-selected` на всех её строках.

### 6.4. Компонент

```ts
type DataGridProps<Row> = {
  label: string                              // доступное имя сетки, обязательно
  layout: RecordLayout<Row>
  rows: Row[]
  total: number
  page: number                               // с единицы
  pageSize: number
  onPage: (n: number) => void
  pageSizes?: number[]
  onPageSize?: (n: number) => void
  sort: Sort
  onSort: (s: Sort) => void
  widths: Record<string, number>
  onResize: (p: { id: string; width: number }) => void
  order: string[]
  hidden: string[]
  onColumns: (s: ColumnsState) => void
  selection?: Selection                      // нет — нет выделения
  onSelect?: (p: { id: string; on: boolean }) => void
  onSelectPage?: (p: { ids: string[]; on: boolean }) => void
  state: GridViewState
  error?: string | null                      // текст под «Не удалось загрузить данные»
  onRetry?: () => void
  emptyTitle?: string
  emptyAction?: { label: string; onClick: () => void }
  onOpen?: (row: Row, opts: { secondary: boolean }) => void   // нет — нет кнопки открытия
  skeletonRows?: number                      // по умолчанию 8
}
```

Чистый компонент: все данные — из props, все изменения — наружу. Выделение — два колбэка намерения, а не `onSelection(next)`: грид не вычисляет следующее `Selection` (в режиме `all` это работа модели с `except`), а сообщает, что отмечено — запись или страница. В приложении с effector: `<DataGrid {...useGrid(model)} label=… layout=… />` — хук отдаёт данные и колбэки модели (8.4), экранные пропы (`label`, `layout`, `pageSizes`, `emptyTitle`, `emptyAction`, `onOpen`, `skeletonRows`) задаёт экран.

## 7. Фильтры — рамка

Раздел фиксирует то, что нельзя отложить. Вид и поведение advanced-режима — предмет отдельной проработки до его реализации.

### 7.1. Решено сейчас

**Одна модель, два режима.** `simple` (справочник на 5–10 реквизитов: поля прямо на панели, оператор по умолчанию от типа — текст `CONTAINS`, число и дата `EQ`) и `advanced` (сущность на 200+ реквизитов) — режимы одной `createFiltersModel`, а не два компонента. Состояние одно:

```ts
type Condition =
  | { field: string; op: 'EQ'|'NE'|'CONTAINS'|'STARTS_WITH'|'ENDS_WITH'|'GT'|'GTE'|'LT'|'LTE'; value: Scalar }
  | { field: string; op: 'IN'|'NOT_IN'; values: Scalar[] }
  | { field: string; op: 'BETWEEN'; from: Scalar; to: Scalar }
  | { field: string; op: 'IS_EMPTY'|'IS_NOT_EMPTY' }
type Filter = Condition[]   // v1: только AND
```

Словарь операторов и семантика — из `vtb-filters/docs/filter-contract.md` (14 операторов: 9 сравнений со скаляром, `IN`/`NOT_IN`, `BETWEEN`, `IS_EMPTY`/`IS_NOT_EMPTY`; типы полей, регистр, `NULL`).

**Каталог полей — от бека.** `GET /grids/{gridId}/filter-meta` отдаёт поля, группы, допустимые операторы и встроенные справочники. Кит не знает полей прикладной сущности и не должен.

**Один `$filter` на экран.** На стенде лейн статусов фильтрует отдельно от панели — два механизма пишут в разные места, и пользователь не видит целиком, что применено. В ките лейн и панель — два интерфейса к одному стору условий: лейн ставит условие по полю статуса, панель показывает его чипом наравне с остальными.

**Применённые условия — чипы** с полем, оператором и значением, снимаются по одному, «Сбросить» снимает все.

### 7.2. Уходит в отдельную проработку

- Вид и поведение advanced на 200+ реквизитах: каталог с группами и поиском, закрепление полей на экране (`PUT /grids/{gridId}/filter-layout`), модификатор оператора у поля, наборы фильтров (CRUD на беке).
- Граница simple/advanced: переключатель, автоматика по числу полей или одна растущая панель.
- Справочники с поиском и пагинацией (`GET /dictionaries/{id}`), диапазоны дат с пресетами.
- Группы условий и OR — в контракте v1 только AND, вид не должен закрыть дорогу.

Срез 1 поставляет модель, режим simple и лейн. Перед реализацией advanced — отдельный дизайн-заход с вариантами.

## 8. Модели effector

### 8.1. Фабрики, не синглтоны

На странице может быть два грида. Каждая фабрика создаёт сторы внутри себя — модели fork-безопасны, тестируются без DOM.

### 8.2. Транспорт вне кита

```ts
type GridQuery = { filter: Filter; sort: Sort; page: number; size: number }   // page — с нуля
type GridPage<Row> = { rows: Row[]; total: number }
type PersistAdapter<T> = { load: (key: string) => T | undefined; save: (key: string, value: T) => void }

const grid = createGridModel<Doc>({
  id: 'currency-docs',                      // ключ persist
  columns: layout.columns.map((c) => ({ id: c.id, width: c.width })),
  rowKey: layout.rowKey,
  pageSize: 20,                             // по умолчанию 20
  $filter,                                  // общий стор условий (панель + лейн)
  fetchFx,                                  // Effect<GridQuery, GridPage<Doc>> — даёт приложение
  persist: localStoragePersist(),           // не задан — вид не сохраняется
})
```

Модели нужны только id и начальные ширины колонок и `rowKey`, а не `RecordLayout`: раскладка с `render` — это JSX экрана, модель без DOM её не знает; `layout` экран передаёт в `DataGrid` сам.

Сторы: `$rows $total $page $pageSize $sort $widths $order $hidden $selection $state $error $query`.
События: `sortBy resize setColumns toggleColumn moveColumn setPage setPageSize select selectPage selectAll clearSelection retry refresh`. Публичные события обеих моделей (и фильтров, 8.3) типизированы `EventCallable<T>`: в effector 23 `Event<T>` снаружи не вызывается. Модель отдаёт и `fetchFx` приложения, и `rowKey`.

Правила связывания внутри модели: смена `$filter` → страница 1, выделение сброшено, запрос; смена сортировки или размера страницы → страница 1, запрос; смена страницы → запрос; `refresh`/`retry` → запрос с текущим `$query`; ресайз и состав колонок → без запроса, только `persist`. `GridQuery.page` — с нуля, как у бека (контракт фильтров §2), `$page` — с единицы, как в интерфейсе; перевод делает `$query`.

**Первый запрос делает приложение** — вызовом `refresh()` при монтировании экрана. Модель при создании в бек не ходит: её можно создать заранее, на уровне модуля. До первого ответа `$state = loading`.

**Приём ответа.** Модель вызывает не `fetchFx`, а свою копию `requestFx = attach({ effect: fetchFx })`: `fetchFx` приложения может обслуживать несколько гридов, а `pending`/`done`/`fail` копии относятся только к вызовам этой модели. Ответ принимается, только если его `params` совпадает с текущим `$query` (сравнение по значению): поздний ответ на прежнюю страницу или фильтр не перезапишет актуальный, отказ устаревшего запроса не выставит ошибку. `$state` считается из `requestFx.pending` и наличия данных: первая загрузка — `loading`, повторная — `refreshing`, отказ текущего запроса — `error`. Отмены запросов нет: пока устаревший запрос в полёте, `$state` остаётся `refreshing`, данные при этом верные.

**persist** — адаптер `PersistAdapter<T>`; `load` синхронный — настройки нужны при создании сторов. Кит даёт `localStoragePersist(prefix = 'katran')` (ключ `prefix:id`, приватный режим — молча) и `memoryPersist()` (тесты, SSR). Серверный адаптер (персональные настройки пользователя) пишет приложение и загружает настройки до создания модели. Сохраняется `GridPersisted = { widths, order, hidden, pageSize }` — при `resize`, `setColumns`, `toggleColumn`, `moveColumn`, `setPageSize`. Сохранённое сверяется с колонками: чужие id выбрасываются, новые дописываются в конец порядка. Выбора полей (`keep`) нет и пока не нужно: все четыре поля — настройки вида, а сортировка, страница и фильтр — часть запроса и не сохраняются. Понадобится экран, которому что-то из четырёх хранить нельзя, — `keep` добавляется без поломки API.

### 8.3. Фильтры

`createFiltersModel({ meta, initial })` → `$conditions` (применённые), `$draft` (черновик панели до «Применить»), `$dirty` (черновик отличается от применённых). События: `edit(condition)` — условие поля в черновик; `discard(field)` — убрать условие поля из черновика; `apply` — черновик → применённые; `remove(field)` — снять чип: условие уходит из применённых и из черновика, неприменённые правки других полей остаются; `reset` — очистить всё в `[]`, а не откатить к `initial`. Эффекты наборов подставляет приложение (не в срезе 1). `$conditions` и есть `$filter` для грида.

### 8.4. Хуки

`useGrid(model)`, `useFilters(model)` в `@katran/effector` — через `useUnit`, возвращают props для соответствующих компонентов. Единственное место, где модель и компонент встречаются. `useGrid` → `GridBinding<Row>`: данные `rows total page pageSize sort widths order hidden selection state error` и колбэки `onPage onPageSize onSort onResize onColumns onSelect onSelectPage onRetry`; то, что это подмножество `DataGridProps`, проверяется при компиляции.

## 9. Качество

- **Тесты**: vitest + Testing Library для `ui`; модели — без DOM. Обязательно для грида: `resolveSpans`, сортировка с `order` и `then`, сброс страницы и выделения по правилам 8.2, трёхпозиционный чекбокс, клавиатурная навигация, ARIA-счёт строк (6.3), минимум показа скелетона (фейковые таймеры), приём только ответа на текущий запрос.
- **Сверка с эталоном**: Playwright-замеры пяти опорных величин на демо — высота записи, скелетона записи, шапки грида, строки SWIFT-поля, drawer в покое. Ожидаемые значения снимаются с замороженного стенда. Срез 1 замеряет запись, скелетон и шапку плюс масштаб при плотности 125 % (`apps/demo/e2e/geometry.spec.ts`, вне `pnpm check`), строку SWIFT-поля и drawer — срез 2. Замер идёт против production-сборки демо: dev-сервер скрывает дефекты сборки вроде потери `tokens.css` (3.4). Коридоры: запись 60–74, шапка 40–56, скелетон = запись ± 2, 125 % = ×1.25 ± 2. Замер 2026-09-24: запись 72, шапка 49, скелетон 72, 125 % → 89.75. Эталон записи — открытый вопрос (6.1, 12).
- **Доступность**: axe в тестах каждого интерактивного компонента; `jsx-a11y` в линте; правило «интерактив = кнопка с именем».
- **Палитра**: скрипт контраста в CI поверх `tokens.src.ts`. Пороги по замеру 2026-09-23: `ink`, `ink2` ≥ 4.5 на всех поверхностях; `muted`, `val`, семантические ≥ 4.5 на `paper`; `muted` ≥ 4.0 на подложках; `ok`/`warn` на своих `-soft` ≥ 4.0 (кратковременная подсветка: 4.17/4.26), остальные семантические на своих `-soft` ≥ 4.5; `paper` на статусных тонах `flow/flowd/bad/badd/warn/ok` ≥ 4.5 (буква в точке; на `flowl/okl/grey` буква не применяется — 3.0–3.2); `faint` ≥ 3.0 — служебный токен (3.75 на белом), для читаемого текста не применяется. Правило добавляется тогда же, когда в CSS появляется пара «цвет на цвете». Изменение порога — осознанное решение, не тихая правка.
- **Токены**: CI проверяет, что `tokens.css` и `index.ts` соответствуют источнику.

## 13. Словарь

- **Запись** — единица грида, `<tbody>` из одной строки колонок и сквозных строк.
- **Сквозной сегмент (span)** — ячейка второй и следующих строк записи, накрывающая диапазон колонок.
- **Составная колонка** — колонка с несколькими ключами сортировки; выбор ключа — через меню.
- **Плотность** — множитель размеров `--k-density` вместо CSS `zoom`.
- **Эталон** — замороженный `pi-constructor`, источник правды по поведению и геометрии.
