# Дизайн-система katran — спецификация

Дата: 2026-09-23 · Статус: согласована по секциям, на финальном ревью · Владелец: Иван Клименко

Katran — самостоятельная дизайн-система для интерфейсов проекта на React + effector. Источник — макеты реестра и деталки валютных платёжных инструкций (`pi-constructor`), прошедшие дизайн-ревью в сентябре 2026. Кит строится вертикальными срезами: первым переносится реестр целиком, компоненты добываются из реального экрана, а не проектируются впрок.

---

## 1. Назначение и границы

### 1.1. Что обслуживает

- **Реестры** — валютные и рублёвые ПИ, справочники, журналы: грид + фильтры + деталка.
- **Формы ввода и правки** — создание и редактирование документа, валидация, подтверждения.
- **Дашборды и мониторинг** — динамика статусов, плитки показателей.

### 1.2. Не делаем

| Что | Почему |
|---|---|
| Admiral — ни как зависимость, ни как обёртка | Решение владельца: кит самостоятелен. Снимает styled-components и привязку к версиям чужого кита |
| Админка, навигация, деревья, сложные селекты | Не в перечне обслуживаемых экранов |
| Виртуализация списка | Пагинация 20 записей на страницу; виртуализация не даёт ничего, кроме сложности |
| i18n | Интерфейс русский |
| Темизация под несколько брендов | Две темы: светлая и тёмная |
| Мульти-сортировка | Вторичный ключ задаётся декларативно через `then`, этого хватает |
| Перетаскивание колонок мышью | Состав и порядок — через меню; DnD конфликтует с ресайзом на той же границе и требует клавиатурного эквивалента |

### 1.3. Отложено с памятью о причине

- **Свой календарь с производственным календарём** — решено «не сейчас»; `DateInput` оставляет место под замену нативного пикера.
- **Advanced-режим фильтров** — требует отдельной проработки (раздел 7). Вендоренная панель `ermo-snapshot` на стенде — функциональный макет, не образец.
- **Канал поставки в целевой проект** — организационно сложен, возможно ручное копирование. Не фиксируем; проектируем переносимость (раздел 3.4).

## 2. Принципы

1. **Компонент рождается из экрана.** Срез 1 — реестр, срез 2 — деталка, срез 3 — дашборд. Ничего впрок.
2. **UI чистый, состояние в моделях, транспорт в приложении.** `@katran/ui` не знает об effector, `@katran/effector` не знает о DOM и HTTP.
3. **Токены — единственный источник цветов и размеров.** Голые `px` и `hex` в компонентном CSS запрещены и ловятся линтером.
4. **Интерактив — настоящая кнопка с именем.** Клавиатура и скринридер — не опция: в банковской ИС «деталку нельзя открыть с клавиатуры» — блокирующий дефект.
5. **Переносимость.** Исходники должны переживать ручное копирование в другой проект.
6. **Эталон поведения — замороженный `pi-constructor`.** Геометрия и поведение сверяются с ним; новые правки идут только в katran.

## 3. Репозиторий и пакеты

### 3.1. Структура

```
katran/
  packages/
    tokens/     источник токенов → tokens.css + index.ts
    ui/         React-компоненты; deps: tokens, @floating-ui/dom
    effector/   фабрики моделей и хуки; deps: effector, effector-react
  apps/
    demo/       витрина и боевые экраны → GitHub Pages
  docs/
    superpowers/specs/, superpowers/plans/
```

Инструменты: pnpm workspaces · TypeScript strict · Vite (library mode для пакетов, app для демо) · vitest + Testing Library · eslint (`import/no-restricted-paths`, `jsx-a11y`) · stylelint · Playwright для замеров геометрии.

### 3.2. Правило зависимостей — проверяется, не декларируется

| Пакет | Может импортировать | Запрещено |
|---|---|---|
| `tokens` | ничего | — |
| `ui` | `tokens`, `react`, `@floating-ui/dom` | `effector`, всё из `packages/effector` |
| `effector` | `effector`, `effector-react`, типы из `ui` (только `import type`) | DOM API, компоненты `ui` |
| `demo` | всё | — |

Нарушение ловит `eslint-plugin-import/no-restricted-paths` и сборка падает. Без этого граница между слоями исчезнет на третьей «срочной» правке.

`@floating-ui/dom` — единственная рантайм-зависимость `ui` помимо React: позиционирование тултипа, меню и поповера. Своя реализация была бы хуже и больше.

### 3.3. Компонент

Папка из четырёх файлов: `Thing.tsx`, `Thing.module.css`, `Thing.test.tsx`, `index.ts`. Стили — CSS Modules без рантайма, имена детерминированные: `k-Thing__part`. Изоляция от хозяина — префиксом `k-`; имена читаемы в devtools и переопределяемы в аварийной ситуации, чего не даёт хеш.

### 3.4. Переносимость

- Пакеты ссылаются друг на друга только по имени (`@katran/tokens`), никаких путей и alias'ов монорепо внутри `src`.
- Peer-зависимости: `react ≥ 18`, `react-dom ≥ 18`, `effector ≥ 23`, `effector-react ≥ 23`. Рантайм-зависимостей сверх `@floating-ui/dom` нет.
- Шрифты IBM Plex Sans / Mono лежат в `tokens` и подключаются `@font-face` — не с Google Fonts: в банковской сети внешних ресурсов нет.
- Каждый пакет собирается в `dist/` (ESM + `.d.ts` + CSS), но и исходники пригодны к прямому подключению. В монорепо потребители работают исходниками (`exports` → `src`); для внешних потребителей `publishConfig.exports` указывает на `dist`. `@floating-ui/dom` не вшивается в сборку.
- **Встраивание через федерацию.** Приложение живёт внутри метаприложения (module federation), поэтому кит не трогает `<html>`, `<body>` и глобальные стили: тема, плотность, портал наложений — всё на корне `KatranProvider`. Близкие по смыслу справочники объединяются в один блок табами ради экономии на точках встраивания.

## 4. Токены

### 4.1. Один источник

`packages/tokens/src/tokens.src.ts` — единственное место правки. Скрипт генерирует `tokens.css` (переменные для двух тем) и `index.ts` (константы для JS — нужны графику). CI проверяет, что сгенерированные файлы совпадают с источником. Два списка руками уже расходились на стенде.

### 4.2. Цвет

Палитра переносится из эталона без изменений — она прошла ревью: `--k-val` = XP-синий `#3A6EA5` (цвет значений, требование владельца), `--k-faint` — служебный токен с контрастом 3.75:1 на белом (не для читаемого текста), статусы сведены с девяти оттенков к четырём семействам.

| Группа | Токены (светлая тема) |
|---|---|
| Поверхности | `ground #EEF1F6` · `paper #FFFFFF` · `sunk #F5F7FB` · `hover #F2F6FA` · `chip #EEF0F4` |
| Текст | `ink #141A29` · `ink2 #3A4357` · `muted #6B7488` · `faint #7C8496` |
| Линии | `line #DCE1EA` · `line2 #EAEEF4` |
| Акцент | `val #3A6EA5` · `val-soft #E9EFF7` |
| Семантика | `ok #17844B` / `ok-soft #E3F5EA` · `bad #C2372E` / `bad-soft #FCE6E4` · `warn #A8620B` / `warn-soft #FDF1DD` / `warn-row #FFF9EE` · `opt #B0247A` / `opt-soft #FBE8F3` · `fold #D0342C` |
| Статусы | в движении: `st-flow #3A6EA5` · `st-flowl #6B98C6` · `st-flowd #2B5384` — внимание: `st-bad #C2372E` · `st-badd #8C2B23` · `st-warn #A8620B` — успех: `st-ok #17844B` · `st-okl #4E9E77` — нейтрально: `st-grey #8A93A6` |

Тёмная тема — свой набор значений тех же имён (перенос из эталона). Роли: значения параметров — `val`, названия полей — `ink2`, теги SWIFT-полей — `opt`, служебные токены вроде `S:`/`R:` — `faint`.

Переключение: атрибут `data-theme="light|dark"` на корне провайдера; без атрибута — `prefers-color-scheme`. Светлая палитра объявляется под `:root, [data-theme="light"]`, тёмная — под `[data-theme="dark"]` и в медиа-запросе `:root:not([data-theme="light"])`: иначе `data-theme="light"` внутри тёмного предка (или при системной тёмной теме) не действует — найдено финальным ревью 2026-09-23.

### 4.3. Плотность вместо zoom

На стенде масштаб 100/110/125 % сделан через CSS `zoom` на `<html>`. Он ломает `getBoundingClientRect` — каждому компоненту, считающему координаты, приходится делить на коэффициент. В ките:

- `--k-density` ∈ {1, 1.1, 1.25}, выставляется провайдером inline на своём корне; корень несёт атрибут `data-k-root`;
- **все размерные токены уже умножены**: `--k-fs-1: calc(12.5px * var(--k-density))`, `--k-sp-2: calc(8px * var(--k-density))`, `--k-h-ctl-m: calc(28px * var(--k-density))`;
- **размерные токены объявляются под селектором `:root, [data-k-root]`**, а не только в `:root`. Причина — правило CSS: `var()` внутри значения custom property резолвится на элементе, где свойство объявлено, и наследуется уже вычисленным; объяви размеры только в `:root` — и переопределение `--k-density` на корне провайдера ни на что не повлияет (найдено браузерной проверкой демо 2026-09-23). Побочный выигрыш: вложенный провайдер с другой плотностью работает. **Общее правило:** любая группа токенов, которую провайдер переопределяет на своём корне (плотность, тема), объявляется под `:root, [селектор корня]`, а не только в `:root`;
- компонентный CSS использует только токены; `stylelint` запрещает голые `px`.

`<html>` не трогаем — чужой CSS в `rem` не страдает; координаты честные. Базовые размеры рассчитаны на 1080p @ 100 % ≈ 2K @ 125 %. По умолчанию плотность 1.25 при ширине экрана ≥ 2200.

### 4.4. Остальные группы

- **Типографика**: `sans` IBM Plex Sans, `mono` IBM Plex Mono; три кегля `fs-1/2/3` = 12.5 / 11 / 10.5; веса 400/500/600/700; заголовок экрана 20.
- **Ритм**: шаг 4; отступы `sp-1..8`; высоты контролов `h-ctl-s/m/l` = 24 / 28 / 32; строка SWIFT-поля 23; радиусы `r-s/m` = 4 / 6.
- **Тень**: `shadow` для наложений.
- **Слои**: `z-sticky 10` · `z-drawer 100` · `z-menu 200` · `z-tooltip 300`. Промт рендерится внутри контекста своего drawer — окно принадлежит документу, а не странице.
- **Длительности**: `t-fast 120ms` · `t-base 200ms`; порог показа скелетона 200 мс, минимум показа 400 мс.

`Chart` (единый многорядный линейный график: шкала по видимым рядам, легенда-переключатель, Shift — оставить один ряд, диапазоны сегодня / 3 дня / 7 дней, прореживание до 600 точек, подписи концов линий при ≤ 4 рядах), `StatTile`, `PanelLayout`. Модель: `createChartModel`. Цвета рядов = статусные токены; девять линий в одних осях цветом не разводятся, идентичность держат легенда и подписи.

## 6. DataGrid

### 6.1. Модель записи

Запись — не строка, а **`<tbody>` из нескольких `<tr>`**. Первая строка — ячейки колонок, следующие — сквозные сегменты (причина статуса под статусом и ID, назначение платежа сквозь 50–59). Граница `--k-line` проходит по записи; внутри записи линий нет. Запись ≤ 3 строк контента (≈ 65 px при плотности 1).

### 6.2. Контракт

```ts
type ColumnDef<Row> = {
  id: string
  title?: string            // пустой допустим — у колонки статуса заголовка нет
  menuTitle?: string        // имя в меню сортировки и состава, если title пуст
  subtitle?: string
  width?: number            // начальная ширина в px при плотности 1
  minWidth?: number         // по умолчанию 36
  resizable?: boolean       // по умолчанию true
  lines?: 1 | 2 | 3         // строк контента; по умолчанию 1. Задаёт скелетон и кламп
  align?: 'left' | 'right'  // right — для сумм
  sort?: SortKey[]          // пусто → не сортируется
  render: (row: Row) => ReactNode
}

type SortKey = {
  id: string
  label: string             // подписывается в шапке, когда ключ выбран
  type?: 'text' | 'number' | 'date'
  then?: string             // второй ключ, в том же направлении
  order?: string[]          // фиксированный порядок значений: ['IN','OUT','TRANSIT','OTHER']
}

type SpanDef<Row> = {
  id: string
  from: string              // id колонки начала
  to: string                // id колонки конца, включительно
  lines?: 1 | 2
  render: (row: Row) => ReactNode | null   // null → бледная подложка, не закрашивается
}

type RecordLayout<Row> = {
  columns: ColumnDef<Row>[]
  spans?: SpanDef<Row>[][]  // дополнительные строки записи; в каждой — сегменты слева направо
  rowKey: (row: Row) => string
}
```

### 6.3. Правила

**Сквозные сегменты** адресуются по `id` колонок, не числом `colspan`. Ширина считается от текущего видимого состава: часть колонок диапазона скрыта — сегмент сжимается; все скрыты — не рисуется. При пользовательском порядке сегмент накрывает всё, что стоит между `from` и `to`, границы нормализуются. Реализация — чистая функция `resolveSpans(spans, visibleOrder) → { colStart, colSpan }[]`, тестируется без DOM.

**Сортировка.** Одна активная: `{ key, dir }`. Простая колонка (один ключ) — клик по заголовку переключает направление. Составная — клик открывает меню реквизитов, выбранный ключ подписывается в шапке вместо `subtitle`, есть «Сбросить сортировку». Направление по умолчанию: `date` и `number` — по убыванию, `text` — по возрастанию. `order` задаёт фиксированный порядок значений, `then` — вторичный ключ в том же направлении. Разрешение ничьих стабильное. В серверном режиме грид не сортирует сам — модель отправляет `sort` в запрос.

**Ресайз.** Ручка на правой границе `<th>`, `min 36`; ширина таблицы = сумма ширин, таблица прижата влево. С клавиатуры: ручка — `role="separator"`, стрелки ← → шаг 8, Shift — 32.

**Состав колонок.** Меню: поиск по названию, галочки показать/скрыть, перенос вверх/вниз. Порядок и видимость хранятся в модели и сохраняются через `persist`.

**Пагинация.** Порядковый номер записи на странице, размер страницы 20 (настраивается), переключатель страниц внизу. Смена фильтра или сортировки — на первую страницу.

**Состояния.** `loading` — скелетон той же геометрии (по `lines` колонок и сегментов), порог показа 200 мс, минимум 400 мс. `refreshing` — полоса прогресса и приглушение (`dim`) показанных данных. `empty` — сообщение и действие «Сбросить фильтр». `error` — сообщение и «Повторить».

**Выделение и массовые действия.** Чекбокс в первой колонке и в шапке (трёхпозиционный). Состояние:

```ts
type Selection = { mode: 'ids'; ids: Set<string> } | { mode: 'all'; except: Set<string> }
```

`mode: 'all'` — «всё по текущему фильтру» (серверный режим, не список id). `BulkBar` показывает «Выбрано N» или «Все N по фильтру», действия получают `{ filter, selection }`. Выделение обеих строк записи подсвечивается вместе. Смена фильтра сбрасывает выделение; смена сортировки и страницы — нет.

**Открытие деталки.** Запись **не кликабельна** (правило владельца). Открывает только кнопка в первой ячейке — настоящая `<button>` с именем. Грид отдаёт `onOpen(row, { secondary })`; `secondary` — двойной клик, приложение решает, что это второй drawer.

**Клавиатура.** Паттерн WAI-ARIA `grid`: один таб-стоп на весь грид, дальше стрелки по ячейкам (roving tabindex). Вторая строка записи — обычная строка сетки, стрелка вниз на неё заходит: там настоящие данные. `Enter` на значении — копировать; на кнопке — открыть; на заголовке — сортировка/меню. `Home`/`End` — начало/конец строки.

### 6.4. Компонент

```tsx
<DataGrid
  layout={layout}
  rows={rows} total={total}
  page={page} pageSize={20} onPage={...}
  sort={sort} onSort={...}
  widths={widths} onResize={...}
  order={order} hidden={hidden} onColumns={...}
  selection={selection} onSelection={...}
  state="ready" | "loading" | "refreshing" | "error"
  emptyAction={{ label: 'Сбросить фильтр', onClick }}
  onOpen={(row, { secondary }) => ...}
/>
```

Чистый компонент: все данные — из props, все изменения — наружу. В приложении с effector: `const props = useGrid(model); <DataGrid {...props} />`.

## 7. Фильтры — рамка

Раздел фиксирует то, что нельзя отложить. Вид и поведение advanced-режима — предмет отдельной проработки до его реализации.

### 7.1. Решено сейчас

**Одна модель, два режима.** `simple` (справочник на 5–10 реквизитов: поля прямо на панели, оператор по умолчанию от типа — текст `CONTAINS`, число и дата `EQ`) и `advanced` (сущность на 200+ реквизитов) — режимы одной `createFiltersModel`, а не два компонента. Состояние одно:

```ts
type Condition =
  | { field: string; op: 'EQ'|'NE'|'CONTAINS'|'STARTS_WITH'|'ENDS_WITH'|'GT'|'GTE'|'LT'|'LTE'; value: Scalar }
  | { field: string; op: 'IN'|'NOT_IN'; values: Scalar[] }
  | { field: string; op: 'BETWEEN'; from: Scalar; to: Scalar }
  | { field: string; op: 'IS_EMPTY'|'IS_NOT_EMPTY' }
type Filter = Condition[]   // v1: только AND
```

Словарь операторов и семантика — из `vtb-filters/docs/filter-contract.md` (13 операторов, типы полей, регистр, `NULL`).

**Каталог полей — от бека.** `GET /grids/{gridId}/filter-meta` отдаёт поля, группы, допустимые операторы и встроенные справочники. Кит не знает полей прикладной сущности и не должен.

**Один `$filter` на экран.** На стенде лейн статусов фильтрует отдельно от панели — два механизма пишут в разные места, и пользователь не видит целиком, что применено. В ките лейн и панель — два интерфейса к одному стору условий: лейн ставит условие по полю статуса, панель показывает его чипом наравне с остальными.

**Применённые условия — чипы** с полем, оператором и значением, снимаются по одному, «Сбросить» снимает все.

### 7.2. Уходит в отдельную проработку

- Вид и поведение advanced на 200+ реквизитах: каталог с группами и поиском, закрепление полей на экране (`PUT /grids/{gridId}/filter-layout`), модификатор оператора у поля, наборы фильтров (CRUD на беке).
- Граница simple/advanced: переключатель, автоматика по числу полей или одна растущая панель.
- Справочники с поиском и пагинацией (`GET /dictionaries/{id}`), диапазоны дат с пресетами.
- Группы условий и OR — в контракте v1 только AND, вид не должен закрыть дорогу.

Срез 1 поставляет модель, режим simple и лейн. Перед реализацией advanced — отдельный дизайн-заход с вариантами.

## 8. Модели effector

### 8.1. Фабрики, не синглтоны

На странице может быть два грида. Каждая фабрика создаёт сторы внутри себя — модели fork-безопасны, тестируются без DOM.

### 8.2. Транспорт вне кита

```ts
type GridQuery = { filter: Filter; sort: { key: string; dir: 'asc'|'desc' } | null; page: number; size: number }
type GridPage<Row> = { rows: Row[]; total: number }

const grid = createGridModel<Doc>({
  id: 'currency-docs',
  layout,
  pageSize: 20,
  $filter,                                  // общий стор условий (панель + лейн)
  fetchFx,                                  // Effect<GridQuery, GridPage<Doc>> — даёт приложение
  persist: { key: 'currency-docs', keep: ['widths', 'order', 'hidden', 'pageSize'] },
})
```

Сторы: `$rows $total $page $sort $widths $order $hidden $selection $state $error`.
События: `sortBy resize toggleColumn moveColumn setPage select selectAll clearSelection retry`.

Правила связывания внутри модели: смена `$filter` → страница 1, выделение сброшено, запрос; смена сортировки → страница 1, запрос; смена страницы → запрос; ресайз и состав колонок → без запроса, только `persist`. `$state` считается из `fetchFx.pending` и наличия данных: первая загрузка — `loading`, повторная — `refreshing`.

`persist` — адаптер `{ load(key), save(key, value) }`; по умолчанию `localStorage`, приложение может подставить серверный (персональные настройки пользователя).

### 8.3. Фильтры

`createFiltersModel({ meta })` → `$conditions` (применённые), `$draft`, события `edit apply reset remove`, эффекты наборов подставляет приложение. `$conditions` и есть `$filter` для грида.

### 8.4. Хуки

`useGrid(model)`, `useFilters(model)` в `@katran/effector` — через `useUnit`, возвращают props для соответствующих компонентов. Единственное место, где модель и компонент встречаются.

## 9. Качество

- **Тесты**: vitest + Testing Library для `ui`; модели — без DOM. Обязательно для грида: `resolveSpans`, сортировка с `order` и `then`, сброс страницы и выделения по правилам 8.2, трёхпозиционный чекбокс, клавиатурная навигация.
- **Сверка с эталоном**: Playwright-замеры пяти опорных величин на демо — высота записи, скелетона записи, шапки грида, строки SWIFT-поля, drawer в покое. Ожидаемые значения снимаются с замороженного стенда.
- **Доступность**: axe в тестах каждого интерактивного компонента; `jsx-a11y` в линте; правило «интерактив = кнопка с именем».
- **Палитра**: скрипт контраста в CI поверх `tokens.src.ts`. Пороги по замеру 2026-09-23: `ink`, `ink2` ≥ 4.5 на всех поверхностях; `muted`, `val`, семантические ≥ 4.5 на `paper`; `muted` ≥ 4.0 на подложках; `ok`/`warn` на своих `-soft` ≥ 4.0 (кратковременная подсветка: 4.17/4.26), остальные семантические на своих `-soft` ≥ 4.5; `paper` на статусных тонах `flow/flowd/bad/badd/warn/ok` ≥ 4.5 (буква в точке; на `flowl/okl/grey` буква не применяется — 3.0–3.2); `faint` ≥ 3.0 — служебный токен (3.75 на белом), для читаемого текста не применяется. Правило добавляется тогда же, когда в CSS появляется пара «цвет на цвете». Изменение порога — осознанное решение, не тихая правка.
- **Токены**: CI проверяет, что `tokens.css` и `index.ts` соответствуют источнику.

## 13. Словарь

- **Запись** — единица грида, `<tbody>` из одной строки колонок и сквозных строк.
- **Сквозной сегмент (span)** — ячейка второй и следующих строк записи, накрывающая диапазон колонок.
- **Составная колонка** — колонка с несколькими ключами сортировки; выбор ключа — через меню.
- **Плотность** — множитель размеров `--k-density` вместо CSS `zoom`.
- **Эталон** — замороженный `pi-constructor`, источник правды по поведению и геометрии.
