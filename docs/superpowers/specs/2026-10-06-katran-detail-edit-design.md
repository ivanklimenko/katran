## 1. Зачем и что в срезе

После 2b деталка показывает документ целиком, но ничего не меняет. На эталоне валютная деталка правит часть реквизитов: поля SWIFT, 20 исх, счета Дт/Кт, дату валютирования, с маркерами «изменено», аудитом поля и подтверждением. Срез 2c переносит это в кит и `apps/pi`. Поведение каждого куска выражается моделью effector (STATE §10: «нет модели — поведение не перенесено»).

### 1.1. Входит в 2c

| Что правится | Где | Как на эталоне | Сохранение |
|---|---|---|---|
| Поля 50, 52, 56, 57, 59 (стороны и банки) | «Общие», сетка SWIFT; у MT202COV и B.* | карандаш → редактор «Как есть \| Редактирование» на всю ширину под строкой; опция буквой, счёт (у сторон), N строк по W | правка с аудитом |

Набор правимых полей по профилям — как на эталоне: MT103 — 50, 52, 56 (если заполнено), 57, 59, 70, 72; MT202 — 52, 56, 57, 72; MT202COV — как MT202 плюс B.50, B.52, B.56, B.57, B.59, B.70, B.72; MT199 — полей нет (79 только просмотр), 20 исх и счета — да, даты валютирования нет. **Рубль в 2c только на просмотр** — на эталоне у рублёвой деталки карандашей нет; механизм в ките общий.

Кроме правки: блок аудита поля (сводка «N изменений», люди, бейдж «ожидает утверждения» / «утверждено», кнопка «История», таймлайн с диффом строк); `Prompt` в ките; после успешного сохранения — новая деталь в кэше, сброс кэша вкладок документа, перезапрос реестра.

### 1.2. Не входит в 2c

- **Утверждение чужой правки** («вторая рука», автор ≠ утверждающий) — кнопка «Утвердить» и её эндпоинт: 2d (решение владельца 06.10). В 2c аудит показывает статусы, которые прислал бек; предложение эндпоинта утверждения — в документ контракта как задел.
- Действия лейна и вкладок (Обновить F5, Редактировать E, Печать, Аннулировать и т. д.), «Курс», «Проверить баланс», горячие клавиши — 2d. «Редактировать» в лейне на эталоне без обработчика — остаётся заглушкой.
- Правка рублёвых документов, правка поля 79, свёрнутая форма транзакции (основная спека §12).
- Пометка изменённой записи в реестре (на эталоне нет).

## 3. `apps/pi`

### 3.1. Контракт (предложение в `vtb-filters`)

- **Сохранение правки:** `POST /grids/{gridId}/documents/{id}/edits` с телом `{ target, was, now }`, где `target` — `field:<tag>` (с `B.` у seqB), `refOut`, `accDt`, `accKt`, `valueDate`; ответ — **обновлённая деталь целиком** (тот же разбор, что `detailFx`). Ошибки: `400 VALIDATION` (бек повторяет правила; фронт показывает `problem.errors[0].message` дословно), `409 CONFLICT` (`was` не совпал — документ изменили; Problem `type` `urn:katran:edit-conflict`, `title` «Документ изменили»), `403`. ↺ — обычная правка «стало = исходное»: правилами домена не проверяется (исходное могло быть пустым или вне правил), §9 п. 9.
- **Аудит в детали:** поле детали `edits: Record<target, { now, hist: HistEntry[] }>`; `HistEntry = { who, when, was, now, note?, status: 'pending' | 'confirmed', by?, at? }`. Бек ставит `status/by/at`; автоматическое подтверждение даты валютирования автором — тоже бек (`confirmed`, `by = who`).
- **Пересчёт маршрута:** после `accKt` бек возвращает деталь с новым маршрутом и `edits.route = { hist: [{ who: 'система', ... }] }` (запись `confirmed`, `by: 'система'`).
- **Счета для подсказки:** `GET /grids/{gridId}/documents/{id}/accounts?side=kt|dt` (параметр `side` обязателен) → `{ items: { account, ccy, kind }[] }` (Кт — карточка клиента по валюте документа, 10–15 шт.; Дт — счета банка); фронт фильтрует сам, показывает до 5.
- **Утверждение (задел 2d):** `POST …/edits/{target}/confirm` — только в документе, без кода.

Всё — в `pi-api.md` новыми разделами (§1.7–1.8, §7.x) с примерами из фейка.

## 4. Поведение

- **Заблокированный документ** (у строки реестра `lock` — запись с замком, при открытии «Открыт документ … (только просмотр)») — только просмотр: без карандашей, редакторов и ↺; маркеры «изменено» и аудит видны; бек правку такого документа отклоняет (`400`); документ, пришедший заблокированным при открытом редакторе (перезапрос по 409), редактор закрывает (решение контроллера при исполнении, сделано в финальной волне — `detail-drift.md` Д66).
- Карандаш виден у правимых полей при наведении на строку и в фокусе с клавиатуры (`:focus-visible`); имя «Редактировать поле {tag}» / «Изменить 20 исх» / «Изменить счёт Дт|Кт» / «Изменить дату валютирования».
- Редактор открывается с **текущим** значением (последняя правка или исходное), «Как есть» — исходное с бека. Фокус — в первое поле ввода. Один редактор на деталь; открытие второго при грязном первом — `Prompt` «Отменить правку?».
- Валидация на лету, «Сохранить» недоступна при ошибке, показывается первая ошибка; тексты ошибок — дословно эталона (§ таблица исследования: строка k, символы, счёт до 34, всего N·W; 20 исх — референс; счета — «не из карточки клиента / не из списка счетов банка»).
- Сохранение: строки обрезаются, переводятся в верхний регистр, хвостовые пустые убираются; если «стало = текущее» — редактор закрывается без запроса; если «стало = исходное» — это правка-откат (в2), запрос уходит.
- Во время сохранения кнопки недоступны, ввод сохраняется; ошибка — строкой в редакторе, «Повторить» = «Сохранить»; 409 — текст «Документ изменили — откройте заново» и перезапрос детали.
- После сохранения: деталь из ответа, вкладки документа сбрасываются, реестр перезапрашивается, объявление «Изменения сохранены» в живую область. Отказ, которому негде показаться строкой (↺ или редактор уже закрыт уходом), — объявление «Изменения не сохранены: {текст отказа}».
- Esc в редакторе = «Отмена»: явная отмена, черновик сбрасывается без `Prompt` (вопрос в3 — только про уход из деталки, не про явную отмену; §8 п. 1). Esc в `Prompt` = отказ. Esc вне редактора — закрывает деталку, как в 2a (с проверкой `requestLeave`).
- ↺ у 20 исх, счетов и маршрута — правка «стало = исходное» с аудитом. ↺ у Кт возвращает и маршрут (бек пересчитывает); ↺ маршрута отдельно нет (на эталоне был — несогласован, класс C).
- Дата валютирования: выбор даты → `Prompt` «Утвердить новую дату валютирования?», note «было → стало», «Утвердить» / «Отмена»; отказ — остаёмся в правке с выбранной датой (как на эталоне); `min` — дата создания.

## 9. Уточнения при исполнении

Решения, принятые при исполнении плана (леджер `.superpowers/sdd/2026-10-06-katran-detail-edit/progress.md`, строки `Ruling:`; решения плана Р1–Р16 приняты как написаны). Владелец может переиграть любое; цена — в скобках.

1. **`Prompt` в drawer — слой `Drawer.overlay`** (Р1): корень `Drawer` больше не прокручивается, прокрутка — во внутреннем `[data-part="scroll"]`, `overlay` рисуется поверх панели и не уезжает с содержимым. Подложка — токен `scrim` восьмизначным hex (Р16). Тексты «Отменить правку?» (Р4): note «Несохранённые изменения будут потеряны.», «Отменить правку» / «Продолжить правку», тон `danger`, фокус на «Продолжить правку».
2. **API `createEditModel` шире §2.2** (Р3): `submit` (↺), `$dirty`, `failed`, `$editing.initial`, `leave`; ответ своего визита даёт `saved` для любого ключа, редактор меняется только для того же ключа; уход во время сохранения — без `Prompt`. Отмена игнорируется, только пока летит запрос ключа открытого редактора; `open`/`save` при открытом `Prompt` игнорируются (одна строка).
3. **Нормализованное исходное и сырое `was`** (меняет §2.2 и §3.1): модель получает нормализованное текущее значение (иначе только что открытый редактор «грязный»), а в `was` запроса уходит значение, как его прислал бек, — бек сверяет его со своим текущим (иначе `409` на строчных буквах, кириллице, пробелах). Равенство значений — правило сущности `same` (`sameEditValue`), не JSON (небольшая обёртка).
4. **Esc во время сохранения поглощается без отмены** (меняет §4): «Отмена» недоступна, сохранение в 2c не прерывается (одна строка).
5. **`SuggestInput` — Tab в содержимое строки состояния** (уточняет Р15): Tab переводит фокус в фокусируемое содержимое `status` («Повторить» при отказе справочника); Tab за последним и Esc там — отмена; клик вне — отмена (как у эталона); клик вне `FieldEditor` его не закрывает. Клавиатурный доступ к повтору — WCAG 2.1.1 (небольшая правка клавиатуры).
6. **Бейдж сводки аудита — по последней записи** (уточняет §2.1 `EditHistory`): последняя запись говорит, утверждено ли текущее значение; на эталоне `pending` бывает только у последней, правила на его данных совпадают (одна строка и тест).
7. **Текстовые 70/72 — панель под текстовым блоком** (механизм решения в4, §1.3): «Было / Стало», `EditHistory` и «✎ Изменить» под полем, когда у него есть правки; редактор — сразу за полем на всю ширину сетки. «✎ Изменить» в раскрытии — только у поля с правками (у остальных вход — карандаш); скрытый текст изменённой ячейки — сам `tip` («Изменено: …»).
8. **Поле 56 (`hideIfEmpty`) с правками видно** (уточняет §1.1): правится только заполненное; правка может его опустошить — пока у поля есть правки, ячейка видна (прячется, только если пусто и правок нет), аудит остаётся доступен (одно условие).
9. **↺ не проверяется правилами домена** (меняет §3.1): откат «стало = исходное» бек принимает всегда — исходное могло быть пустым (20 исх), вне набора или вне справочника счетов.
10. **Дата валютирования — проверка формата** (меняет §3.3): `validateFxEdit` для `valueDate` требует `ГГГГ-ММ-ДД` (по контракту было `null`) — фейк отклоняет мусор; `DateInput` и так даёт ISO.
11. **Заголовок `FieldEditor` — `h4`, не `h6`** (меняет вид §2.1 только в разметке): порядок заголовков под `h3` `ConfigForm` (axe); внешний вид тот же.
12. **409** (Р5, §4): редактор остаётся открытым, «Сохранить» доступна (повтор снова даст `409` — текст велит открыть заново); виджет получает `reloadDetail(id)`. Текст ошибки `400` — `problem.errors[0].message` без префикса; отказ без текста — «Не удалось сохранить изменения». Подпись «Сохранить» при ошибке не меняется (Р13).
13. **Охрана ухода — `createDetail({ guard: true })`** (Р6): закрытие и замена документа идут через `leaveRequested`, выполняются по `leave`; тип `LeaveIntent` — в `shared/lib/detail`; уход с экрана (`pageClosed`) — без вопроса. Ответы детали и вкладок, ушедшие до `replaceDetail`, кэш не трогают (эпоха документа).
14. **Прочее из плана:** один редактор на экран, A и B вместе (Р2, `detail-drift.md` Д59); после сохранения поле не раскрывается само (Р8, Д60); правка счёта открывается с пустым запросом, черновик — только выбранный счёт (набор цифр — не «несохранённый ввод»), «Загрузка счетов…», «Не удалось загрузить счета» + «Повторить» (Р9); склонение «изменение/изменения/изменений» по правилам языка (Р10); время правки «дд.мм.гггг чч:мм» (Р12); имя карандаша с `B.` (Р14); фейк — правки только на детали, `who: 'Вы'`, маршрут — следующий по кругу в `ROUTES` (Р11).
15. **Заблокированный документ — только просмотр** (решение контроллера после ревью Task 12, §4): без карандашей, редакторов и ↺ — сделано в финальной волне: `fxEditableTargets` у документа с `lock` пуст (бек отклоняет правку `400`), виды не рисуют карандаши, ↺ и редакторы (маркеры и аудит остаются), модель страницы закрывает редактор, если документ пришёл заблокированным (`detail-drift.md` Д66 — закрыт).
16. **Факты фичи** (меняет §3.2): `docEdited({ id, detail })` — деталь из ответа (`gridId` не нужен: модель живёт на странице одного реестра), отдельный факт `conflict({ id })` — `409`; `$savedCount` и `$unsaved` — для объявлений «Изменения сохранены» / «Изменения не сохранены: …» (финальная волна).
17. **Финальная волна** (решения после финального ревью ветки): `submit` (↺) при открытом `Prompt` игнорируется, как `open` и `save`; `Popover` кита не считает «снаружи» `pointerdown` и Esc внутри `Prompt`, а правка 20 исх — клик по `Prompt` (иначе черновик сбрасывался до ответа); список `SuggestInput` привязан к полю со строкой подсказки — подсказка видна над списком (Д63, класс C против эталона, где список её закрывает); `FieldEditor.invalid` — подсвечены только виноватые строки и счёт (Д64); выбор счёта во время сохранения игнорируется; `replaceDetail` снимает загрузку детали сразу.
