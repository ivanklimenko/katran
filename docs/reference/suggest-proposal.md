# Подсказки при вводе в фильтр: предложение в контракт `vtb-filters`

Для владельца контракта `vtb-filters`. Дата: 2026-10-05. Статус: предложение кита katran, реализовано на фронте и в фейковом сервере `apps/pi`; до согласования форма запроса — черновик кита.

Ссылки на контракт — разделы `vtb-filters/docs/filter-contract.md`: §4.2 (операторы строк, экранирование), §4.4 (несколько условий по полю), §6 (каталог фильтров), §6.1 (справочники), §8 (ошибки).

## 1. Зачем

В текстовых полях фильтра (наименования сторон, BIC, назначение платежа, причина статуса) пользователь угадывает написание: «ООО Ромашка» или «ООО «Ромашка»», «Не найден счёт» или «Счёт не найден». Подсказки показывают под полем значения, которые реально есть в выборке, — пользователь выбирает существующее значение, и фильтр находит то, что он искал, с первого раза.

## 2. `filter-meta`: флаг `suggest` у поля

У поля каталога (§6) — необязательное свойство `suggest: boolean`, по умолчанию `false`. Бек включает его там, где подсказки дешёвые: есть индекс по полю, значений не миллионы. Фронт запрашивает подсказки только для полей с `suggest: true`.

```json
{ "id": "f50name", "label": "Приказодатель", "type": "STRING",
  "operators": ["EQ", "NE", "CONTAINS", "STARTS_WITH", "ENDS_WITH", "IN", "NOT_IN", "IS_EMPTY", "IS_NOT_EMPTY"],
  "suggest": true }
```

Свойство имеет смысл у полей `STRING`. У остальных типов фронт его не использует.

## 3. `POST /grids/{gridId}/suggest`

**Тело запроса:**

| Свойство | Тип | Обязательно | Смысл |
|---|---|---|---|
| `field` | строка | да | id поля из каталога с `suggest: true` |
| `query` | строка | да | введённый текст; фронт обрезает пробелы по краям и не шлёт пустую строку |
| `filter` | объект `{ conditions: Condition[] }` | да | формат условий как у `search`; фронт присылает применённые условия **без условий по самому `field`** — убирает их сам |
| `limit` | целое | нет | сколько подсказок вернуть, 1–50; по умолчанию 10 |

**Ответ — 200:** `{ "items": string[] }`.

**Семантика:**

- `items` — **различные** значения поля `field` среди записей, удовлетворяющих `filter`, которые содержат `query` без учёта регистра. Пустые значения и `NULL` не включаются.
- `%`, `_` и символ экранирования в `query` экранируются так же, как у `CONTAINS` (§4.2): `query` — текст, а не шаблон.
- Порядок — по убыванию частоты значения в выборке; при равной частоте — по алфавиту.
- Не больше `limit`.
- Права — как у `search` того же грида: пользователь видит в подсказках только значения записей, которые ему доступны.

Условия по самому полю из `filter` исключены намеренно: если пользователь уже ввёл в поле фразу «договор» и печатает вторую, подсказки не должны сужаться первой фразой. Так же фронт считает фасеты лейна статусов (`POST /grids/{gridId}/facets`, `docs/reference/pi-api.md` §1.3).

**Пример** — фейковый сервер `apps/pi`, грид `fx-docs`, поле `f50name` (тест `apps/pi/src/app/fake/contract.test.ts`, «suggest: различные значения поля по выборке…»; в тесте `limit` 3):

```json
POST /grids/fx-docs/suggest
{ "filter": { "conditions": [] }, "field": "f50name", "query": "ооо", "limit": 10 }
```

```json
{ "items": ["ООО «Ромашка»", "ООО «Кедр»", "ООО «Лотос»", "ООО «Меридиан»", "ООО «Северный ветер»"] }
```

Значений с «ооо» в наборе фейка пять, поэтому их меньше `limit`. С условием по другому полю выборка сужается:

```json
POST /grids/fx-docs/suggest
{ "filter": { "conditions": [{ "field": "status", "op": "EQ", "value": "ERROR" }] }, "field": "f50name", "query": "о", "limit": 50 }
```

В ответе — только приказодатели документов в статусе «Ошибка».

## 4. Ошибки

Problem Details, как у `search` (§8):

| Случай | Статус | `errors[].code` | `errors[].path` |
|---|---|---|---|
| поле без `suggest: true` или неизвестное | 400 | `SUGGEST_NOT_SUPPORTED` | `field` |
| `limit` вне 1–50 | 400 | `LIMIT_OUT_OF_RANGE` | `limit` |
| условие `filter` невалидно | 400 | как у `search` | как у `search` |
| неизвестный `gridId` | 404 | — | — |

Пример — `docs/reference/pi-api.md` §5.9.

## 5. Нагрузка

- Фронт шлёт запрос через 250 мс после последнего нажатия клавиши, не на каждое.
- Пустой текст не отправляется (минимум — 1 символ после обрезки пробелов).
- Ответ на устаревший запрос фронт отбрасывает. Отмены запросов на фронте нет, поэтому бек может получить несколько запросов подряд.
- Отказ (любой статус, сеть) фронт не показывает: список подсказок молча пуст, фильтр работает как обычное текстовое поле.

## 6. Для сведения, контракт не меняется

Панель фильтров кита складывает условия так:

- **Фразы одного поля** — несколько условий `CONTAINS` по этому полю, все должны выполняться (AND, §4.4): `[{ "field": "purpose", "op": "CONTAINS", "value": "договор" }, { "field": "purpose", "op": "CONTAINS", "value": "НДС" }]`.
- **Списки ID и номеров** — одно значение уходит как `EQ`, два и больше — одним `IN`, не больше 500 значений (предел контракта на `IN`).
- **Периоды `DATETIME`** — границы со смещением зоны, взятым на ту минуту, на которую приходится граница: `{ "op": "BETWEEN", "from": "2026-09-01T09:30:00+03:00", "to": "2026-09-03T23:59:59+03:00" }` (граница «по» без времени — конец дня). В зонах с переходом на летнее время смещение начала и конца одного дня может различаться — бек приводит момент к одной зоне.

## 7. Дальше

Серверные справочники `LOOKUP` (§6.1, `GET /dictionaries/{id}` с поиском и пагинацией) подключатся к тем же контролам тем же путём: ввод в поле → модель фильтров с задержкой и отбрасыванием устаревших ответов → эффект приложения → эндпоинт бека. На фронте `SearchSelect`/`MultiSelect` получат режим «варианты с бека» без изменения остального API.
