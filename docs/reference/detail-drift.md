Список расхождений деталки «Платёжная инструкция», которую план 2a переносит в кит (`docs/superpowers/specs/2026-09-29-katran-detail-view-design.md`), с замороженным эталоном стенда. ### Вопросы владельцу

- **В-Д1.** Заголовок валютной деталки — «Платёжная инструкция» (как в плане 2a) или «Платёжная инструкция ВАЛЮТА» (как на эталоне, `dhHtml(d,'Платёжная инструкция ВАЛЮТА')`, `index.html:1369`)? У рубля на эталоне заголовок без суффикса в обоих случаях. Влияет на `FX_DETAIL_TITLE`, Task 8.
- **В-Д2.** Состав вкладок рубля — как `TABS_RUB` стенда (Общие данные / Статусы / Комплаенс / Связанные документы / Задачи / Нотификации / ED244 / Стриминг / MPU / Аудит, без «Доп. полей», «Исходный текст» заменён на ED244) или иначе? Влияет на набор вкладок `entities/rub-doc`, Task 9.
- **В-Д3.** Пути ED107 (узлы `AcctWithInst`, `PrevInstrAgent` и другие из `RSECTIONS.ed107.groups`) и коды операций рубля — переносить как на стенде (PAYDOCRU `'01'`, REQDOCRU `'06'`; для PAYORDRU кода на стенде нет вовсе, включая «16») или сверять по справочнику ЦБ? Влияет на профили рубля, Task 9.
- **В-Д4.** Открывать ли первую запись реестра в drawer A при входе на экран, как на эталоне (`openDoc(0,'A')`), или экран открывается без деталки (как сейчас в плане 2a §1.1)? Влияет на связку страницы с реестром, Task 11.
- **В-Д5.** Ширины блоков деталки (транзакции, таблица сторон, секции рубля) — токенами `dt-*` в ките (как в плане) или числами в раскладке приложения? Токены держат правило «CSS — только `var(--k-*)`» (constraints, никаких голых `px`, кроме border/outline/box-shadow/letter-spacing), но добавляют в кит размеры, специфичные для одного приложения; числа в раскладке `apps/pi` оставляют кит без знания домена, но требуют явного `box-sizing`/расчётов на стороне приложения. Влияет на состав `packages/tokens/src/tokens.src.ts` и на то, что попадает в `ConfigForm`/слоты приложения, Task 8–9.

Ответ «как на эталоне» по любому вопросу — пункт делается по колонке «Эталон» таблицы сверки.

## 2b–2d — сверяются в начале своих подсрезов против того же коммита

Части деталки, не входящие в 2a (спека §1.2: остальные вкладки — 2b; правка, аудит, саджест, `Prompt`, `DateInput`, перезапрос реестра — 2c; настоящие действия лейна вместе с эндпоинтами — 2d), сверяются с эталоном отдельно, каждая в начале своего подсреза, против того же замороженного коммита `e065bfb` (деталка заморожена целиком, решение владельца 29.09 — STATE §10). Этот документ их не описывает.
